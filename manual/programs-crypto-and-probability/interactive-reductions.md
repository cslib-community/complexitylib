# Public-coin interactive reductions and oracle access

`Computability/Interactive` models a protocol that turns one relation into another: a verifier receives an input statement and either rejects or outputs a new statement, while the prover outputs a corresponding witness. Reductions to the always-valid `Unit` relation are proofs of the input language. This reusable model is distinct from the native private-coin IP class and from three-message Sigma protocols [complexitylib][complexitylib]. Its source credits the interactive-oracle-proof framework of Ben-Sasson, Chiesa and Spooner [bcs16][bcs16].

## Messages, scheduling, and the execution law

[OracleInterface](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L70) supplies the queries and dependent response types through which a message is accessed. `full M` permits one query returning the entire message; `coord ι A` permits reading a coordinate of `ι → A`. This controls information access, without assigning bit cost or native runtime to either query. Reading a large message in one full-access query is not a constant-time Turing operation.

[Spec](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L103) is a finite list of prover-message and verifier-challenge rounds. The list, message types and interfaces depend on parameters fixed before interaction, not on the input statement or transcript. A [Verifier](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L173) has a fixed sampler for each public challenge and a final `OracleComp` decision given the input and all challenges. Challenge samplers do not adapt to earlier messages. The prover's strategy tree can use private randomness and external oracle calls, and its continuation receives each preceding challenge before producing later messages.

[Reduction](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L180) pairs this verifier with an honest prover. Execution first obtains the transcript causally, then lets the decision query prover messages through their interfaces and use its external oracle. [World](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L242) implements the joint prover/verifier oracle with shared state; `World.eval` returns the result law and discards the final oracle state. This is different from the state-preserving native open-program realization contract discussed [elsewhere](programs-and-realization.md).

## Security properties and efficiency refinements

| Property | Actual quantifiers and event | Resource qualification |
|---|---|---|
| [Reduction.Complete](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Security.lean#L97) | Every valid input/witness pair yields matching prover/verifier output statements and a valid output witness, except with probability `ε`, in the supplied world | Honest prover cost is not bundled |
| [Verifier.Sound](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Security.lean#L105) | For every false input, every result type and every malicious prover strategy, probability of outputting a statement in the target language is at most `ε`, in the supplied world | Provers are unrestricted in time and query count |
| [Verifier.KnowledgeSound](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Security.lean#L115) | In the plain model, whenever the verifier accepts an output statement with the prover's valid output witness, a named extractor recovers a valid input witness, except with probability `ε` | Extractor is an arbitrary straight-line function of input, transcript and output witness |
| [Reduction.HVZK](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Security.lean#L177) | For every valid input/witness pair, a named input-only simulator's transcript law is `ε`-close to the honest transcript law | No simulator efficiency; honest verifier only |
| [Verifier.EfficientKnowledgeSound](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Efficient.lean#L97) | The same knowledge property at every family index, plus one word function realizing all extractors | One native deterministic polynomial-time function; index, statement, transcript and output witness are encoded inputs |
| [Reduction.EfficientHVZK](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Efficient.lean#L114) | The same typed simulation at every index, plus one program approximating all encoded simulator laws within `δ` | One uniform strict-PPT program on index and encoded statement |

`CloseTo` is the all-events statistical-distance bound, even for infinite result types. The realization error `δ` permits exact typed laws, such as uniform field challenges, to be approximated by a strict fair-coin machine. [SimulatorRealizedBy.closeTo_run](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Efficient.lean#L127) gives total honest-transcript distance `ε(i)+δ(i)` for the native realizing program. The index encoding is supplied explicitly; the interface does not silently fix unary encoding or grant arbitrary advice for free.

These efficient properties constrain extractors or simulators. They do not by themselves certify the verifier or honest prover. The raw properties cannot be read as efficient extraction or zero knowledge: `ComplexityTests/InteractiveKnowledgeSound.lean` and `ComplexityTests/UnboundedSimulators.lean` contain examples exposing that distinction. Rewinding extraction, malicious-verifier zero knowledge and computational zero knowledge are separate notions.

## Composition and model instances

[Verifier.RbrSound.sound](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Plain.lean#L209) turns a round-by-round invariant into information-theoretic soundness with the sum of challenge errors. Prover messages preserve a false invariant; each random challenge can escape it only with the stated error. In the plain model, sequential composition preserves completeness, soundness and straight-line knowledge soundness with additive errors. `Reduction.iterate` composes stages; `Reduction.bundle` packages a family with a common round shape and samplers so an earlier claim can select the later statement parameter. These are semantic composition theorems; no automatic efficient-verifier or efficient-extractor composition theorem is inferred from them.

| Instance | Mathematical input and messages | Proved endpoint and limits |
|---|---|---|
| [Sumcheck with final evaluation](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Sumcheck.lean#L132) | An `n`-variate polynomial over a finite field, each individual degree at most `d`; each round sends a univariate polynomial read in full, then receives an exact uniform field challenge | [Perfect completeness](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Sumcheck.lean#L319) and [soundness error `n·d/|F|`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Sumcheck.lean#L328) for the Boolean-hypercube sum claim; the verifier directly evaluates the polynomial at the last point |
| [GKR](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/GKR/Protocol.lean#L589) | A layered fan-in-two addition/multiplication circuit, fixed input table and claimed output table; output-point check, per-layer sumcheck and line restriction, then input evaluation | [Perfect completeness](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/GKR/Protocol.lean#L597) and [soundness error `(width(depth)+Σᵢ<depth 5·width(i))/|F|`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/GKR/Protocol.lean#L606) against every prover; verifier efficiency is explicitly unproved |

The sumcheck claim shrinks from a Boolean-cube sum to a single evaluation. Only rounds `i<n` are used. The formulas are error bounds in `ℝ≥0∞`; a useful constant error requires choosing field size accordingly. Neither theorem supplies a native runtime certificate merely because field operations or full messages occur as pure Lean computation [lfkn92][lfkn92].

In [LayeredCircuit](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/GKR/Layered.lean#L69), `width(i)` is the number of **address bits**: layer `i` has `2^width(i)` gates. The sumcheck part of layer `i` has `2·width(i)` rounds, each contributing `2/|F|`, and the line step contributes `width(i)/|F|`. The direct wiring-extension evaluation has no circuit-uniformity or native verifier-cost theorem. Layer numbering runs from input upward; the cited Thaler exposition numbers from output downward [gkr15][gkr15] [thaler22][thaler22].

## Design observations and evidence

The round list makes transcript concatenation and dependent message types compute structurally, while oracle interfaces separate full-message interaction from coordinate access. **Inference:** this permits common composition proofs across ordinary interactive proofs and oracle-access protocols without claiming identical resource costs. The GKR endpoint illustrates that advantage: its completeness and soundness use the generic stage composition results.

Source statements and representative execution definitions were inspected at `13e6a31951bf1c89a1a6258c44f9444aecbbefd8`. Existing interactive, sumcheck and GKR regression modules were identified, without compiling them. Thaler's author manuscript (18 July 2023) §4.6 and Lemma 4.7 were consulted for the identity and layer orientation. The publisher texts for BCS/LFKN/GKR were inaccessible in this pass; their exact literature correspondence remains source-docstring attribution, not a completed independent literature audit.
