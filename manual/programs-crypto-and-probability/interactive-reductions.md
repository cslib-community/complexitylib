# Public-coin interactive reductions and oracle access

`Computability/Interactive` models a protocol that turns one relation into another: a verifier receives an input statement and either rejects or outputs a new statement, while the prover outputs a corresponding witness. Reductions to the always-valid `Unit` relation are proofs of the input language. This reusable model is distinct from the native private-coin IP class and from three-message Sigma protocols, though [SigmaProtocol/Interactive.lean](../../CslibFrontier/Crypto/Protocols/SigmaProtocol/Interactive.lean) embeds `SigmaProtocol` into `Interactive.Reduction` with completeness, round-by-round soundness, soundness, straight-line knowledge soundness, and HVZK/efficient-HVZK transfers (see [Sigma protocols and explicit extraction](protocols-and-privacy.md#sigma-protocols-and-explicit-extraction)) [cslib-frontier][complexitylib]. Its source credits the interactive-oracle-proof framework of Ben-Sasson, Chiesa and Spooner [bcs16][bcs16].

## Messages, scheduling, and the execution law

[OracleInterface](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L70) supplies the queries and dependent response types through which a message is accessed. `full M` permits one query returning the entire message; `coord ι A` permits reading a coordinate of `ι → A`. This controls information access, without assigning bit cost or native runtime to either query. Reading a large message in one full-access query is not a constant-time Turing operation.

[Spec](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L103) is a finite list of prover-message and verifier-challenge rounds. The list, message types and interfaces depend on parameters fixed before interaction, not on the input statement or transcript. A [Verifier](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L173) has a fixed sampler for each public challenge and a final `OracleComp` decision given the input and all challenges. Challenge samplers do not adapt to earlier messages. The prover's strategy tree can use private randomness and external oracle calls, and its continuation receives each preceding challenge before producing later messages.

[Reduction](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L180) pairs this verifier with an honest prover. Execution first obtains the transcript causally, then lets the decision query prover messages through their interfaces and use its external oracle. [World](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/Basic.lean#L242) implements the joint prover/verifier oracle with shared state; `World.eval` returns the result law and discards the final oracle state. This is different from the state-preserving native open-program realization contract discussed [elsewhere](programs-and-realization.md).

To run an adaptive verifier with role-local effects, import `CslibFrontier.Computability.Interactive.StrategyEffect` ([source](../../CslibFrontier/Computability/Interactive/StrategyEffect.lean)). `ProverStrategy.hoist` and `VerifierStrategy.hoist` translate every effect while retaining the captured continuations; they do not rerun initialization or resample captured coins. Translate the initial prover/verifier computations separately, in the intended order, using `liftProver` and `liftVerifier`, then hoist their returned strategies into the joint oracle monad and call `runAgainst`. The verifier may choose challenges from earlier messages and its private state. `runAgainst_hoist` proves that a lawful monad morphism preserves the full transcript and both outputs. For a stateful interpretation, translate into `StateT` and run the whole combined computation once: evaluating each effect at the initial state would reset the oracle and is not such a morphism. The [checked clients](../../CslibFrontierTests/InteractiveStrategyEffect.lean) verify initialization and terminal-query order, distinct role channels, and a private coin retained across a reply and later query. Run `scripts/build.sh CslibFrontierTests.InteractiveStrategyEffect` from the repository root to check them. This execution API does not itself establish a security or efficiency property.

`CloseTo` is the all-events statistical-distance bound, even for infinite result types; [CloseTo.lean](../../CslibFrontier/Probability/StatisticalDistance/CloseTo.lean#L56-L160) supplies reflexivity (`CloseTo.refl`), monotonicity (`CloseTo.mono`), symmetry (`CloseTo.symm`), deterministic postprocessing (`CloseTo.map`), transitivity (`CloseTo.trans`), and randomized data-processing laws (`CloseTo.bind_left`, `CloseTo.bind_right`, `CloseTo.bind`) without `Fintype` assumptions, and [Game/CloseTo.lean](../../CslibFrontier/Crypto/Game/CloseTo.lean#L66-L190) connects `CloseTo` in both directions to `Game.advantage` via deterministic (`Game.closeTo_iff_forall_advantage_map_le`) and randomized (`Game.closeTo_iff_forall_advantage_bind_le`) Boolean distinguishers (complementing `CslibFrontier/Crypto/Game/Statistical.lean` when the ambient type is infinite, such as `List Bool`). The realization error `δ` permits exact typed laws, such as uniform field challenges, to be approximated by a strict fair-coin machine. [SimulatorRealizedBy.closeTo_run](../../CslibFrontier/Computability/Interactive/Efficient.lean#L134) and [AuxSimulatorRealizedBy.closeTo_run](../../CslibFrontier/Computability/Interactive/AuxZK.lean#L426) give total honest-transcript distance `ε(i)+δ(i)` for the native realizing program. Both `ε` and `δ` in `Verifier.EfficientKnowledgeSound`, `Reduction.EfficientHVZK`, and `Reduction.EfficientAuxHVZK` are explicit, unconstrained parameters rather than bundled `Negligible` hypotheses (`ε(i) ≥ 1` or `δ(i) ≥ 1` is vacuous because `PMF.toOuterMeasure` never exceeds `1`), so a computational claim must supply an explicit quantitative or `Negligible` bound along its parameter distribution (as in [Reduction.EfficientAuxHVZK.exists_computationalAuxHVZK](../../CslibFrontier/Computability/Interactive/AuxZK.lean#L589) and [Reduction.EfficientHVZK.exists_computationalHVZK_zero](../../CslibFrontier/Computability/Interactive/AuxZK.lean#L605)). Because an honest-verifier simulator only needs the statement `x`, every `HVZK`, `PerfectHVZK`, `EfficientHVZK`, or `ComputationalHVZK` reduction lifts automatically to its auxiliary-input counterpart by ignoring the auxiliary input (`Reduction.HVZK.auxHVZK`, `Reduction.PerfectHVZK.perfectAuxHVZK`, `Reduction.EfficientHVZK.efficientAuxHVZK`, `Reduction.ComputationalHVZK.computationalAuxHVZK`), and embedding the honest challenge samplers via `honestVerifierStrategy` shows that malicious-verifier `Reduction.ZK` implies `Reduction.AuxHVZK` (`Reduction.ZK.auxHVZK`). The index encoding is supplied explicitly; the interface does not silently fix unary encoding or grant arbitrary advice for free.

These efficient properties constrain extractors or simulators. They do not by themselves certify the verifier or honest prover. The raw properties cannot be read as efficient extraction or zero knowledge: `CslibFrontierTests/InteractiveKnowledgeSound.lean`, `CslibFrontierTests/UnboundedSimulators.lean`, [CslibFrontierTests/InteractiveReduction.lean](../../CslibFrontierTests/InteractiveReduction.lean), and [CslibFrontierTests/ComputationalSpecialHVZK.lean](../../CslibFrontierTests/ComputationalSpecialHVZK.lean) contain examples exposing those distinctions. Rewinding extraction remains a separate notion; Sigma-protocol computational special HVZK (`SigmaProtocol.ComputationalSpecialHVZK`) is documented under [Sigma protocols and explicit extraction](protocols-and-privacy.md#sigma-protocols-and-explicit-extraction).

For independent repetition, import [Security/Repeat.lean](../../CslibFrontier/Computability/Interactive/Security/Repeat.lean). `CloseTo.iid`, `CloseTo.iid_replicate` and `CloseTo.eval_replicate` turn a single-run error `ε` into `k * ε` for `k` independent runs, without a finite sample-space assumption. Apply `CloseTo.map` afterwards to select or otherwise process the results. The Schnorr conversation bounds in [SchnorrEavesdrop.lean](../../CslibFrontier/Crypto/Computational/SchnorrEavesdrop.lean) use this shared API.

For fixed-round specifications `s : Spec`, [ToIP.lean](../../CslibFrontier/Computability/Interactive/ToIP.lean) compiles a plain-model `Interactive.Verifier` into a word-level oracle verifier (`Verifier.wordVerifierWith`, `Verifier.wordVerifier`) via per-round bit-word codecs (`RoundCodecs s`) with explicit reply-length caps (`List.take c.limit`) and adversarial decoding fallback (`c.decodeOrDefault`). Completeness transfers through the compiled honest word prover (`Reduction.Complete.acceptProb_wordVerifier`), soundness against arbitrary stateful randomized `Cslib.Complexity.Prover Unit` strategies transfers by backwards induction to an optimal plain-model typed strategy while rejecting malformed replies (`Verifier.Sound.acceptProb_wordVerifier`), approximate fair-coin challenge samplers `PerChallenge.CloseTo` perturb word-level acceptance probabilities by at most `PerChallenge.sum s δ` (`Verifier.closeTo_wordVerifierWith`), and polynomial-time round codecs and decision predicates yield uniform `IsOraclePPTOn` certificates (`Verifier.isOraclePPTOn_wordVerifierWith`) and `IP` membership (`mem_IP_of_reduction_closeTo`, `Reduction.mem_IP`), exercised in [CslibFrontierTests/PublicCoinToIP.lean](../../CslibFrontierTests/PublicCoinToIP.lean). Uniform compilation across input-dependent round counts (needed for `Sumcheck` and `GKR` families) remains separate.

## Composition and model instances

[Verifier.RbrSound.sound](../../CslibFrontier/Computability/Interactive/Plain.lean#L211) turns a round-by-round invariant into information-theoretic soundness with the sum of challenge errors. Prover messages preserve a false invariant; each random challenge can escape it only with the stated error. [Verifier.RbrKnowledgeSound](../../CslibFrontier/Computability/Interactive/RbrKnowledge.lean#L124) strengthens this with a straight-line extractor `E` and requires the initial prefix to be doomed on every input statement `x` (not only `x ∉ language relIn`); it implies both `Verifier.RbrSound` (`Verifier.RbrKnowledgeSound.toRbrSound`), `Verifier.KnowledgeSound` with error `PerChallenge.sum s ε` (`Verifier.RbrKnowledgeSound.toKnowledgeSound`), and `Verifier.EfficientKnowledgeSound` when paired with a polynomial-time word realization (`Verifier.RbrKnowledgeSound.efficientKnowledgeSound`), with concrete and separation tests in [CslibFrontierTests/RbrKnowledgeSound.lean](../../CslibFrontierTests/RbrKnowledgeSound.lean). In the plain model, sequential composition (`Verifier.append` / `Reduction.append`) preserves completeness, soundness, round-by-round soundness, straight-line knowledge soundness, and round-by-round knowledge soundness (`Verifier.RbrKnowledgeSound.append`) with additive or concatenated errors. `Reduction.iterate` composes stages (`Verifier.RbrKnowledgeSound.iterate`); `Reduction.bundle` packages a family with a common round shape and samplers so an earlier claim can select the later statement parameter (`Verifier.RbrKnowledgeSound.bundle`). For product (AND) relations [relProd](../../CslibFrontier/Computability/Interactive/AuxZK.lean#L629) (defined alongside the disjunctive relation [relDisj](../../CslibFrontier/Computability/Interactive/AuxZK.lean#L635)), [Verifier.seqProd](../../CslibFrontier/Computability/Interactive/AuxZK.lean#L679) and [Reduction.seqProd](../../CslibFrontier/Computability/Interactive/AuxZK.lean#L703) compose two reductions over `s₁ ++ s₂` on product statements and witnesses: completeness errors add (`Reduction.Complete.seqProd`), soundness error against `language (relProd rel₁ rel₂)` is `max ε₁ ε₂` (`Verifier.Sound.seqProd`) because a false product statement is false in at least one coordinate, straight-line knowledge soundness composes with `Verifier.extractSeqProd` and error `κ₁ + κ₂` (`Verifier.KnowledgeSound.seqProd`), round-by-round soundness and round-by-round knowledge soundness compose with `PerChallenge.append s₁ s₂ ε₁ ε₂` (`Verifier.RbrSound.seqProd`, `Verifier.RbrKnowledgeSound.seqProd`), and `HVZK`, `PerfectHVZK`, `AuxHVZK`, and `PerfectAuxHVZK` compose via independent transcript simulation (`simSeqProd`, `auxSimSeqProd`) with additive statistical errors (`Reduction.HVZK.seqProd`, `Reduction.AuxHVZK.seqProd`). These are semantic composition theorems; no automatic efficient-verifier or efficient-extractor composition theorem is inferred from them.

The sumcheck claim shrinks from a Boolean-cube sum to a single evaluation. Only rounds `i<n` are used. The formulas are error bounds in `ℝ≥0∞`; a useful constant error requires choosing field size accordingly. Neither theorem supplies a native runtime certificate merely because field operations or full messages occur as pure Lean computation [lfkn92][lfkn92].

In [LayeredCircuit](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Interactive/GKR/Layered.lean#L69), `width(i)` is the number of **address bits**: layer `i` has `2^width(i)` gates. The sumcheck part of layer `i` has `2·width(i)` rounds, each contributing `2/|F|`, and the line step contributes `width(i)/|F|`. The direct wiring-extension evaluation has no circuit-uniformity or native verifier-cost theorem. Layer numbering runs from input upward; the cited Thaler exposition numbers from output downward [gkr15][gkr15] [thaler22][thaler22].

For the finite-field probability fact alone, import `CslibFrontier.Probability.LinearCombination` ([LinearCombination.lean](../../CslibFrontier/Probability/LinearCombination.lean)). The API lives in `Cslib.Probability`: `linearCombAddHom` forms the linear functional, `linearCombAddHom_surjective` uses a nonzero coefficient, and `uniformOfFintype_map_linearComb` proves its uniform output law. `toOuterMeasure_uniform_linearComb_eq` and `toOuterMeasure_uniform_linearComb_eq_zero` give exact `1 / |F|` event probabilities. This import requires neither polynomial commitments nor the interactive-protocol core. The checked [direct client](../../CslibFrontierTests/LinearCombination.lean) shows that the difference of two uniform elements of `ZMod 5` is uniform; from the repository root, run `scripts/build.sh CslibFrontierTests.LinearCombination` to check it. Existing evaluation-batching and Ligero clients publicly import the shared API through the polynomial-commitment module.

For matrix outputs over a finite field, [Probability/HashFamily/Matrix.lean](../../CslibFrontier/Probability/HashFamily/Matrix.lean) provides `uniformOfFintype_map_mulVec`: a uniform matrix sends each fixed nonzero vector to a uniform vector. `isDeltaUniversalHash_mulVec` uses the existing universality predicate for ordinary `Matrix.mulVec`; apply `.isTwoUniversal` after importing `Probability.UniversalHash` to use the existing leftover-hash bounds. The [checked matrix client](../../CslibFrontierTests/MatrixHash.lean) covers a nonzero input over `ZMod 17`, the deterministic zero-input boundary, empty output dimensions, and a seeded leftover-hash bound of `sqrt(1/17)/2`. Here `dist` is half the L1 distance, so this also bounds event-probability differences without an extra factor of two. These laws use ideal uniform finite matrices and do not certify a bounded fair-coin implementation.

[PolynomialCommitment/Basic.lean](../../CslibFrontier/Crypto/Protocols/PolynomialCommitment/Basic.lean) also defines the standalone polynomial-commitment interface [`PolyCommitScheme`](../../CslibFrontier/Crypto/Protocols/PolynomialCommitment/Basic.lean#L115) (`eval`, `ValidPoly`, `commit`, `openEval`, `verifyEval`) with evaluation completeness (`EvalComplete`), open-value correctness (`OpenValueCorrect`), strict and witness-extracting commitment binding (`CommitmentBinding`, `CommitmentBindingExtract`), strict and witness-extracting evaluation binding (`EvaluationBinding`, `EvaluationBindingExtract`), and the transparent degree-bounded instance `PolyCommitScheme.direct`. ## Design observations and evidence

The round list makes transcript concatenation and dependent message types compute structurally, while oracle interfaces separate full-message interaction from coordinate access. **Inference:** this permits common composition proofs across ordinary interactive proofs and oracle-access protocols without claiming identical resource costs. The GKR endpoint illustrates that advantage: its completeness and soundness use the generic stage composition results.

Source statements and representative execution definitions were inspected at `13e6a31951bf1c89a1a6258c44f9444aecbbefd8`. Existing interactive, sumcheck and GKR regression modules were identified, without compiling them. Thaler's author manuscript (18 July 2023) §4.6 and Lemma 4.7 were consulted for the identity and layer orientation. The publisher texts for BCS/LFKN/GKR were inaccessible in this pass; their exact literature correspondence remains source-docstring attribution, not a completed independent literature audit.
