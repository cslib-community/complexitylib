# Networks and finite dynamics

The frontier development studies how local constraints or local weights interact with a graph layout. It supports lower bounds by exposing separators and algorithms by organizing contractions. Several neighboring types deliberately use different acceptance semantics. [cslib-frontier][complexitylib]

## Expander certificates and cut rank

The regular-graph interface uses a `RotationMap` and its normalized spectral expansion: the
largest absolute eigenvalue of the random walk on mean-zero functions. For a simple degree-`d`
graph, an ordinary adjacency eigenvalue bound `λ` therefore becomes `λ / d` in this interface.
[The spectral cut-rank module](../../CslibFrontier/Foundations/Combinatorics/Expander/CutRank.lean)
combines the sharp mixing lemma, Tanner's full-neighborhood estimate, and a row-support rank
bound. Over every field, it proves
`(1 - ρ²) s (n - s) ≤ d r (s + ρ² (n - s))`, where `ρ` is normalized spectral expansion,
`s` is the size of one side, and `r` is the adjacency cut rank. For degree seven and `ρ ≤ 7/10`,
every cut with both sides of size at least `n/3` satisfies `n ≤ 41 r`. The graph and its spectral
certificate are inputs. The theorem does not construct a degree-seven near-Ramanujan family.
The [support-rank clients](../../CslibFrontierTests/RankSupport.lean) include finite-field matrices,
an actual graph cut, and use of the spectral bound.

The degree-two/three matching-path construction needs a different interface because its walk
is not regular. [MatchingPaths](../../CslibFrontier/Foundations/Combinatorics/Expander/MatchingPaths.lean)
works directly with the generalized eigenvector equations on the core and the path interiors.
Its core bounds `μ` and `ν` are for the ordinary Laplacian and signless Laplacian quadratic forms,
respectively. If `τ < π` and
`2τ / (ℓ sin τ) + 3τ² / (2ℓ²) < min(μ, ν)`, the equations have no nonzero mode at `±cos θ`
for `0 < ℓθ ≤ τ`. Sine interpolation accounts for every internal path coordinate. The endpoint
`-1` has a separate affine-recurrence certificate. The
[checked matching-path client](../../CslibFrontierTests/ExpanderMatchingPencil.lean) uses the
four-vertex core obtained by deleting one edge of `K₄`, including genuine length-ten
trigonometric parameters. [Path interpolation clients](../../CslibFrontierTests/ExpanderPathInterpolation.lean)
also demonstrate why the nonresonance hypothesis is needed. These are finite equation
certificates: the simple-graph path construction, normalized spectral bridge, explicit core
family, and asymptotic `π²/8` coefficient remain the construction direction in
[#3348](https://github.com/cslib-community/cslib-frontier/issues/3348).

[NeighborDeletion](../../CslibFrontier/Foundations/Combinatorics/Expander/NeighborDeletion.lean)
transfers lossless expansion from a degree-`D` graph to a supplied spanning degree-`a` subgraph
with `a > 0`, changing loss `ε` to `ε D / a` while preserving the set-size cutoff. The local-degree version
can be applied separately on the two sides of a biregular graph. The
[checked deletion client](../../CslibFrontierTests/ExpanderNeighborDeletion.lean) deletes a perfect
matching from `K₄` to obtain `C₄`, with a tight two-vertex bound. Choosing an equivariant subgraph
and proving its adjacency matrix has full row rank are separate remaining tasks.

## Constraint networks and read-once branching programs

[Network](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Frontier/Network.lean#L104) is a multigraph whose input coordinates are assigned to vertices. A local predicate at a vertex reads only its incident edge labels and its assigned input coordinates. An input is accepted when some global edge-label assignment satisfies all local predicates. This is existential constraint satisfaction, not arithmetic contraction.

A layout orders vertices, and a sweep retains information on edges crossing the processed/unprocessed boundary. The [ReadOnceNBP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Frontier/BranchingProgram.lean#L91) representation records a sequence of revealed input-coordinate sets, a starting/accepting state condition, and transitions on the newly read block. The revealed sets grow from empty to all coordinates, so blocks are read once. Acceptance means that an accepting state path exists. The representation allows abstract state types; finiteness and numerical width/size bounds are supplied where needed.

The network-to-program bridge preserves acceptance. When the network has a unique satisfying edge assignment, the compiled program is unambiguous. Frontier size then controls available states and transitions. This gives a concrete route from separator structure to branching-program size bounds. It is different from [monoid/permutation programs](circuits-and-formulas.md), which deterministically multiply input-selected monoid elements and measure instruction length. See [frontier programs](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Frontier/BranchingProgram.lean) and [network semantics](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Frontier/Network.lean).

[DecomposableDAG](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Decomposable.lean#L90) supplies a related but more semantic model. Nodes carry variable scopes and sets of assignments. A union node has children of the same scope; a product node combines disjoint scopes; leaves accept at most one assignment; a rank enforces acyclicity. This captures the decomposition pattern used by rectangle arguments without assuming that every assignment set comes with a compact executable code. A native knowledge-compilation interpretation therefore requires more than the semantic DAG alone.

## Deterministic read-once programs and Nisan's generator

[ReadOnceProgram](../../CslibFrontier/Computability/BranchingProgram/ReadOnce.lean) is a deterministic read-once branching program in standard order. It has a start state, a time-indexed transition `step : Fin L → S → X → S` and an accepting predicate, and its width is the number of states. Unlike `ReadOnceNBP` it is deterministic and reads one letter per step, in the fixed order. `toMonoidProgram` turns it into a monoid program over `Function.End S`, and `blocks` regroups `m * n` letters into `m` blocks with the same states. The predicate `IsReadOnceTest w` in [Nisan.lean](../../CslibFrontier/Crypto/Primitives/PRG/Nisan.lean) admits exactly the deterministic tests computed by width-`w` programs, for use as the admissibility predicate of `Generator.Secure`.

[Nisan's generator](../../CslibFrontier/Crypto/Primitives/PRG/Nisan.lean) works by recursive doubling: from a block `x` and `k` seeds of a pairwise independent family `h : ι → X → X` it outputs `2^k` blocks. `abs_dens_eval_blocks_sub_le` bounds the difference in acceptance probability for every program with state type `S` by `(2^k − 1)|S|/(2√|X|)`, and `secure_generator` restates this bound as `Generator.Secure` against `IsReadOnceTest w`. The proof is Nisan's hashing argument in exact expectation form. The [hash mixing lemma](../../CslibFrontier/Probability/PairwiseIndependentHash/Mixing.lean) computes the variance of `dens {x ∈ A | h i x ∈ B}` exactly, and an induction over all start distributions bounds the expected ℓ¹ error of the transition matrices. On bit strings, the [Toeplitz hash over `Bool`](../../CslibFrontier/Probability/BitString/ToeplitzHash.lean) gives [`bitGenerator`](../../CslibFrontier/Crypto/Primitives/PRG/Nisan/Bits.lean), which has `n + k(3n − 1)` seed bits and `2^k n` output bits. For `n = 2(k + a + d)`, `secure_bitGenerator_of_le` bounds the error by `2^(−d)` against width at most `2^a` [nisan92][nisan92].

These theorems are information-theoretic statements about distributions. The [checked examples](../../CslibFrontierTests/NisanGenerator.lean) cover the block order, read-once tests that hold at width `2` and fail at width `1`, and an instance that stretches `734` seed bits into `24576` output bits with error `1/2` against width `2`. Several pieces remain open under [#474](https://github.com/cslib-community/cslib-frontier/issues/474), among them space-efficient computability of the generator, a bridge from the configuration graphs of randomized logspace machines to `ReadOnceProgram`, `BPL ⊆ L²` and the Saks–Zhou theorem `BPL ⊆ L^{3/2}`.

## Tensor networks and their explicit representations

[TensorNetwork](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Frontier/TensorNetwork.lean#L128) assigns a semiring-valued tensor to each vertex. Its contraction sums, over edge-label assignments, the product of all local entries. With Boolean labels, each edge has two choices, but the coefficient semiring is independent of this label domain. Semiring homomorphisms and graph transformations support correctness arguments.

The algorithm-facing [DescribedNetwork](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Frontier/TensorNetwork/Explicit.lean#L102) is a natural edge count and a list of vertices with ordered port lists and descriptors. An evaluator interprets a descriptor on the port bits. [ExplicitTensorNetwork](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Frontier/TensorNetwork/Explicit.lean#L157) specializes descriptors to tables indexed least-significant-bit first. A k-port vertex can have `2^k` table entries. Degree, number of vertices, number of edges and total table length are separate measures; a statement polynomial in explicit table length need not be polynomial in just the graph description's vertex count.

Raw representation is total: an out-of-range port reads false and a missing table entry is zero. Predicates such as rows-first bipartiteness express the intended structural constraints. The `toExplicit` bridge tabulates a semantic finite tensor network and proves contraction preservation, degree bounds and table-size facts. See [the explicit/descriptor interface](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Frontier/TensorNetwork/Explicit.lean).

The large contraction subtree adds schedules, recursion guards, coefficient schemes, truncated rings, entry evaluators and native resource certificates. These are implementation and proof interfaces for this network semantics rather than independent notions of what a tensor contraction means. The root source refers to OpenAI's 2026 ETH manuscript for its contraction construction. This survey inspected the model boundary and selected endpoint links, not the complete mathematical argument of that manuscript.

Quantum [path networks](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Quantum/PathNetwork.lean) and CNF/counting clients supply concrete networks. A contraction theorem transports to those clients only after the compilation proves that weights, multiplicities and output normalization encode the intended amplitude or count. The [native counting chapter](../machines-and-classes/native-counting.md) states the fixed-width result, its fine-grained consequences and the manuscript correspondence limits.

### Weighted CSP partition functions and variable elimination

For discrete weighted CSP partition functions over finite domains and explicit base-`d` factor tables (`{0, ..., d - 1}`), import `CslibFrontier.Logics.Propositional.CSP.PartitionFunction.Properties` ([Properties.lean](../../CslibFrontier/Logics/Propositional/CSP/PartitionFunction/Properties.lean)) and `CslibFrontier.Logics.Propositional.CSP.FactorTable` ([FactorTable.lean](../../CslibFrontier/Logics/Propositional/CSP/FactorTable.lean)). Basic evaluation, isolated-variable scaling, relabeling, and conditioning (`partitionFunctionOn_eq_sum_restrictOn`) hold over any `Semiring R`, whereas disjoint-union/separator product factorization and order-invariant variable elimination require a commutative semiring (`CommSemiring R`):

- **Partition-function laws:** Over `[Fintype D] [Inhabited D]` and `Semiring R`, `CSP.partitionFunctionOn wt F declared` sums factor weights over `declared → D` (fixing variables outside `declared` to `default : D`); `CSP.partitionFunctionOn_boole` recovers `CSP.modelCountOn` on `0`/`1` `ℕ`-weights, `partitionFunctionOn_eq_card_pow_mul_partitionFunction` pulls out `|D| ^ (declared \ F.vars.toFinset).card` for isolated variables, and `partitionFunction_relabel_equiv` gives equivalence invariance. Over `CommSemiring R`, `partitionFunctionOn_append_of_disjoint` factors disjoint unions as products, and `partitionFunctionOn_separator` / `partitionFunction_separator` condition on any variable separator `S` via `CSP.restrictOn` and `PinnedRel` so the conditioned components multiply across `S`.
- **Factor tables and tensor bridges:** `FactorTable R V` pairs a variable list `scope` (possibly empty or with repeated variables) with a flat `entries : Array R` indexed by LSB radix evaluation `Nat.ofDigits d` (`0` outside bounds, paired with fixed-width `lsbDecode`; `ofDigits_two_eq_lsbValue` matches `Cslib.BitString.lsbValue` at `d = 2`). For any inhabited finite domain `D` (`[Fintype D] [Inhabited D]`) with `e : D ≃ Fin d`, `FactorTable.ofCSP d e wt F` compiles `F` into well-formed tables whose `FactorTable.contractionOn` agrees with `CSP.partitionFunctionOn` when `F.vars.toFinset ⊆ declared` (`contractionOn_ofCSP`, and unconditionally `contraction_ofCSP`). Over `CommSemiring R` at `d = 2`, `FactorTable.contractionOn` bridges both ways with `ExplicitTensorNetwork.contraction` (`contractionOn_ofExplicitTensorNetwork`, `contraction_toExplicitTensorNetwork`), `DescribedNetwork.contraction` (`contractionOn_ofDescribedNetwork`), and `TensorNetwork.contraction` (`contraction_tensorNetwork_eq_factorTable`).

For variable elimination and weight-representation bounds, import `CslibFrontier.Algorithms.Lean.CSP.VariableElimination` ([VariableElimination.lean](../../CslibFrontier/Algorithms/Lean/CSP/VariableElimination.lean)) and `CslibFrontier.Algorithms.Lean.CSP.WeightCost` ([WeightCost.lean](../../CslibFrontier/Algorithms/Lean/CSP/WeightCost.lean)):

- **Order-invariant elimination and intermediate costs (`CommSemiring R`):** `ElimState R V` tracks a constant scalar factor, live `FactorTable`s, and remaining variables. Order invariance requires `CommSemiring R`: over a noncommutative semiring, even at `d = 1` with live factors `[constant A, x-factor B]`, eliminating `x` reorders `A * B` into `B * A`. Over `CommSemiring R`, both pure `eliminateOrder` and executable `eliminateOrderM` (`ret_eliminateOrderM`) in `TimeM ℕ` preserve `ElimState.eval` along *any* variable list `order` (`eval_eliminateOrder`), including repeated variables in a scope and inactive or repeated variables in `order`. Extracting the final scalar `result` requires `order` to cover all remaining variables (`s.remaining.toFinset ⊆ order.toFinset`, `result_eliminateOrder_of_subset`), and recovering `F.partitionFunctionOn wt declared.toFinset` via `FactorTable.ofCSP` (`result_eliminateOrder_ofCSP`, `result_eliminateOrderM_ofCSP`, over `[Fintype D] [Inhabited D]` with `e : D ≃ Fin d`) requires both `F.vars.toFinset ⊆ declared.toFinset` (`declared` contains all occurring variables) and `declared.toFinset ⊆ order.toFinset` (`order` covers `declared`). `traceOrder` records per-step joint scope lengths `maxJointScopeLen`, output scope lengths `maxOutScopeLen`, `peakLiveEntries`, and scalar operation counts `totalArithOps`; `totalArithOps_le_of_intermediate`, `peakLiveEntries_le`, and `time_eliminateOrderM_le` bound operations, live entries, and `TimeM` ticks exponentially only in `maxJointScopeLen` / `maxOutScopeLen`.
- **Weight bit-growth and factor-record codecs:** Over `ℤ`, `natAbs_entry_eliminateOrder_le` bounds every intermediate and final entry by `d ^ order.length * W ^ factors.length` (`O(order.length * d.size + factors.length * W.size)` bits under `encIntBin`, `length_encIntBin_entry_eliminateOrder_le`). Over `ZMod p`, `liveFieldBits p` sums `Cslib.TreeEval.Ary.Iter.encField p` bit lengths across all live tables and is bounded at every elimination prefix `order.take k` within `peakLiveEntries * p.size` (`liveFieldBits_eliminateOrder_take_le_peak`, `liveFieldBits_eliminateOrder_le`). Over `ℚ`, direct elimination bounds denominator growth per bucket (`rat_elimBucketTable_bounds`), whereas clearing integer denominators with `mapFactorHom` and `scaleFactor` preserves exact values modulo division by `denoms.prod` (`result_eliminateOrder_ratScaled`) and achieves linear `encRat` result bit-length (`length_encRat_cleared_result_le`). Monomorphic factor records `NatFactorRecord`, `IntFactorRecord`, `RatFactorRecord`, and `ModFactorRecord` carry `enc_structure` multi-tape codecs.

The [weighted-CSP elimination tests](../../CslibFrontierTests/Logics/Propositional/CSP/WeightedElimination.lean) check `modelCountOn` equivalence, relabeling, separator conditioning, `ExplicitTensorNetwork` and `DescribedNetwork` bridges (including repeated and empty scopes), strict order separation on a six-variable star (`[0, 1, 2, 3, 4, 5]` vs. `[1, 2, 3, 4, 5, 0]`), exact `ℤ`, `ZMod 5`, and cleared-denominator `ℚ` elimination, and `enc_structure` bounds. Check them with `scripts/build.sh CslibFrontierTests.Logics.Propositional.CSP.WeightedElimination`.

## Cyclic circuits as fixed-point systems

[CyclicCircuit](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Cyclic.lean#L63) permits a gate to reference any other gate, including itself. Its semantics assumes a monotone interpretation over a complete lattice and takes the least fixed point of the simultaneous gate-update map. Theorems identify this as a fixed point and the least solution, and the acyclic embedding preserves evaluation and weighted operation cost.

This model is useful for comparing feedback systems and ordinary source-relative circuit complexity. It does not give an arbitrary Boolean feedback circuit with NOT gates a unique operational meaning. Both the complete-lattice order and monotonicity belong to the mathematical contract. It also differs from finite-state time iteration: the least fixed point is an order-theoretic semantics, not the state reached after a designated number of clock steps.

## Fixed powers and finite-state iteration

The [fixed-power circuit theorem](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Boolean/Iteration.lean), credited to Samuel Schlesinger's iterated-functions construction, supplies an ordinary De Morgan circuit for every fixed iterate of an n-bit map. If one step has s gates, the displayed bound is `40000 (L s + (n+1)^3 (L + 2^n/L + 1))` for `0 < L <= 2^n`. The invariant-subset version replaces `2^n` by the set cardinality. Checkpoints and their distant images are chosen nonconstructively and hardwired; the size bound is independent of the iterate exponent but says nothing about the cost of finding the circuit. This theorem is the main circuit-level client of the finite-dynamics representations below.

[Machine](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Boolean/Iteration/InPlace.lean#L113) is an explicit finite-state machine on a fixed finite set of writable input cells. Several heads move with boundary clamping; a deterministic priority rule resolves simultaneous writes. With n cells, h heads, alphabet Gamma and state set Q, the total configuration space has size `|Gamma|^n n^h |Q|`. Halting is represented through an absorbing condition.

Its circuit theorems are conditional on a representation of reachable configurations and circuits for initialization/one step. They then derive circuit bounds for long iterates or a halting encoding. The model is useful for finite dynamical arguments, but it is not the native multi-tape machine model with read-only input that anchors the library's time/space classes.

[Description](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Boolean/Iteration/UniversalMap.lean#L288) gives a description/configuration pair that interprets a circuit one gate at a time and performs a reset/copy phase. A round takes the stated number of steps relative to description length. The `universal_power_circuit` theorem assumes the required finite encoding and circuit representation of powers. It should be described as a universal finite-map construction with conditional circuit bounds, not as a resource-certified native universal Turing machine. See [in-place dynamics](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Boolean/Iteration/InPlace.lean) and [universal gate map](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Circuit/Boolean/Iteration/UniversalMap.lean).

## Known Limitations

The network inventory distinguishes existential, unambiguous and weighted semantics, as well as semantic and serialized presentations. The substantial recursion/truncated-arithmetic implementation underneath native contraction has not been independently proof-audited here. Its resource claims must be assessed at the native endpoint rather than inferred from the abstract tensor definition. Similarly, `eliminateOrderM` charges scalar arithmetic and index lookups in `TimeM ℕ` and pairs with explicit multi-tape bit-length bounds on `FactorTable` records, without compiling variable elimination down to a Word-RAM or multi-tape Turing machine.
