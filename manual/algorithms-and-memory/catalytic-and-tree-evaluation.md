# Borrowed registers and native Tree Evaluation

The catalytic material has two distinct levels. `Catalytic/Comparison.lean` proves algebraic operations that restore arbitrary borrowed memory exactly. The Tree Evaluation development additionally constructs a native machine and proves a workspace bound for an explicitly encoded problem. Restoring an algebraic register file alone is not a native catalytic-space class theorem [cslib-frontier][complexitylib].

## Arbitrary contents and exact restoration

The register file is `S : ι → Fin ℓ → R`, with no zero-initialization premise. Over a commutative ring, [addSqDist](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L120) is a four-visit transform alternating the two operand vectors: mask a borrowed register with `x`, use `y`, unmask with `x`, then use `y` again. [addSqDist_eq](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L134) proves the exact result `(S, z + c·Σⱼ(xⱼ−yⱼ)²)` for every initial `S,z`. Calling it with `−c` undoes the transform.

The [eqTest](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L153) wrapper compares the accumulator before and after this transform and then applies its inverse. It restores both the file and accumulator for every starting state. The flag tests vanishing squared distance, so it detects equality over integers; it is not universally an equality test in modular rings. For natural digits below `b`, [eqTest_eq_natCast](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L220) requires the explicit no-wraparound bound `ℓ·(b−1)² < m`. [eqTest_eq_two_pow](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L242) supplies the sufficient modulus `2^k`, with `k = Nat.size ℓ + 2·Nat.size b`. A realization must retain the original accumulator or start it at zero, in addition to the phase and result flag. These are storage observations attached to the algebraic contract; this module does not provide a native instruction or workspace certificate.

A second interface, [keyTest](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L258), borrows a table `V : κ → M` for an additive commutative group. It adds `c` at key `a`, reads key `b`, undoes the update at `a`, and reads `b` again. [keyTest_eq](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L270) returns exactly `(V, s + if a=b then c else 0)` for arbitrary initial table contents. It specifies restoration and the result, without assigning an address representation or table-access cost.

The source credits Christian Reitwiessner and identifies the four-visit construction in the pinned OpenAI `CatalyticComparison.lean`, re-proved here using vectors and dot products. Its listed `fair`, `pupils`, `back`, `test_eye`, `paw` and `small` declarations were checked in that source. This is attribution for a bounded construction; the broader unreviewed preprint's derandomization claim is not an endpoint of this local module [openai-logspace26][openai-logspace26].

Let `B` be the space scale, so that identifiers have `n ≤ C_N · B` bits for a constant `C_N`. For `n`-bit natural identifiers (`x, y < 2^n`), holding an `O(log B)`-bit accumulator in every suspended call frame is too large. [Catalytic/VertexEquality.lean](../../CslibFrontier/Computability/Catalytic/VertexEquality.lean) instead composes two stages of `addSqDist` with `keyTest` over `ZMod 2` into the 64-excursion procedure `vertexEqProc` and its Boolean wrapper `catalyticVertexEq`. The excursion-restoration principle and the `ZMod 2` key test follow the OpenAI preprint [openai-logspace26][openai-logspace26]; the two-stage composition and its bit-budget bounds are original to this library. Across all 64 single-endpoint excursions the caller retains only the 7-bit local frame `VertexLocalFrame = Fin 64 × ZMod 2` (`card_vertexLocalFrame`), while `catalyticVertexEq_eq` restores arbitrary shared catalytic memory `VertexCatState B n` of `vertexCatBits B n ≤ vertexCatLinearConst C_N * (B + 1)` bits whenever `n ≤ C_N * B` (`vertexCatBits_le`) and composes across nested restoring excursions (`ExcursionProc.runExcursions_eq_run`). The [checked clients](../../CslibFrontierTests/CatalyticVertexEquality.lean) cover multi-chunk runs with non-zero catalytic memory, range-hypothesis necessity (`x < 2^n`), a nested-excursion callback on the same shared catalyst, and concrete bit-budget bounds. Like `Comparison.lean`, this is an algebraic single-endpoint excursion and state-cardinality contract rather than a native Turing-machine workspace certificate.

## Tree instances, gate tables, and native resources

[Tree](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Basic.lean#L48) is a perfect binary tree of height `H`. Each leaf contains an `ℓ`-bit value; each internal gate is an arbitrary function on two `ℓ`-bit values. The output is the root value. [Instance](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Instance.lean#L43) packages `ℓ,H` with the tree, giving one input type across all sizes.

The [injective instance encoding](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Instance.lean#L93) has unary header `1^ℓ 0 1^H 0`, then a preorder body: each gate's complete `4^ℓ·ℓ`-bit truth table and each leaf's `ℓ` bits. This is an explicit table input, not an oracle gate or a succinct circuit input. The native reader recomputes node offsets from paths and accesses the encoded input through the read-machine/step-machine route.

The algebraic [proc](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/CookMertz.lean#L97) uses three shared vector registers over a finite field. Given a repetition-free enumeration of all nonzero field elements and `2ℓ < |K|−1`, [proc_eq](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/CookMertz.lean#L152) adds a scalar multiple of the subtree value to the chosen register and restores the other registers, for arbitrary initial contents. Signed recursive calls undo temporary child values. Its correctness theorem is separate from the native space theorem, following the Cook–Mertz procedure and Goldreich's signed-call exposition [cookmertz24][cookmertz24] [goldreich-tree24][goldreich-tree24].

| Native endpoint | Exact scope |
|---|---|
| [computableInSpace_eval](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Space.lean#L67) | For all encoded instances, some time bound `t` gives native `ComputableInBigO` with space `O((ℓ+H+1)·log(ℓ+2)+log(n+2))`, where `n` is encoded input length |
| [computableInSpace_eval_log_mul_log_log](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Space.lean#L140) | On the subtype `ℓ≥1` and `H≥1`, native workspace is `O(bitlength(n)·bitlength(bitlength(n)))` |

Both use the independent-workspace convention: the output value is not charged to workspace. Time is existentially bounded, with no polynomial-time conclusion from these statements. On nontrivial instances the explicit tables and leaves make `2^ℓ,2^H ≤ n`; the source proves a factor-six bound converting the parameter budget to the bitlength product. The result therefore depends on the gate-table encoding as well as the algorithm. Cook–Mertz's report gives the corresponding `O(log n log log n)` Tree Evaluation theorem [cookmertz24][cookmertz24].

## Fan-in and packed-controller variants

[Ary.Tree d ℓ H](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Ary/Basic.lean#L56) permits `d` children with arbitrary gates on `d` values. The binary embedding preserves evaluation, and `Ary.proc_ofBinary` identifies the binary procedure with the `d=2` procedure on the same three registers. This is an explicit bridge between the problem variants, not an identification with a branching-program model.

The packed variant groups several bits per field symbol and interpolates on a chunk alphabet `A`, following the packing construction in Williams's Appendix A, equation (6). Signed recursive calls and sums over nonzero field elements allow arbitrary characteristic here, whereas that exposition uses characteristic two [williams25][williams25]; its strict unmasking condition is `d·r·(|A|−1) < |K|−1` for `r` chunks. `Ary/Packed.lean` proves decoding and algebraic correctness, while the separate [raw-controller native step](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Ary/Packed/RawControllerNative.lean#L490) and `need_inSpace`/`halted_inSpace` certify local runtime-parameter operations in linear encoded-input space. These local contracts do not themselves supply a global time-to-space theorem. See [native counting](../machines-and-classes/native-counting.md) for the separately stated counting applications and [machine endpoints](../machines-and-classes/endpoints-and-hierarchies.md) for time-to-space results.

## Black pebble games

The [black pebble game](../../CslibFrontier/Computability/Pebbling/Basic.lean) is the combinatorial model of evaluating a computation DAG with a bounded number of registers. It is stated on a Mathlib `Digraph V`, where `G.Adj u v` means that `u` is an immediate predecessor of `v`. `blackPebbleGame G s` is a cslib `LTS` on `Finset V` configurations: `BlackStep.place` adds a vertex whose predecessors are all pebbled, `BlackStep.remove` deletes one, and every configuration reached holds at most `s` pebbles. `BlackPebblable G s v` asks for a run from `∅` to a configuration containing `v`, and `blackPebblingPrice G v` is the least such `s`. When no budget suffices, for instance at a vertex with a self-loop, infinitely many predecessors or no open source path, the price is `sInf ∅ = 0`. Equalities for the price therefore need a pebblability witness, as in `blackPebblingPrice_eq`. On a finite graph with well-founded predecessor relation every vertex is pebblable (`blackPebblable_fintypeCard`). The convention is Nordström's, without sliding. Under Savage's sliding rule every price is one lower, so compare constants with the source's convention before citing [nordstrom15][nordstrom15].

On `Fin N`, a configuration is also a word of `N` bits: its indicator word [indicatorList C](../../CslibFrontier/Foundations/Data/BitString/Support.lean) sets bit `i` exactly when `i ∈ C`. [wordStep ready s u v](../../CslibFrontier/Computability/Pebbling/Words.lean) is one legal move with at most `s` pebbles on words: it flips one bit, and sets a bit only where the Boolean test `ready u i` allows it. `wordStep_indicatorList_iff` shows that on configuration words this is exactly a move that changes the configuration, provided that `ready` tests whether all predecessors carry pebbles. Since there are `2 ^ N` configurations, Savitch's midpoint recursion `reach (wordStep ready s) N N` at depth `N` decides reachability in the game (`reach_wordStep_iff_canReach`) and pebblability from the zero word (`reach_wordStep_iff_blackPebblable`). A space-bounded simulation can walk this recursion with one configuration per level instead of storing a pebbling strategy; the `Digraph` itself never has to be computed. The [checked client](../../CslibFrontierTests/PebblingWords.lean) decides with `decide` that the end of a two-vertex path needs two pebbles.

Upper bounds come from `BlackPebblable.of_forall_adj`. If each predecessor of `v` is in `ps` and pebblable with `s` pebbles, then `v` is pebblable with `t` pebbles whenever `#ps + 1 ≤ t` and `s + #ps ≤ t + 1`. Lower bounds use the [path-blocking engine](../../CslibFrontier/Computability/Pebbling/Blocking.lean). `ForcesPebbles G R v n` says that every legal run that starts with an open source path into `v` and later pebbles `v` passes through a configuration with `n` pebbles on `R`. `ForcesPebbles.step` adds one pebble at a vertex with exactly two predecessors, given that blocking either predecessor puts a pebble in `v`'s region outside the other predecessor's region. `ForcesPebbles.le_of_blackPebblable` then bounds every budget. The [pyramid](../../CslibFrontier/Computability/Pebbling/Pyramid.lean) theorem `blackPebblingPrice_pyramid_top` gives Cook's price `h + 2` for height `h ≥ 1` [cook74][cook74]. The [complete binary tree](../../CslibFrontier/Computability/Pebbling/BinaryTree.lean) theorem `blackPebblingPrice_completeBinaryTree_root` gives `h + 2` as well. The [checked clients](../../CslibFrontierTests/Pebbling.lean) show that one pebble fewer fails on `Π_2` and `T_3`, and write out an explicit three-pebble run on `Π_1`.

Pebbles are registers for cslib straight-line programs. [Program.dag](../../CslibFrontier/Computability/Circuit/Pebbling.lean) is the computation DAG of a `Program σ n g`: the argument wires of a gate are its predecessors, and the inputs are sources. `Program.registerLTS p I x s` evaluates `p` with one register per wire and at most `s` occupied registers. A step loads an input, computes a gate whose argument registers are occupied, or frees a register. `Program.registerLTS_mTr_trace_eq` shows that every occupied register holds the value `p.trace I x` of its wire. `Program.evaluatesInRegisters_iff_blackPebblable` shows that `p` evaluates `w` with `s` registers exactly when `w` is black-pebblable with `s` pebbles in `p.dag`, for every interpretation, input and initial register contents; inputs occupy registers, as in Savage's model. A computed value always goes into the gate's own fresh register; Savage also lets a result be placed on (or moved to) an argument's register, and under that sliding rule the register count of every gate that reads at least one wire is one lower. To use a price computed on a named graph, transport it along a relation isomorphism `G.Adj ≃r H.Adj` with [blackPebblingPrice_relIso](../../CslibFrontier/Computability/Pebbling/Map.lean). The [checked client](../../CslibFrontierTests/CircuitPebbling.lean) does this for a three-gate De Morgan program whose DAG is `Π_2`, which therefore needs exactly four registers without in-place overwrite (three under Savage's sliding rule).

`Program.ncard_dag_adj_le` bounds the in-degree of `p.dag` by the fan-in of `p`. A computation with decreasing indices, as unfolded into a tree by `TreeEval.Ary.Descending`, keeps its sharing as a straight-line program: [Descending.program child g](../../CslibFrontier/Computability/Circuit/Descending.lean) has the single input at index `0` and one gate of fan-in `d` for each index `1, …, g`. `Descending.trace_node_eq` identifies its trace with any solution of the computation's equations, and `Descending.dag_adj_node` gives the dependency edges. [BlockComputation.program σ](../../CslibFrontier/Computability/Machines/Turing/MultiTape/BlockComputationProgram.lean) applies this to the block computation of a guessed movement schedule `σ` with `q` intervals. Its DAG has `q + 1` vertices of in-degree at most `3 * k + 1` and depends only on `σ`; `exists_registerLTS_value` turns a black pebbling of interval `n` with `s` pebbles into an evaluation that holds at most `s` interval views and ends with the value of `n`. This is Williams's computation graph of the block computation, which he notes is very similar to the graphs of Hopcroft, Paul and Valiant, with the library's aligned three-block windows in place of a block-respecting normal form [williams25][williams25]. The pebbling bound, the native search over schedules and the space accounting that `DTIME(t) ⊆ DSPACE(t / log t)` also needs are not proved here. The [Fibonacci client](../../CslibFrontierTests/CircuitDescending.lean) and the [block client](../../CslibFrontierTests/Machines/Turing/MultiTape/BlockComputationProgram.lean) check both constructions; the block client includes a window edge of a concrete schedule.

An evaluator can also follow a word walk directly, without building a program. [Pebbling.Descending.graph child](../../CslibFrontier/Computability/Pebbling/Descending.lean) is the dependency graph on `Fin N` of the same descending computation, with the same `child`. When children lie below their parents and `N = g + 1`, it has the edges of `(Circuits.Descending.program child g).dag` relabelled by `i ↦ Circuits.Descending.node g i` (compare `Circuits.Descending.dag_adj_node`); no theorem states this correspondence. It is a DAG of in-degree at most `d` (`Pebbling.Descending.wellFounded_graph`, `Pebbling.Descending.ncard_graph_adj_le`), and `Pebbling.Descending.ready child` is the readiness test on words (`Pebbling.Descending.ready_indicatorList`). `Pebbling.Descending.tableStep` updates a list of `(index, value)` pairs along a walk of words: it drops the index of a cleared bit, stores the value of a set bit computed by its gate from the stored values of its children, and never holds more than `s` entries (`Pebbling.Descending.length_tableStep_le`). `Pebbling.Descending.lookup_eq_of_tableStep` shows that along any walk from the zero word to the word of `{v}` whose consecutive words are equal or one legal move apart, the final table returns the value of `v` (`List.lookup`). The values are only assumed to satisfy the gate equations, and the walk decides the evaluation order. These are statements about functions on lists. [The pebbling evaluator](../machines-and-classes/endpoints-and-hierarchies.md#follow-a-path-in-savitchs-space) runs them as a query machine that calls a gate machine at each placement; the work space of one of its steps on multi-tape machines is not proved yet. The [checked client](../../CslibFrontierTests/PebblingDescending.lean) follows a seven-move walk with three pebbles through a four-index computation.

This development does not connect pebblings to Turing-machine space. Black-white pebbling and the Paul–Tarjan–Celoni bounds are open ([#2995](https://github.com/cslib-community/cslib-frontier/issues/2995)). The Hopcroft–Paul–Valiant pebbling bound for bounded in-degree DAGs is [#3573](https://github.com/cslib-community/cslib-frontier/issues/3573), and the inclusion `DTIME(t) ⊆ DSPACE(t / log t)` built from it and the block computation above is [#4081](https://github.com/cslib-community/cslib-frontier/issues/4081).

## Reversible pebble games

The [reversible pebble game](../../CslibFrontier/Computability/Pebbling/Reversible.lean) models Bennett's reversible simulation of an irreversible computation, where pebbles are checkpoints [bennett89][bennett89]. `RevStep G` uses the black game's `Move` type, but placing a pebble on `v` and removing it both require every predecessor of `v` to be pebbled. The moves toggle: `place v` needs `v` unpebbled and `remove v` needs it pebbled, as in the rule of [ltv98][ltv98], Section 6. `reversiblePebbleGame G s` is the cslib `LTS` with budget `s`. `ReversiblePebblable G s v` asks for a run from `∅` to a configuration containing `v`. `PersistentReversiblePebblable G s v` asks for a run that ends at `{v}`, so that the output is kept and every checkpoint erased. `reversiblePebblingPrice` and `persistentReversiblePebblingPrice` are the least budgets, `0` when none suffices, as for the black price. On a loopless graph `reversiblePebbleGame_mTr_reverse` plays a run backwards with each move swapped. `RevStep.filter` restricts a move to a predecessor-closed vertex set. Every reversible run is a black run, which gives `blackPebblingPrice_le_reversiblePebblingPrice`.

On the [directed path](../../CslibFrontier/Computability/Pebbling/Path.lean) `pathDigraph`, `0 → 1 → ⋯` on `ℕ`, every vertex but the source has black price `2` (`blackPebblingPrice_pathDigraph_succ`). The reversible prices grow logarithmically ([ReversiblePath.lean](../../CslibFrontier/Computability/Pebbling/ReversiblePath.lean)). With `k` pebbles, `reversiblePebblable_pathDigraph_iff` reaches `v` exactly when `v + 2 ≤ 2 ^ k`. `persistentReversiblePebblable_pathDigraph_iff` ends at `{v}` exactly when `2 * (v + 1) ≤ 2 ^ k`. The prices are `Nat.clog 2 (v + 2)` and `Nat.clog 2 (v + 1) + 1`. The upper bounds come from Bennett's recursive strategy `bennettMoves a k`, which follows the procedures `pebble(s, n)` and `unpebble(s, n)` of [ltv98][ltv98], Section 7, in the form that ends with a single pebble. On a block of length `2 ^ (k + 1)`, `bennettMoves a (k + 1)` pebbles the midpoint with `bennettMoves a k`, then the end, then plays the first run backwards. `bennettMoves_mTr` and `length_bennettMoves` show that it uses `k + 1` extra pebbles and `3 ^ k` moves. So `exists_mTr_bennett_pathDigraph` pebbles the path of `2 ^ k` vertices with `k + 1` pebbles in `3 ^ k` moves, ending at `{2 ^ k - 1}`. By `persistentReversiblePebblingPrice_pathDigraph_two_pow_sub_one`, `k + 1` pebbles are optimal there. The lower bound `add_two_le_of_reversiblePebbleGame_pathDigraph_mTr` is [ltv98][ltv98], Corollary 2 and Theorem 2(i), which say that the maximum reachable node with `n` pebbles is `2^n − 1`. Lean vertex `v` is their node `v + 1`, and their permanently pebbled node `0` is not counted. Their proof goes through the characterization of every reachable configuration (Theorem 1, Corollary 1). The Lean proof of the bound instead inducts on `k` with a bound on the least pebble. It plays the run backwards to `∅`, restricted to the vertices below the least pebble, and it shifts the run's upper part down by `2 ^ (k - 1)`. The [checked clients](../../CslibFrontierTests/ReversiblePebbling.lean) write out the nine-move strategy on four vertices, check each characterization where it holds and where it fails, and show a remove that is black-legal but not reversible.

That characterization is in [ReversiblePathReachable.lean](../../CslibFrontier/Computability/Pebbling/ReversiblePathReachable.lean). A configuration `C` with `n` pebbles leaves `f = n - #C` free. A pebble `x` of `C` is available (`PathAvailable C f x`) when the path start or another pebble lies at most `2 ^ f` positions to its left. The path start sits at position `-1`, so the first condition reads `x + 1 ≤ 2 ^ f`. `PathAvailable.exists_mTr_remove` and `PathAvailable.exists_mTr_place` turn Bennett's procedure into runs that remove or place an available pebble and touch nothing else. `PathRemoval n` is LTV's big removal step.

`PathWeaklySolvable n C` says some sequence of big steps frees every pebble, and `PathStronglySolvable n C` says no sequence of big steps gets stuck first. `PathWeaklySolvable.pathStronglySolvable` is their Theorem 1. `IsPathRemovalNumbering n C σ` numbers the pebbles `n - #C, …, n - 1` so that each pebble `x` has a higher-numbered pebble, or the path start, at most `2 ^ σ x` positions to its left. `exists_reversiblePebbleGame_pathDigraph_mTr_iff` is their Corollary 1: `C` is reachable from `∅` iff `HasPathRemovalNumbering n C`. The key step of Theorem 1, `IsPathRemovalNumbering.erase_of_pathAvailable`, removes any available pebble and moves the pebbles numbered below it up by one. A pebble whose witness was the removed pebble follows the chain of witnesses to the left (`IsPathRemovalNumbering.chain`), and the distances along the chain sum to at most `2 ^ (i + 1)`.

A consequence is `add_one_add_two_pow_le_of_reversiblePebbleGame_pathDigraph_mTr`: with `f` free pebbles, every pebble `v` satisfies `v + 1 + 2 ^ f ≤ 2 ^ n`. With `f = 0` this gives the visiting bound, and with `C = {v}` the persistent bound. By Theorem 1, the greedy test `pathGreedySolvable`, which keeps removing the least available pebble, decides weak solvability. So both predicates are decidable, and reachability of a concrete configuration is checked by rewriting with Corollary 1 and running the greedy test: `rw [exists_reversiblePebbleGame_pathDigraph_mTr_iff]; decide` closes `¬ ∃ ms, (reversiblePebbleGame pathDigraph 3).MTr ∅ ms {3, 6}`. The [checked clients](../../CslibFrontierTests/ReversiblePathReachable.lean) pair reachable and unreachable configurations at the same budget. Among them are `{0, 2}` with two pebbles and `{3, 6}` with three, which are unreachable even though `{0, 2}` meets the per-pebble bound and both `3` and `6` occur in the reachable `{3, 5, 6}`. The clients also write out a removal numbering and rederive both bounds of `ReversiblePath.lean`.

This covers only the space of reversible pebbling on paths. Whether `3 ^ k` moves are optimal for `k + 1` pebbles, other time–space trade-offs, and the erasure trade-off of [ltv98][ltv98], Lemma 1 and Theorem 2(ii), remain open ([#3199](https://github.com/cslib-community/cslib-frontier/issues/3199)).

## Evidence and limits

This revision inspected the listed semantics, encodings, restoration equations, native endpoint statements and representative controller contracts at `13e6a31951bf1c89a1a6258c44f9444aecbbefd8`. Existing `CslibFrontierTests/CatalyticComparison.lean`, `TreeEval.lean`, `TreeEvalAry.lean`, `TreeEvalPacked.lean` and `TreeEvalRawController.lean` were located; they were not run.
