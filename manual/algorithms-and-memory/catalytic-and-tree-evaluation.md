# Borrowed registers and native Tree Evaluation

The catalytic material has two distinct levels. `Catalytic/Comparison.lean` proves algebraic operations that restore arbitrary borrowed memory exactly. The Tree Evaluation development additionally constructs a native machine and proves a workspace bound for an explicitly encoded problem. Restoring an algebraic register file alone is not a native catalytic-space class theorem [complexitylib][complexitylib].

## Arbitrary contents and exact restoration

The register file is `S : ι → Fin ℓ → R`, with no zero-initialization premise. Over a commutative ring, [addSqDist](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L120) is a four-visit transform alternating the two operand vectors: mask a borrowed register with `x`, use `y`, unmask with `x`, then use `y` again. [addSqDist_eq](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L134) proves the exact result `(S, z + c·Σⱼ(xⱼ−yⱼ)²)` for every initial `S,z`. Calling it with `−c` undoes the transform.

The [eqTest](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L153) wrapper compares the accumulator before and after this transform and then applies its inverse. It restores both the file and accumulator for every starting state. The flag tests vanishing squared distance, so it detects equality over integers; it is not universally an equality test in modular rings. For natural digits below `b`, [eqTest_eq_natCast](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L220) requires the explicit no-wraparound bound `ℓ·(b−1)² < m`. [eqTest_eq_two_pow](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L242) supplies the sufficient modulus `2^k`, with `k = Nat.size ℓ + 2·Nat.size b`. A realization must retain the original accumulator or start it at zero, in addition to the phase and result flag. These are storage observations attached to the algebraic contract; this module does not provide a native instruction or workspace certificate.

A second interface, [keyTest](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L258), borrows a table `V : κ → M` for an additive commutative group. It adds `c` at key `a`, reads key `b`, undoes the update at `a`, and reads `b` again. [keyTest_eq](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Catalytic/Comparison.lean#L270) returns exactly `(V, s + if a=b then c else 0)` for arbitrary initial table contents. It specifies restoration and the result, without assigning an address representation or table-access cost.

The source credits Christian Reitwiessner and identifies the four-visit construction in the pinned OpenAI `CatalyticComparison.lean`, re-proved here using vectors and dot products. Its listed `fair`, `pupils`, `back`, `test_eye`, `paw` and `small` declarations were checked in that source. This is attribution for a bounded construction; the broader unreviewed preprint's derandomization claim is not an endpoint of this local module [openai-logspace26][openai-logspace26].

## Tree instances, gate tables, and native resources

[Tree](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Basic.lean#L48) is a perfect binary tree of height `H`. Each leaf contains an `ℓ`-bit value; each internal gate is an arbitrary function on two `ℓ`-bit values. The output is the root value. [Instance](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Instance.lean#L43) packages `ℓ,H` with the tree, giving one input type across all sizes.

The [injective instance encoding](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Instance.lean#L93) has unary header `1^ℓ 0 1^H 0`, then a preorder body: each gate's complete `4^ℓ·ℓ`-bit truth table and each leaf's `ℓ` bits. This is an explicit table input, not an oracle gate or a succinct circuit input. The native reader recomputes node offsets from paths and accesses the encoded input through the read-machine/step-machine route.

The algebraic [proc](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/CookMertz.lean#L97) uses three shared vector registers over a finite field. Given a repetition-free enumeration of all nonzero field elements and `2ℓ < |K|−1`, [proc_eq](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/CookMertz.lean#L152) adds a scalar multiple of the subtree value to the chosen register and restores the other registers, for arbitrary initial contents. Signed recursive calls undo temporary child values. Its correctness theorem is separate from the native space theorem, following the Cook–Mertz procedure and Goldreich's signed-call exposition [cookmertz24][cookmertz24] [goldreich-tree24][goldreich-tree24].

| Native endpoint | Exact scope |
|---|---|
| [computableInSpace_eval](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Space.lean#L67) | For all encoded instances, some time bound `t` gives native `ComputableInBigO` with space `O((ℓ+H+1)·log(ℓ+2)+log(n+2))`, where `n` is encoded input length |
| [computableInSpace_eval_log_mul_log_log](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Space.lean#L140) | On the subtype `ℓ≥1` and `H≥1`, native workspace is `O(bitlength(n)·bitlength(bitlength(n)))` |

Both use the independent-workspace convention: the output value is not charged to workspace. Time is existentially bounded, with no polynomial-time conclusion from these statements. On nontrivial instances the explicit tables and leaves make `2^ℓ,2^H ≤ n`; the source proves a factor-six bound converting the parameter budget to the bitlength product. The result therefore depends on the gate-table encoding as well as the algorithm. Cook–Mertz's report gives the corresponding `O(log n log log n)` Tree Evaluation theorem [cookmertz24][cookmertz24].

## Fan-in and packed-controller variants

[Ary.Tree d ℓ H](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Ary/Basic.lean#L56) permits `d` children with arbitrary gates on `d` values. The binary embedding preserves evaluation, and `Ary.proc_ofBinary` identifies the binary procedure with the `d=2` procedure on the same three registers. This is an explicit bridge between the problem variants, not an identification with a branching-program model.

The packed variant groups several bits per field symbol and interpolates on a chunk alphabet `A`, following the packing construction in Williams's Appendix A, equation (6). Signed recursive calls and sums over nonzero field elements allow arbitrary characteristic here, whereas that exposition uses characteristic two [williams25][williams25]; its strict unmasking condition is `d·r·(|A|−1) < |K|−1` for `r` chunks. `Ary/Packed.lean` proves decoding and algebraic correctness, while the separate [raw-controller native step](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/TreeEval/Ary/Packed/RawControllerNative.lean#L490) and `need_inSpace`/`halted_inSpace` certify local runtime-parameter operations in linear encoded-input space. These local contracts do not themselves supply a global time-to-space theorem. See [native counting](../machines-and-classes/native-counting.md) for the separately stated counting applications and [machine endpoints](../machines-and-classes/endpoints-and-hierarchies.md) for time-to-space results.

## Evidence and limits

This revision inspected the listed semantics, encodings, restoration equations, native endpoint statements and representative controller contracts at `13e6a31951bf1c89a1a6258c44f9444aecbbefd8`.
