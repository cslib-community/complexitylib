# Approximation and exact exponential algorithms

Part of the [representative algorithm endpoints](algorithm-endpoints.md); the conventions and limitations stated there apply to this page.

## Scheduling bounds

[CslibFrontier/Algorithms/Lean/Scheduling/](../../CslibFrontier/Algorithms/Lean/Scheduling/) contains
classical makespan bounds as mathematical statements about schedules. These are not runtime claims.
`IdenticalMachines.lean` models `P || C_max`: an assignment `σ : Fin n → Fin m` of jobs with
processing times `p : Fin n → α` (an ordered field for the ratio theorems). `IsListSchedule p σ`
is Graham's rule that each job goes to a least-loaded machine over the earlier jobs.
`listSchedule` computes such an assignment. `IsListSchedule.makespan_le_optMakespan` proves
`C ≤ (2 - 1/m) · OPT`, and `IsListSchedule.makespan_grahamTight` shows that the ratio is
attained for every `m`. `LPT.lean` defines `lptSchedule`, which applies `listSchedule` after
sorting by `lptOrder`, and proves `makespan_lptSchedule_le`: `C ≤ (4/3 - 1/(3m)) · OPT`.

`Precedence.lean` models `P | prec | C_max` in discrete time. Start times are `s : J → ℕ`,
processing times are natural numbers and `prec` is any relation; the bounds assume it is
well-founded. `IsFeasible` and `IsGreedy` are predicates on
schedules. `exists_isGreedy` constructs a greedy schedule for well-founded precedences and
positive processing times. `IsGreedy.exists_chain` is Graham's critical chain.
`IsGreedy.mul_makespan_le_of_le` is Graham's 1966 anomaly theorem. `Brent.lean` defines the
critical-path `span` and proves the work and span laws, the greedy bound
`m · T ≤ ∑ p + (m - 1) · span`, and Brent's lemma for unit-time DAGs
(`exists_isFeasible_mul_makespan_le`). Two limitations apply: processing times in the precedence
model are integers, and Graham's anomaly instances are not formalized.
[CslibFrontierTests/Scheduling.lean](../../CslibFrontierTests/Scheduling.lean) checks the tight
instances, nonvacuity of `IsGreedy`, a feasible schedule that is not greedy, and a zero-length
self-loop showing that the critical-chain theorem needs well-founded precedences.

## Greedy weighted set cover

Import `CslibFrontier.Algorithms.Lean.SetCover.Greedy` ([CslibFrontier/Algorithms/Lean/SetCover/Greedy.lean](../../CslibFrontier/Algorithms/Lean/SetCover/Greedy.lean)). This is a pure Lean function analyzed for solution quality, not a machine program with a step bound. `greedy S w J U` takes a ground set `U : Finset α`, sets `S : ι → Finset α`, weights `w : ι → 𝕜` in a linearly ordered field and a candidate list `J`. Each round it picks a candidate minimizing `w j / |S j ∩ R|` over the uncovered elements `R`, with ties going to the earliest candidate in `J`. It stops when no candidate meets `R` and returns the chosen candidates in order.

- **Feasibility:** `greedy_covers` needs every element of `U` to lie in some candidate set; `CslibFrontierTests/SetCoverGreedy.lean` shows the loop stopping with an incomplete cover when that fails. `nodup_greedy` and `length_greedy_le` bound the output by `U.card` distinct candidates.
- **Ratio, stated against any cover:** `sum_greedy_le_harmonic_mul` proves `cost ≤ H d · w(C)` for every cover `C` drawn from `J` whose sets meet `U` in at most `d` elements, given nonnegative candidate weights. Instantiating `C` with an optimal cover gives Chvátal's `H d` ratio. `sum_greedy_le_harmonic_card_mul` takes `d = |U|`, and `sum_greedy_le_one_add_log_mul` gives `(1 + log d) · w(C)` over `ℝ`.
- **Fractional form:** `sum_greedy_le_harmonic_mul_fractional` compares with every nonnegative fractional cover `x` instead. This is Theorem 1.12 of [Williamson and Shmoys][williamsonshmoys11] stated without the linear-programming API: the dual-fitting step and weak duality are merged into one inequality, and the caller supplies the fractional cover. Instantiating it with an LP optimum would go through the [duality theorems](optimization-and-duality.md#linear-programming-duality-over-ordered-fields); no set-cover LP is stated yet.

The [checked examples](../../CslibFrontierTests/SetCoverGreedy.lean) include an instance where greedy pays `11/6` against an optimum of `11/10`, inside the bound `121/60`. They also show a fractional cover strictly cheaper than every integral cover. Machine-level running time is open ([ROADMAP](../../ROADMAP.md#combinatorial-optimization)).

## Greedy submodular maximization over matroids and `p`-systems

Import `CslibFrontier.Algorithms.Lean.Submodular.MatroidGreedy` ([source](../../CslibFrontier/Algorithms/Lean/Submodular/MatroidGreedy.lean)) for the algorithm and its guarantees, and `CslibFrontier.Algorithms.Lean.Query.Submodular.MatroidGreedy` ([source](../../CslibFrontier/Algorithms/Lean/Query/Submodular/MatroidGreedy.lean)) for the oracle program. Like greedy set cover, this is analyzed for solution quality and query counts, not for machine running time. `submodularMatroidGreedy f indep xs` takes a value function `f : Finset α → β`, an independence test `indep : Finset α → Bool` and a ground list `xs`. Starting from `∅`, each round adds an element `c ∉ S` of `xs` with `indep (insert c S)` that maximizes `f (insert c S)`, with ties going to the earliest element of `xs`. It stops when no element can be added. This is the greedy algorithm of [Fisher, Nemhauser and Wolsey][fnw78], as described in [Călinescu et al.][ccpv11].

- **Constraint families:** `IsPSystem indep p` in [CslibFrontier/Algorithms/Lean/Matroid/PSystem.lean](../../CslibFrontier/Algorithms/Lean/Matroid/PSystem.lean) asks that `∅` is independent, that independence is inherited by subsets, and that any two maximal independent subsets `A, B` of a finite set satisfy `|A| ≤ p * |B|` ([Călinescu et al.][ccpv11], Section 1). `isPSystem_matroid` shows that every Mathlib `Matroid` is a `1`-system on finite sets, and `isPSystem_iInter_matroid` that the intersection of `k ≥ 1` matroids is a `k`-system. The analysis uses the blocking form `IsPSystem.card_le_mul_card_of_blocked`: if every element of an independent `T` outside an independent `S` is blocked by `S`, then `|T| ≤ p * |S|`.
- **Feasibility:** `indep_submodularMatroidGreedy` (the output is independent whenever `∅` is) and `not_indep_insert_submodularMatroidGreedy` (no element of `xs` can be added). Under a matroid oracle, `submodularMatroidGreedy_isBasis'` makes the output a basis of the ground list.
- **Ratio, stated against any independent set:** for monotone submodular `f`, a `p`-system `indep` and any independent `O ⊆ xs.toFinset`, `add_nsmul_le_succ_nsmul_submodularMatroidGreedy` proves `f O + p • f ∅ ≤ (p + 1) • f G` in any linearly ordered additive group. Over an ordered field with `0 ≤ f ∅`, `div_succ_le_submodularMatroidGreedy` gives `f O / (p + 1) ≤ f G`. Specializations: `half_le_submodularMatroidGreedy_of_matroid` (`1/2` for a matroid) and `div_card_succ_le_submodularMatroidGreedy_of_iInter_matroid` (`1/(k+1)` for `k` matroids). Nonnegativity of `f` is not assumed in the group form; it is replaced by the `f ∅` terms. The proof charges each element of `O` to the greedy rounds in which it was still feasible, and the blocking bound limits how many elements of `O` can stop being feasible early. This is a different bookkeeping from the explicit partition of `O` in [Călinescu et al.][ccpv11], Appendix B.
- **Modular objectives:** for nonnegative weights `w`, `sum_le_nsmul_sum_submodularMatroidGreedy` gives `∑ O w ≤ p • ∑ G w`, the `1/p` bound that [Călinescu et al.][ccpv11] attribute to Jenkyns, and `sum_le_sum_submodularMatroidGreedy_of_matroid` gives optimality over a matroid.
- **Tightness:** `exists_tight_submodularMatroidGreedy` gives a coverage objective and a partition matroid on three elements on which the greedy value is exactly half the value of an independent set.
- **Queries:** `submodularMatroidGreedyQuery xs` runs the same algorithm in `FreeM (SumQuery (ValueQuery α β) (IndepQuery α))`. `SumQuery` ([source](../../CslibFrontier/Algorithms/Lean/Query/SumQuery.lean)) charges value queries (`countInl`) and independence queries (`countInr`) separately. These counts describe this implementation, which re-tests every remaining element in each round; they are not claimed optimal. With `n` distinct ground elements and output `G`, `countInr_submodularMatroidGreedyQuery` gives exactly `∑ t ∈ range (|G| + 1), (n - t)` independence queries, and under a matroid oracle `|G|` is the rank of the ground list (`countInr_submodularMatroidGreedyQuery_of_isBasis'`). `countInl_submodularMatroidGreedyQuery` counts one value query per feasible candidate in each round, which is never more than the independence count. Each count is at most `n (n + 1) / 2`, and `submodularMatroidGreedyQuery_upperBound` bounds the total by `m (m + 1)` for ground lists of length at most `m`. `half_le_eval_submodularMatroidGreedyQuery` restates the `1/2` bound for the query program under `IndepQuery.ImplementsMatroid`.

The [checked examples](../../CslibFrontierTests/SubmodularMatroidGreedy.lean) run the tight instance, where greedy makes `6` independence and `4` value queries, also on a ground list with repeated elements. They also show that matchings of a three-edge path form a `2`-system (as the intersection of two partition matroids) but not a matroid, and that greedy gets exactly half of the maximum modular weight there, so the `1/p` bound is attained at `p = 2`. The continuous greedy with pipage rounding (`1 - 1/e` over a matroid), knapsack constraints and non-monotone objectives remain open ([ROADMAP](../../ROADMAP.md#combinatorial-optimization)).

## Vertex cover and metric TSP 2-approximations

Two more classical approximation algorithms are stated as plain inequalities against the optimum.

- **Vertex cover from a maximal matching.** Import `CslibFrontier.Computability.Complexity.Problems.VertexCover.Approximation` ([source](../../CslibFrontier/Computability/Complexity/Problems/VertexCover/Approximation.lean)); the generic algorithm is in `CslibFrontier/Algorithms/Lean/VertexCover/Matching.lean`. `matchingCover es` scans an edge list once, keeps every edge with distinct endpoints that are both still unmatched, and returns their endpoints. This is `APPROX-VERTEX-COVER` of [Cormen et al., Section 35.1][clrs09] with "an arbitrary remaining edge" read as "the first one in list order". `isVertexCover_matchingCover` proves feasibility, and `length_matchingCover_le_two_mul_vertexCoverNum` bounds the size by twice Mathlib's `vertexCoverNum`. The matching lower bound `length_le_encard_of_isVertexCover` is stated for any vertex cover. On the library's `Graph` encoding, `approxCover G` runs on the edges between declared vertices: `approxCover_mem_VertexCover` and `length_approxCover_le_two_mul_vertexCoverNum` compare it with `VertexCover` and `Graph.vertexCoverNum`, and `computableInPolyTime_approxCover` is a plain `ComputableInPolyTime` certificate from `encGraph`.
- **Metric TSP through a minimum spanning tree.** Import `CslibFrontier.Computability.Complexity.Problems.TSP.Approximation` ([source](../../CslibFrontier/Computability/Complexity/Problems/TSP/Approximation.lean)); the generic algorithm is in `CslibFrontier/Algorithms/Lean/TSP/MSTTour.lean`. `mstTour δ` computes Kruskal's minimum spanning tree of the complete graph on `Fin n` and grows a tour from vertex `0`: while some tree edge has exactly one endpoint on the tour, it inserts the other endpoint right after that one. `totalWeight_kruskalEdges_le_cycleCost` is Lemma 2.10 of [Williamson and Shmoys][williamsonshmoys11] (the tree costs at most any tour). `cycleCost_insertAfter_le` is the insertion step of their Theorem 2.11, which they prove for the nearest-addition algorithm on Prim's tree; here it is applied to Kruskal's tree. Together they give `cycleCost_mstTour_le_two_mul`. On `TSP` instances, `TSP.approxTour D` visits every city exactly once (`approxTour_perm`), and when `TSP.IsMetric D` holds, `tourLength_approxTour_le_two_mul` bounds its length by twice every tour's. `IsMetric` asks only for symmetry and the triangle inequality among cities. The triangle inequality covers all triples, including `i = k`, so each diagonal entry is at most twice any distance from its city; diagonal entries need not be zero (Williamson and Shmoys assume they are).

The [vertex-cover examples](../../CslibFrontierTests/VertexCoverApproximation.lean) pin the optimum of a path and a star exactly, so the factor `2` is attained. The [TSP examples](../../CslibFrontierTests/TSPApproximation.lean) include a matrix violating the triangle inequality where the tour costs `202` against a tour of cost `4`, so the metric hypothesis cannot be dropped. Concrete TSP runs first pin the sorted edge list with `simp [sortEdges_cons_cons]`, because `List.mergeSort` does not reduce in the kernel. No machine running time is certified for the TSP tour yet; that needs a polynomial-time certificate for Kruskal's algorithm on encoded matrices.

## Metric k-center: Gonzalez's 2-approximation and the dominating-set gap

Import `CslibFrontier.Algorithms.Lean.KCenter.Gonzalez` ([source](../../CslibFrontier/Algorithms/Lean/KCenter/Gonzalez.lean)) and `CslibFrontier.Algorithms.Lean.KCenter.DominatingSet` ([source](../../CslibFrontier/Algorithms/Lean/KCenter/DominatingSet.lean)). Like the set-cover and TSP algorithms above, Gonzalez's algorithm and the gap are pure Lean functions and statements analyzed for solution quality, with no running time; the Theorem 2.4 bullet below is the polynomial-time statement. A distance is any `d : V → V → α` into a linear order. The definitions are in [KCenter/Basic.lean](../../CslibFrontier/Algorithms/Lean/KCenter/Basic.lean): `centerDist d S v : WithTop α` is the distance from `v` to its nearest center in `S` (`⊤` when `S` is empty), `radius d S` is the largest such distance over a finite nonempty `V`, and `optRadius d k` is the least radius of a center set with at most `k` points. This is the k-center problem of Section 2.2 of [Williamson and Shmoys][williamsonshmoys11].

- **Gonzalez's algorithm.** `gonzalez d P k` is Algorithm 2.1 of Williamson and Shmoys, which their chapter notes attribute to Gonzalez (1985). Over a candidate list `P` it runs `k` rounds of `farthestStep`. Each round appends the first point of `P` maximizing `centerDist` to the centers chosen so far (`List.argmax`), so the first center is the head of `P`. `length_gonzalez` gives exactly `k` centers when `P` is nonempty. `nodup_gonzalez` makes them distinct when `d` vanishes exactly on the diagonal and `P` has at least `k` distinct points.
- **The ratio.** `radius_gonzalez_le_two_mul` is Theorem 2.3: if `d` is symmetric and satisfies the triangle inequality, `P` lists every point and `optRadius d k ≤ r`, the radius is at most `2 * r`. The bound is stated against every upper bound `r` on the optimum, which avoids multiplication in `WithTop α`; `radius_gonzalez_le_two_mul_optRadius` specializes it to the finite optimum when `k ≥ 1`. Unlike Williamson and Shmoys, it does not assume `d i i = 0`. The proof is a packing argument instead of their cluster argument. If a point were farther than `2r` from every center, then the centers and that point would be `k + 1` points pairwise farther than `2r` apart (`IsFarthestFirst.pairwise_lt`). `length_le_card_of_pairwise_lt` shows that `k` centers covering within `r` cannot cover such points. The analysis holds for every farthest-first traversal (`IsFarthestFirst`), whatever its first point or tie-breaking. `centerDist_gonzalez_le_two_mul` also allows the competing centers to lie outside `P`.
- **The gap behind Theorem 2.4.** `domDist G` gives a simple graph the metric with `0` on the diagonal, `1` on edges and `2` elsewhere. `radius_domDist_le_one_iff` shows that a center set has radius at most `1` exactly when it is a `SimpleGraph.IsDominatingSet` ([CslibFrontier/Foundations/Combinatorics/SimpleGraph/DominatingSet.lean](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/DominatingSet.lean)). `optRadius_domDist_le_one_iff` and `optRadius_domDist_eq_two` then give an optimum of `1` or `2`, depending on whether a dominating set of at most `k` vertices exists. `isDominatingSet_of_radius_le_mul` and `exists_isDominatingSet_iff_of_radius_le_mul` show that a `ρ`-approximate solution with `ρ < 2` and at most `k` centers is dominating exactly when such a set exists, so it decides dominating set. Williamson and Shmoys attribute the hardness to Hsu and Nemhauser (1979). NP-hardness of dominating set on the library's encoded graphs is `DominatingSet_npComplete` (import `CslibFrontier.Computability.Complexity.Problems.DominatingSet`, [source](../../CslibFrontier/Computability/Complexity/Problems/DominatingSet.lean)). It uses a reduction from `VertexCover` that sends `(G, k)` to a graph with a hub, a pendant, a copy of every vertex and a vertex for every edge, and the target `k + 1` (`0` when `k` exceeds the number of distinct vertices).
- **Theorem 2.4 on encoded instances.** Import `CslibFrontier.Computability.PCP.Approximation.KCenter` ([source](../../CslibFrontier/Computability/PCP/Approximation/KCenter.lean)). `P_eq_NP_of_kCenter_approx` states that a polynomial-time algorithm `A : List (List ℕ) × ℕ → List ℕ` with ratio `ρ < 2` gives `P = NP`. Instances are distance matrices with binary natural entries and a binary `k`, in the encoding `KCenter.encKCenter`, which pairs `KCenter.encDistMatrix` (`encList (encList encNat)`) with `encNat`. `A` returns point indices, read as the center set `KCenter.centers D (A (D, k))`, which ignores out-of-range indices and repetitions. The hypotheses are required only on metric instances (`KCenter.IsInstance`: square, zero diagonal, `TSP.IsMetric`) with `1 ≤ k ≤ D.length`, the instances of Section 2.2: at most `k` centers, and radius at most `ρ * r` for every bound `r` on `optRadius` with distances cast to `ℝ`. These restrictions only weaken the hypotheses. The reduction `KCenter.domMatrix` maps an encoded graph to its `{0, 1, 2}` matrix on the distinct declared vertices (`isInstance_domMatrix`, `computableInPolyTime_domMatrix`). The decider `KCenter.decideDominatingSet` checks `k` against the number of vertices and then checks whether the vertices named by `A`'s centers dominate the graph. `decideDominatingSet_iff` proves it correct through `isDominatingSet_of_radius_le_mul`, and `DominatingSet_npComplete` finishes the proof. The [hardness examples](../../CslibFrontierTests/KCenterHardness.lean) build the matrix of a path with repeated labels, reject non-instances, and run the decider on a middle center (accepted) and an endpoint center (rejected, radius `2` against `1`). They also show that an exact, non-polynomial algorithm meets the hypotheses with `ρ = 1`, and Gonzalez's algorithm, whose running time is not certified, with `ρ = 2`. Check them with `scripts/build.sh CslibFrontierTests.KCenterHardness`.

The [k-center examples](../../CslibFrontierTests/KCenter.lean) run Gonzalez on three points of a line at `0, 1, 2` with one center. It picks the endpoint and has radius `2`, while the middle point has radius `1`, so the factor `2` is attained. The same tight instance appears on the path `0 - 1 - 2` with `domDist`, where Gonzalez's center does not dominate, so the gap needs `ρ < 2`. A symmetric distance violating the triangle inequality makes Gonzalez pay `100` against an optimum of `1`. A distance vanishing between distinct points makes it repeat a center. The Hochbaum–Shmoys threshold algorithm, k-supplier and k-median are open ([ROADMAP](../../ROADMAP.md#combinatorial-optimization)).

## Exact exponential algorithms: Bellman–Held–Karp

Import `CslibFrontier.Algorithms.Lean.TSP.HeldKarp` ([source](../../CslibFrontier/Algorithms/Lean/TSP/HeldKarp.lean)) for the algorithm and `CslibFrontier.Computability.Complexity.Problems.TSP.HeldKarp` ([source](../../CslibFrontier/Computability/Complexity/Problems/TSP/HeldKarp.lean)) for the decision problems. Like the set-cover algorithm above, `heldKarp d` is a pure Lean program, here in cslib's `TimeM ℕ` tick monad, not a machine program. The cities are `Fin (n + 1)` and `d` is any cost function into a linearly ordered additive commutative monoid: costs may be asymmetric, non-metric or negative (`ℤ`), or `⊤` for a missing edge (`WithTop ℕ`). Tours start and end at city `0`. `walkCosts d S t` is the set of costs of the walks that leave `0`, visit each city of `S ⊆ {1, …, n}` once and then move to `t`. The table entry for `(S, t)` with `t = i + 1`, `i ∉ S`, is the Held–Karp value `C(S ∪ {t}, t)` of [Bellman][bellman62] and [Held and Karp][heldkarp62] ([Fomin and Kratsch, Section 1.2][fominkratsch10]). The table also holds an entry `(S, 0)` for every `S`, the least cost from `0` through `S` back to `0`; only `(univ, 0)`, the optimal tour, is read, and Held and Karp compute it by a separate closing minimization. Walk and closed-walk costs (`walkCost`, `cycleCost`, `cycleCost_cons`, `cycleCost_rotate`, `cycleCost_append_comm`) live in `CslibFrontier.Algorithms.Lean.TSP.Walk`, shared with the MST tour above.

- **Correctness:** `isLeast_heldKarp` proves that `(heldKarp d).ret` is the least element of `walkCosts d univ 0`; `isLeast_heldKarp_permutations` restates this against brute force over all permutations of `1, …, n`. The proof goes through Bellman's principle `isLeast_walkCosts_of_forall` and the table invariant `HeldKarp.isLeast_tableM`.
- **Cost:** `time_heldKarp_le` bounds the ticks by `n² · 2ⁿ`. A tick is one candidate `T (S \ {i}, i) + d i t`, i.e. one addition and one comparison in `W`, whatever the size of the numbers. Table reads and writes and the enumeration of subsets are free, and `TimeM` does not measure the `2ⁿ (n + 1)`-entry table.
- **Decision problems:** `TSP.mem_TSP_iff_heldKarp_le` identifies `TSP` membership of a matrix with `n + 1` rows with `heldKarp` on its `dist` entries; this uses `TSP.tourLength_eq_cycleCost` and the rotation invariance `cycleCost_append_comm`, which turns a tour `A ++ 0 :: B` into one starting at city `0`. `TSP.heldKarpDecide` decides `TSP` (`heldKarpDecide_eq_true_iff`) in `(n - 1)² · 2ⁿ⁻¹` ticks on `n` cities, and composed with the polynomial-time reduction `HamCycle.toTSP` it decides `HamCycle` within the same bound in the number of distinct vertices. No machine-level certificate is given: the bounds count unit-cost operations, not Turing-machine or word-RAM steps.

The [checked examples](../../CslibFrontierTests/TSPHeldKarp.lean) compare a four-city optimum with all six tours, use negative integer costs, cover the one-city edge case and the empty `TSP` instance, and decide `HamCycle` on a triangle (yes) and a three-vertex path (no). Inclusion–exclusion counting of Hamiltonian paths in `2ⁿ · poly(n)` time and polynomial space is open ([ROADMAP](../../ROADMAP.md#search-parameterized-and-fine-grained-complexity)).

## Goemans–Williamson MAX-CUT rounding

Import `CslibFrontier.Algorithms.Lean.MaxCut.GoemansWilliamson` ([GoemansWilliamson.lean](../../CslibFrontier/Algorithms/Lean/MaxCut/GoemansWilliamson.lean)). This analyzes random-hyperplane rounding of a given vector solution of the MAX-CUT semidefinite relaxation [Goemans and Williamson, Sections 2–3][goemanswilliamson95]. The rounding is an expectation under Mathlib's exact `stdGaussian`; no SDP solver, finite-precision sampler or running time is involved. A weighted multigraph is a `Fintype` of edges `ι` with `ends : ι → V × V` and weights `w : ι → ℝ`. `cutValue ends w side` is the weight of a cut and `sdpValue ends w v = ∑ e, w e * (1 - ⟪v (ends e).1, v (ends e).2⟫) / 2` is the relaxation's objective at a vector assignment `v : V → F`. `hyperplaneSide v r i = decide (0 ≤ ⟪v i, r⟫)` is the rounded cut. The source draws `r` uniformly from the sphere; the side depends only on the direction of `r`, so a standard Gaussian gives the same distribution.

- **The constant:** `Real.goemansWilliamsonConstant` ([GoemansWilliamson.lean](../../CslibFrontier/Foundations/Analysis/SpecialFunctions/GoemansWilliamson.lean)) is `α = inf_{0 < θ ≤ π} (2 / π) θ / (1 - cos θ)`. `goemansWilliamsonConstant_mul_le_arccos` is Lemma 3.4 (`α (1 - y) / 2 ≤ arccos y / π` on `[-1, 1]`). `lt_goemansWilliamsonConstant` is Lemma 3.5 (`0.87856 < α`), and `goemansWilliamsonConstant_lt` gives `α < 0.87857`. The numerics use the source's tangent-line argument at `θ₀ = π - 0.810474`, with degree-ten Taylor bounds `Real.cos_bound_ten` and `Real.sin_bound_ten` ([Trigonometric/Bounds.lean](../../CslibFrontier/Foundations/Analysis/SpecialFunctions/Trigonometric/Bounds.lean)) and Mathlib's six-digit bounds on `π`.
- **Expectation:** `integral_cutValue_hyperplaneSide` is Theorem 3.1 (expected weight `∑ e, w e * arccos ⟪…⟫ / π` for unit vectors), from Sheppard's formula (`measureReal_stdGaussian_zero_mem_uIoc_eq_arccos`, the source's Lemma 3.2). `goemansWilliamsonConstant_mul_sdpValue_le_integral` is Theorem 3.3 for nonnegative weights.
- **Guarantee against the true optimum:** `sdpValue_signVector` shows that a cut's `±u` vector solution has objective equal to the cut's weight. Hence `goemansWilliamsonConstant_mul_sub_le_integral` gives `α (cutValue side - ε) ≤ E[cutValue (hyperplaneSide v r)]` for every cut `side`, when `v` are unit vectors within `ε` of optimal. `goemansWilliamsonConstant_mul_cutValue_le_integral` is the exact-optimum form. `exists_forall_goemansWilliamsonConstant_mul_sub_le` picks one hyperplane achieving the bound, and `exists_isMaxOn_sdpValue` shows that optimal unit vectors exist in every nontrivial finite-dimensional space.
- **Bridge:** in [GoemansWilliamsonCutWeight.lean](../../CslibFrontier/Algorithms/Lean/MaxCut/GoemansWilliamsonCutWeight.lean), kept separate so the analysis does not import the machine-level `MaxCut` development, `cutValue_eq_cutWeight` identifies `cutValue` on an edge list with `Cslib.Complexity.MaxCut.cutWeight`, the weight used by the NP-complete `MaxCut` problem. `goemansWilliamsonConstant_mul_cutWeight_le_integral` restates the guarantee there.

The [checked examples](../../CslibFrontierTests/GoemansWilliamsonMaxCut.lean) use the triangle with three unit vectors at `120°`. Their objective `9 / 4` is optimal because `‖a + b + c‖² ≥ 0`, so the headline hypotheses are satisfiable. The rounded cut has expected weight exactly `2`, the maximum cut. Not formalized: polynomial-time SDP solving to precision `ε`, a `ProbComp` realization of the Gaussian, tightness (the Feige–Schechtman integrality gap), the MAX-2SAT and MAX-DICUT extensions and derandomization ([#3230](https://github.com/cslib-community/cslib-frontier/issues/3230)).

## Christofides' 3/2-approximation for metric TSP

Import `CslibFrontier.Computability.Complexity.Problems.TSP.Christofides` ([source](../../CslibFrontier/Computability/Complexity/Problems/TSP/Christofides.lean)); the generic algorithm is in `CslibFrontier/Algorithms/Lean/TSP/Christofides.lean`. It uses the cost model of the MST 2-approximation above: vertices `Fin n`, costs `δ : Fin n → Fin n → ℕ` and closed-walk cost `cycleCost δ`. `christofides δ` takes Kruskal's tree `T` of the complete graph and the odd-degree vertices `oddVertices T`. It computes a minimum-weight perfect matching `M` on them with `minPerfectMatching`, runs Hierholzer's `eulerCircuit` on the edge list `T.map WeightedEdge.endpoints ++ M` (the multigraph `T ⊎ M`, where an edge in both appears twice) from vertex `0`, and shortcuts the result with `List.dedup`. A perfect matching on `O` is an edge list whose `VertexCover.endpoints` are a permutation of `O`. The proof follows Theorem 2.13 of [Williamson and Shmoys][williamsonshmoys11] ([Christofides][christofides76]):

- **Handshake:** `Euler.even_length_filter_odd_degree` ([Handshake.lean](../../CslibFrontier/Algorithms/Lean/Euler/Handshake.lean)) holds for list multigraphs with parallel edges and self-loops. It gives `even_length_oddVertices`.
- **Shortcutting:** `cycleCost_le_of_sublist` ([Shortcut.lean](../../CslibFrontier/Algorithms/Lean/TSP/Shortcut.lean)) says that under the triangle inequality, a subsequence of a closed walk costs no more. `cycleCost_dedup_le_of_isEulerCircuit` bounds a shortcut Euler circuit by the weight of its multigraph. `List.dedup` keeps the last visit to each vertex, whereas the textbook keeps the first; both are subsequences.
- **Matching bound:** `two_mul_sum_le_cycleCost` ([PerfectMatching.lean](../../CslibFrontier/Algorithms/Lean/TSP/PerfectMatching.lean)) shows that a minimum-weight perfect matching on `O` costs at most half of any tour through `O`. The tour is shortcut to `O` and its edges are split into two alternating perfect matchings. This step needs no symmetry.
- **Bound:** `two_mul_cycleCost_shortcutTour_le_three_mul` holds for any `IsMinSpanningTree` and any minimum-weight perfect matching on its odd vertices. `two_mul_cycleCost_christofides_le_three_mul` is the algorithm's instance. On `TSP` instances, `christofidesTour_perm` and `two_mul_tourLength_christofidesTour_le_three_mul` state `2 · length ≤ 3 · length(p)` for every tour `p` of a metric matrix (`TSP.IsMetric`, as above).

`minPerfectMatching` is exhaustive search over `(2k − 1)!!` matchings, with optimality proved by `sum_minPerfectMatching_le`. So these results certify the approximation ratio, not a polynomial running time. Edmonds' weighted matching algorithm ([Edmonds][edmonds65]) and any machine-level certificate remain open. The [examples](../../CslibFrontierTests/TSPChristofides.lean) run the algorithm on a four-city star whose three perfect matchings cost `5`, `6` and `6`; exhaustive search picks the cheapest. The Euler circuit `[0, 1, 2, 0, 3, 0]` is shortcut to an optimal tour of length `11`. The examples also instantiate the general bound with Kruskal's tree, and check the empty and one-city instances.

## Steiner tree through a minimum spanning tree

Import `CslibFrontier.Algorithms.Lean.SteinerTree.Metric` ([source](../../CslibFrontier/Algorithms/Lean/SteinerTree/Metric.lean)) and `CslibFrontier.Algorithms.Lean.SteinerTree.Graph` ([source](../../CslibFrontier/Algorithms/Lean/SteinerTree/Graph.lean)). Both state the approximation ratio as a plain inequality against the optimum; no running time is charged.

- **Metric version.** Points have any type `α` and cost `δ : α → α → ℕ`. A solution is an edge list `T : List (α × α)` whose generated equivalence relation joins every two terminals (`Connects T R`). It may pass through non-terminal Steiner points. `steinerOpt δ R` is the least `edgeCost δ T`. Because costs are nonnegative, this equals the least cost of a connecting tree. `steinerMST δ R` runs Kruskal's algorithm on the complete graph on the indices of the terminal list `R`. `edgeCost_steinerMST_le_two_mul_steinerOpt` is Exercise 2.5(a) of [Williamson and Shmoys][williamsonshmoys11]: for symmetric `δ` with the triangle inequality and duplicate-free `R`, the tree costs at most `2 · OPT`. Williamson and Shmoys attribute this factor to Moore, as described by [Gilbert and Pollak][gilbertpollak68]. `length_mul_edgeCost_steinerMST_le` proves the sharper `|R| · MST ≤ 2 (|R| - 1) · cost(T)` for every connecting `T`. The proof doubles `T`, takes Hierholzer's Euler circuit and shortcuts it to the terminals with `cycleCost_le_of_sublist`. It then drops the most expensive edge of the resulting Hamiltonian cycle (`mul_totalWeight_kruskalEdges_le`, which sharpens Lemma 2.10 to `k · MST ≤ (k - 1) · cost(C)`). When the diagonal cost is zero (`∀ x, δ x x = 0`), repeated terminals do not increase the cycle cost, and the bounds hold for arbitrary terminal lists (`length_mul_edgeCost_steinerMST_le_of_diag`, `edgeCost_steinerMST_le_two_mul_of_diag`). [Kou, Markowsky and Berman][kmb81] prove `2 (1 - 1/ℓ)`, with `ℓ ≤ |R|` the number of leaves of an optimal tree; that leaf bound is not formalized.
- **Graph version.** The graph is a Mathlib `SimpleGraph V` with weights `w : Sym2 V → ℕ`, which need not satisfy the triangle inequality. A solution is a finite set `F` of edges of `G` whose spanning subgraph `fromEdgeSet F` joins every two terminals (`IsSteinerSubgraph`), and `graphSteinerOpt w G R` is the least `F.sum w`. Shortest walks come from an oracle `P : ∀ u v, G.Walk u v` such that no walk is cheaper (`IsShortestWalkOracle`). Any shortest-path algorithm can supply it. `exists_isShortestWalkOracle` builds one on any preconnected graph (and the walks of any oracle show that `G` is preconnected), and `IsShortestWalkOracle.walkWeight_eq` identifies its costs with the metric completion `metricCompletion w G`. `kmbEdges w P R` runs `steinerMST` on these costs and takes the union of the edges of the walks along the tree edges. This is steps 1–3 of the Kou–Markowsky–Berman heuristic. Steps 4–5 (a spanning tree of the union, then pruning non-terminal leaves) can only lower the cost and are not formalized. `isSteinerSubgraph_kmbEdges` proves feasibility, and `sum_kmbEdges_le_two_mul_graphSteinerOpt` (Exercise 2.5(b)) and `length_mul_sum_kmbEdges_le` prove the bounds. A shared edge is paid for once, so the union costs at most the sum of the walk costs (`sum_expandEdges_le`). Because shortest-walk oracle costs have a zero diagonal (`walkWeight w (P x x) = 0`), the graph bounds use the zero-diagonal metric variant `length_mul_edgeCost_steinerMST_le_of_diag` and hold for arbitrary terminal lists without assuming `R.Nodup`.

The [examples](../../CslibFrontierTests/SteinerTree.lean) take a star metric with centre `0` at distance `1` from three terminals that are `2` apart. Kruskal's tree on the terminals costs `4`, while the optimum through the Steiner point is exactly `3`, so the sharp bound `3 · 4 = 2 · 2 · 3` is attained. Two counterexamples show that the hypotheses are needed. Without the triangle inequality the tree costs `20` against `3`. With a repeated terminal (constant cost `5`, terminals `[1, 1]`) it costs `5` against `0`. Here the diagonal cost `δ 1 1 = 5` is positive. On the star graph `K_{1,3}`, every Steiner subgraph for the leaves contains the whole star, and `kmbEdges` returns exactly the star for every choice of walks. On a triangle with one edge of weight `10`, the heuristic never uses that edge to join its endpoints. Remaining work is listed in the [ROADMAP](../../ROADMAP.md#combinatorial-optimization): the leaf bound, Robins–Zelikovsky and Byrka et al., NP-hardness, and a running-time certificate.
