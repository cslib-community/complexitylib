# Dynamic programming and string algorithms

Part of the [representative algorithm endpoints](algorithm-endpoints.md); the conventions and limitations stated there apply to this page.

## Context-free membership and CYK

Like Bellman–Ford, this is a pure Lean function with a `TimeM` cost model, not a machine program.

- **Grammars in Chomsky normal form.** Import `CslibFrontier.Computability.Languages.ChomskyNormalForm` ([source](../../CslibFrontier/Computability/Languages/ChomskyNormalForm.lean)). A `ChomskyNormalFormGrammar` has a list of rules `A → a` (`leaf`) and `A → B C` (`node`), and a flag `nilRule` for the rule `S → ε`. Sipser's definition [Sipser, Definition 2.8][sipser13] forbids the start symbol on every right-hand side; the bundled invariant forbids it only when `nilRule` is set, so Hopcroft, Motwani and Ullman's `ε`-free form, with the start symbol allowed on right-hand sides, is covered too. `toCFG` reads the grammar as a Mathlib `ContextFreeGrammar`, and every statement is about Mathlib's `Derives` and `language` for it. `derives_iff_of_ne_nil` describes the derivations of a nonempty word by a first rule and a split. It rests on `ContextFreeGrammar.derives_append_iff` in [Foundations/Computability/ContextFreeGrammar.lean](../../CslibFrontier/Foundations/Computability/ContextFreeGrammar.lean), which splits a derivation from `u ++ v` into derivations from `u` and from `v`.
- **CYK.** Import `CslibFrontier.Algorithms.Lean.CYK.Basic` ([source](../../CslibFrontier/Algorithms/Lean/CYK/Basic.lean)). `cyk G w` fills the table of nonterminals deriving each subword, level by level, following [Kasami][kasami65], [Younger][younger67] and [Hopcroft, Motwani and Ullman, Section 7.4.4][hmu06]. `mem_table_iff` says that each cell lists exactly the nonterminals deriving its subword. `cyk_eq_true_iff` says that `cyk G w = true` iff `w ∈ G.toCFG.language`, and `decidableMemLanguage` makes membership decidable. `time_cykM` gives the exact cost `(|R| + 1) (n + C(n + 1, 3))` for `|R|` rules and a word of length `n`, and `time_cykM_le` bounds it by `(|R| + 1) (n + 1)³`. One unit is charged per rule examined in each scan, and per split point (or letter) read. Table reads and writes, cell membership tests and insertions are constant-time steps, as on a RAM holding an array of nonterminal sets. Insertion skips nonterminals already present, and `nodup_table_and_length_le` shows that every cell is a list without repetitions of at most `|R|` nonterminals. The pure `cyk` is a specification for proofs and `decide`, not a fast executable (its table is a chain of function updates); the cost statements concern `cykM`.

The [CYK examples](../../CslibFrontierTests/Algorithms/Lean/CYK.lean) decide accepted and rejected words, including the empty word, for `{aⁿbⁿ}` and for balanced parentheses with `S → ε`, using `decide`, and check exact tick counts. This is the algorithm of [Sipser, Theorem 7.16][sipser13] (every context-free language is in P) **only for grammars already in Chomsky normal form**. Conversion of arbitrary grammars, a machine-level `ComputableInPolyTime` decider, Valiant's subcubic parsing, the pumping lemma, and CFG emptiness and universality are not formalized ([ROADMAP](../../ROADMAP.md#structure-time-and-space), [#3303](https://github.com/cslib-community/cslib-frontier/issues/3303)).

## Edit distance and longest common subsequence

Like CYK, these are pure Lean functions with a `TimeM` cost model, not machine programs.

- **Tables over pairs of suffixes.** Import `CslibFrontier.Algorithms.Lean.EditDistance.Grid` ([source](../../CslibFrontier/Algorithms/Lean/EditDistance/Grid.lean)). A `GridDP` holds the four rules of a table indexed by pairs of suffixes of two words: the corner, the two borders, and the interior entry from its three neighbours. `GridDP.value` fills the table row by row, and the row of `a :: x` is computed from the row of `x` alone. The textbook tables are indexed by prefixes. Indexing by suffixes is the same program run on the reversed words. `value_cons_cons` and the border lemmas restate the rules. `ret_valueM` and `time_valueM` show that the `TimeM` version returns `value` and costs exactly `(|x| + 1) (|y| + 1)`. One unit is charged per entry, and an entry is one rule application to neighbours at the heads of the current and previous rows. `TimeM` does not track space, so the two-row space bound is only a property of the definition.
- **Edit distance (Wagner–Fischer).** Import `CslibFrontier.Algorithms.Lean.EditDistance.Basic` ([source](../../CslibFrontier/Algorithms/Lean/EditDistance/Basic.lean)). `Costs α` gives arbitrary natural-number costs `del`, `ins` and `sub`. `Costs.unit` gives the Levenshtein distance. `Costs.indel` charges `1` per insertion or deletion and `2` per replacement by a different letter; such replacements are allowed, and `optScript Costs.indel` may return them. An `EditScript` is a list of operations `del a`, `ins b`, `sub a b`, with `src`, `tgt` and `cost`. This is an alignment, or a trace in the sense of [Wagner and Fischer][wagnerfischer74]. `editDist C x y` is the table entry, with the recurrence `editDist_cons_cons` (see also [CLRS, Problem 15-5][clrs09] and [Kleinberg and Tardos, Section 6.6][kleinbergtardos06]). `isLeast_editDist` says that `editDist C x y` is the least cost of a script from `x` to `y`. The lower bound is `editDist_le_cost`. `optScript` reads an optimal script off the table (`src_optScript`, `tgt_optScript`, `cost_optScript`). `ret_editDistM` and `time_editDistM` show that the algorithm costs exactly `(|x| + 1) (|y| + 1)`.
- **Longest common subsequence.** Import `CslibFrontier.Algorithms.Lean.EditDistance.LCS` ([source](../../CslibFrontier/Algorithms/Lean/EditDistance/LCS.lean)). `lcsLength x y` is the table of [CLRS, Section 15.4][clrs09], whose recurrence is `lcsLength_cons_cons` (Theorem 15.1). Subsequences are `List.Sublist`. `isGreatest_lcsLength` says that `lcsLength x y` is the greatest length of a common subsequence. The upper bound is `length_le_lcsLength`, and `lcs` reads a witness off the table (`lcs_spec`). `editDist_indel_add_two_mul` is the duality `editDist Costs.indel x y + 2 · lcsLength x y = |x| + |y|`. `isLeast_editDist_indel` shows that replacements gain nothing under `Costs.indel`: `splitSubs` turns each into a deletion and an insertion at the same cost, so `editDist Costs.indel x y` is also the least cost of a script without them (`EditScript.IsIndel`), the insertion–deletion distance. `ret_lcsLengthM` and `time_lcsLengthM` give the exact cost `(|x| + 1) (|y| + 1)`.

The [examples](../../CslibFrontierTests/Algorithms/Lean/EditDistance.lean) use `decide`. They check kitten/sitting (`3`, with its traceback), flaw/lawn (`2`), and empty words. They check costs that are neither unit nor symmetric, where a replacement beats a deletion plus an insertion but a swap does not. They check the strings of the running example of CLRS Section 15.4 (`lcsLength = 4`), a replacement returned by `optScript Costs.indel` next to an equal-cost script without it, and the exact tick counts.

**Scope.** Costs are arbitrary: no triangle inequality or symmetry is assumed. The theorem is the trace (alignment) form of Wagner–Fischer. The equivalence with sequences of edit operations applied at arbitrary positions, which Wagner and Fischer prove under their cost conditions, is not formalized. For unit costs, neither the metric properties nor the characterization as the least number of single-letter edits is formalized. Also not formalized: Hirschberg's linear-space recovery of an optimal alignment, a machine-level `ComputableInPolyTime` statement, and the `OV` hardness of edit distance and LCS ([#3472](https://github.com/cslib-community/cslib-frontier/issues/3472), [#3037](https://github.com/cslib-community/cslib-frontier/issues/3037)).

## Optimal binary search trees and the Knuth–Yao speedup

Like CYK, these are pure Lean functions with `TimeM` cost models that fill a triangular table by interval length; they are not machine programs. Import `CslibFrontier.Algorithms.Lean.OptimalBST.Knuth`.

- **The recurrence.** [Basic.lean](../../CslibFrontier/Algorithms/Lean/OptimalBST/Basic.lean) works with an arbitrary interval weight `w : ℕ → ℕ → β` over a linearly ordered additive monoid. `IsBST i j t` says that `t : BinaryTree ℕ` is a search tree whose keys are exactly `i + 1, …, j` (`isBST_iff` relates it to the `Cslib.DataStructure.SearchTree` invariant). `treeCost w i j t` charges `w i' j'` at each node whose subtree holds the keys `i' + 1, …, j'`. For access weights `p` and failure weights `q`, `knuthWeight p q i j = ∑_{i<k≤j} p k + ∑_{i≤g≤j} q g`. `treeCost_knuthWeight` shows that this weight gives the weighted search cost: `p k` times the depth of key `k` plus one, plus `q g` times the number of keys compared by an unsuccessful search in gap `g`. The expected cost `e[1, n]` of [CLRS 15.5][clrs09] also counts the dummy leaf, so it is this cost plus `∑ q g`. `optCost` is the recurrence `c(i, j) = w(i, j) + min_{i<k≤j} (c(i, k−1) + c(k, j))`. `isLeast_optCost` proves that it is the least cost of a tree on the keys, attained by `optTree`, which is read off the largest minimizing roots `optRoot`. No hypothesis on `w` is needed.
- **Yao's lemma and root monotonicity.** [Yao.lean](../../CslibFrontier/Algorithms/Lean/OptimalBST/Yao.lean) defines `QuadrangleIneq` and `MonotoneOnIntervals`. `quadrangleIneq_optCost` says that when `w` has both properties, `optCost w` satisfies the quadrangle inequality [Yao 1980][yao80b]. In an ordered cancellative monoid, `optRoot_mono` then gives `optRoot w i (j−1) ≤ optRoot w i j ≤ optRoot w (i+1) j` for the largest optimal roots, which is Knuth's monotonicity theorem for this problem [Knuth 1971][knuth71]. `knuthWeight` satisfies the quadrangle inequality with equality (`knuthWeight_add_knuthWeight`), and it is monotone on intervals when `p, q ≥ 0`.
- **The algorithms.** [Knuth.lean](../../CslibFrontier/Algorithms/Lean/OptimalBST/Knuth.lean) fills the table by increasing interval length. `TimeM` charges one tick per candidate root scanned. Table accesses, additions, comparisons, evaluations of `w` and tree extraction are free, and the table is a function, not a RAM array. The cubic program `plainBST` returns `(optCost w 0 n, optTree w 0 n)` for every weight (`ret_plainBST`, `isOptimal_plainBST`) and scans exactly `n(n+1)(n+2)/6` candidates (`time_plainBST`). Knuth's `knuthBST` scans only the window `optRoot(i, j−1), …, optRoot(i+1, j)`. Under the two hypotheses it returns the same solution (`ret_knuthBST`, `isOptimal_knuthBST`), and it scans at most `2n²` candidates (`time_knuthBST_le`), because the windows along each diagonal telescope. `knuthBST_knuthWeight` packages both results for nonnegative `p` and `q`. The constant `2` is not Knuth's sharper count.

The [tests](../../CslibFrontierTests/OptimalBST.lean) check both algorithms on the five-key example of [CLRS 15.5][clrs09] (weights scaled by 100). Both return cost `235`, so `e[1, 5] = 2.75`. The returned tree has root `4`, whereas CLRS draws the root `k₂`; both trees cost `235`. The tests also check both algorithms against brute force over all search trees for `n ≤ 4`. Three small weights show that each hypothesis is needed. If both fail, or the weight is monotone but violates the quadrangle inequality, or it satisfies the inequality but is not monotone, `knuthBST` returns a cost above the optimum, while `plainBST` stays optimal.

The Hu–Tucker and Garsia–Wachs `O(n log n)` algorithms for the alphabetic case (`p = 0`), Word-RAM realizations, and the SMAWK and Monge-matrix generalizations are not formalized. Neither is matrix-chain multiplication, whose cost does not satisfy the hypotheses in general.

## String algorithms

String algorithms are written in `Cslib.Algorithms.Lean.TimeM` and charge one tick per character comparison. Array reads and writes, index arithmetic, allocation and list/array conversions are free. Exact matching against a single pattern is Knuth–Morris–Pratt ([source](../../CslibFrontier/Algorithms/Lean/KMP/Search.lean)). It makes at most `2 * (|p| - 1) + 2 * |t|` comparisons (`kmpSearchM_time_le`), and `mem_kmpMatchesList_iff` characterizes its output.

Suffix arrays index one text for many patterns. Import `CslibFrontier.Algorithms.Lean.SuffixArray.Basic`, `.Kasai` and `.Search` ([Basic](../../CslibFrontier/Algorithms/Lean/SuffixArray/Basic.lean), [Kasai](../../CslibFrontier/Algorithms/Lean/SuffixArray/Kasai.lean), [Search](../../CslibFrontier/Algorithms/Lean/SuffixArray/Search.lean)). The alphabet is any `LinearOrder`, ordered with Mathlib's lexicographic order on lists, so a proper prefix comes before the words that extend it. No end-of-word sentinel is assumed, and only the nonempty suffixes `w.drop i` with `i < |w|` are listed.

- **Specification.** `IsSuffixArray w sa` says that `sa` is a permutation of `List.range w.length` whose suffixes strictly increase [Manber and Myers][manbermyers93]. `IsSuffixArray.unique` shows that suffix arrays are unique. `suffixArray w` sorts the positions by their suffixes with `List.mergeSort`, and `isSuffixArray_suffixArray` proves it correct. This reference construction is uncharged and not linear-time.
- **LCP array.** `lcpArray w sa` has `0` at rank `0` and the longest-common-prefix length (`List.lcpLen`, in [Foundations/Data/List/CommonPrefix.lean](../../CslibFrontier/Foundations/Data/List/CommonPrefix.lean)) of the suffixes of ranks `r - 1` and `r` at rank `r > 0`. `IsSuffixArray.getElem_lcpArray_sub_one_le` is the height lemma `lcp[rank[i + 1]] ≥ lcp[rank[i]] - 1` of [Kasai et al.][kasai01].
- **Kasai et al.'s algorithm.** `kasaiM w sa` visits positions in text order. It extends each common prefix from the previous length minus one. `ret_kasaiM` and `kasai_eq_lcpArray` show that it returns `lcpArray` whenever `sa` is a suffix array. `kasaiM_time_le` bounds its cost by `2 * |w|` comparisons for every input, valid suffix array or not. Building the rank array is uncharged.
- **Pattern search.** `searchM w sa p` runs two binary searches (`lowerBoundM`, in `CslibFrontier.Algorithms.Lean.BinarySearch`) and returns a rank interval `[lo, hi)`. Each probe compares `p` with at most `|p|` characters of a suffix. `searchM_spec` shows that the suffix of rank `r` starts with `p` exactly when `lo ≤ r < hi`, so the occurrences form a contiguous interval of the suffix array. `mem_occurrences` turns this into membership of text positions. `searchM_time_le` bounds the cost by `2 * |p| * (⌊log₂ |sa|⌋ + 1)` comparisons. This is the plain `O(|p| log n)` search. The `O(|p| + log n)` search, which reuses precomputed LCP information between probes, is not formalized.

For the empty pattern the search returns every position `i < |w|`. KMP also reports the position `|w|` of the empty suffix. The [examples](../../CslibFrontierTests/SuffixArray.lean) check `banana` and `mississippi`: the suffix and LCP arrays, the comparison counts, and agreement with KMP on several patterns. They also include a kernel-checked suffix array with its uniqueness, a rejected non-sorted permutation, and absent and empty patterns. Linear-time construction (SA-IS, DC3), LCP-accelerated search and suffix trees remain open ([ROADMAP](../../ROADMAP.md#string-algorithms)).

### The Z-algorithm

Import `CslibFrontier.Algorithms.Lean.ZFunction.Search` ([Basic.lean](../../CslibFrontier/Algorithms/Lean/ZFunction/Basic.lean), [Search.lean](../../CslibFrontier/Algorithms/Lean/ZFunction/Search.lean)). The Z-function of a word `s` is `zFunction s`, whose entry at `i < |s|` is `List.lcpLen s (s.drop i)`. Positions are `0`-based and `z[0] = |s|`; [Gusfield][gusfield97] (§1.3–1.4) indexes from `1` and leaves `Z_1` undefined. `zAlgorithmM s` is the Z-algorithm of §1.4. It keeps the rightmost box `[l, r)` that repeats a prefix of `s`. Inside the box it copies `z[i - l]` when that is less than `r - i`, and otherwise extends from `max r i` with the suffix-array primitive `extendM`. `ret_zAlgorithmM` and `zAlgorithm_eq_zFunction` prove that it returns `zFunction s` for every input. `zAlgorithmM_time_le` bounds the cost by `2 * |s| - 3` comparisons (natural subtraction, so `0` for `|s| ≤ 1`) for every input, an explicit form of the linear bound of §1.4. The tests check that `a ^ (n - 1) b` attains the bound for small `n`; a general tightness theorem is not formalized. The cost model is the one above. The copy test `z[i - l] < r - i` and the array reads are free.

For exact matching (§1.5), `zMatchesM p t` computes the Z-function of `p ++ t` and reports the shifts `i ≤ |t|` whose value at `|p| + i` is at least `|p|`. Gusfield's separator `$` is not used, so values above `|p|` are allowed. `mem_zMatches_iff` characterizes the output, `zMatches_eq_kmpMatchesList` shows that it equals the KMP output (including the shift `|t|` for the empty pattern), and `zMatchesM_time_le` bounds the cost by `2 * (|p| + |t|) - 3` comparisons. The [examples](../../CslibFrontierTests/ZFunction.lean) check several Z-arrays against the specification, a kernel-checked instance, the empty word, one letter, constant words and the worst case `a ^ (n - 1) b`. They also check matching with overlapping, absent, overlong and empty patterns against KMP. Not formalized: the conversion between Z-values and the KMP prefix function, and machine-level realizations ([ROADMAP](../../ROADMAP.md#string-algorithms)).

### Multi-pattern matching: Aho–Corasick

Import `CslibFrontier.Algorithms.Lean.AhoCorasick.Search` ([Basic.lean](../../CslibFrontier/Algorithms/Lean/AhoCorasick/Basic.lean), [Search.lean](../../CslibFrontier/Algorithms/Lean/AhoCorasick/Search.lean)). It formalizes the pattern matching machine of [Aho and Corasick][ahocorasick75] for a keyword list `P : List (List α)` over any alphabet with decidable equality. As in Section 4 of the paper, a state is represented by its string: the states are `[]` and the prefixes of keywords (`IsNode P`). The goto function sends `u` on `a` to `u ++ [a]` when that is a state, and the start state loops on every other symbol. The specification is `occurrences P t`: the pairs `(i, y)` with `y ∈ P` nonempty and a suffix of `t.take i`, so `i` is the `1`-indexed end position printed by Algorithm 1. Pairs are listed by increasing end position and, at one position, by decreasing length (`pairwise_occurrences`). A keyword listed twice in `P` is reported once per position, and the empty keyword is never reported.

The paper's lemmas are stated for the string representation:

- **Lemma 1:** `failure P u` is the longest proper suffix of `u` that is a state (`eq_failure_iff`).
- **Lemma 2:** `output P w` lists the keywords that are suffixes of `w` (`mem_output_iff`), and `output_eq_of_ne_nil` is the output recurrence of Algorithm 3.
- **Lemma 3:** the state after reading `w` is `longestNodeSuffix P w` (`foldl_nextMove`, and `longestNodeSuffix_append_singleton_eq_nextMove` for one cycle).

Algorithm 1 is `scanM P M t`, which runs a machine `M` (failure and output tables, both functions on strings). `ret_scanM` shows that with valid tables (`Machine.IsValid`) the scan returns exactly `occurrences P t`. The cost model charges one `TimeM` tick per goto transition (including the start state's self-loop), one per failure transition and one per reported pair. The goto test, table reads and writes, and list construction are free; these are constant-time operations in the paper's integer-state machine. The scan's failure loop is guarded: a failure transition that does not shorten the state stops at the start state, which never happens with a valid table. The guard's length comparison and the abort are not charged. `time_scanM_silent_lt` is Theorem 2: on a nonempty text of length `n` this guarded scan makes fewer than `2n` transitions, for any failure table. `time_scanM_lt` adds one tick per reported pair.

Algorithm 3 is `buildM P`, which computes the tables level by level, taking the failure state of `p.take (d + 1)` from that of `p.take d` by one operating cycle (`failure_append_singleton`). `isValid_build` proves the tables valid. `time_buildM_le` bounds the goto and failure transitions of the construction by `2 * (p.length - 1)` per keyword `p`; these are the transitions counted in the proof of Theorem 4. It is not a bound on total construction time. `buildM` scans all of `P` once per depth to find the keywords longer than that depth, `|P| · (maxLength P − 1)` uncharged visits in total, which can be quadratic in `Σ |p|`: one keyword of length 40 and 40 one-letter keywords give 1599 visits against `Σ |p| = 80`. The bound is also per keyword rather than per trie state, because `buildM` recomputes the failure state of a prefix shared by several keywords once per keyword (with the same result). `search_eq` and `time_searchM_le` give the end-to-end statement: `search P t = occurrences P t`, with at most `Σ 2 (|p| - 1) + 2|t| + |occurrences P t|` ticks.

For one keyword, [KMP.lean](../../CslibFrontier/Algorithms/Lean/AhoCorasick/KMP.lean) connects the machine to the Knuth–Morris–Pratt matcher of [CslibFrontier/Algorithms/Lean/KMP](../../CslibFrontier/Algorithms/Lean/KMP/Search.lean). `failure_singleton_take` identifies the failure function with the KMP prefix function `borderLen`, and `search_singleton` shows that `search [p] t` is `kmpMatchesList p t` with each shift moved to its end position.

The [checked examples](../../CslibFrontierTests/AhoCorasick.lean) reproduce Figures 1 and 2 of the paper. The keywords are `he`, `she`, `his` and `hers`, and the text is `ushers`. The examples check the failure and output functions, the three reported pairs, and the seven transitions of the scan. Further examples cover empty text, the empty keyword list and the empty keyword, a repeated keyword, keywords that are suffixes of each other, and the KMP special case. They also show that a failure table that always returns the start state is not valid: with the constructed output table it misses `hers`. Not formalized: the integer-state trie of Algorithm 2 and its linear construction (Theorem 3), a construction whose level bookkeeping is charged and linear, the deterministic automaton of Section 6, and machine-level or RAM realizations ([ROADMAP](../../ROADMAP.md#string-algorithms)).

### Palindromes and Manacher's algorithm

Import `CslibFrontier.Algorithms.Lean.Palindrome.Basic` and `.Manacher` ([Basic](../../CslibFrontier/Algorithms/Lean/Palindrome/Basic.lean), [Manacher](../../CslibFrontier/Algorithms/Lean/Palindrome/Manacher.lean)). A word of length `n` has `2n + 1` centers `c = 0, …, 2n`: odd `c` is the letter at position `c / 2` and even `c` is the gap before it. The factor `w.extract a b` has center `a + b`. `radius w c` is the largest `k` such that `w.extract (c / 2 - k) ((c + 1) / 2 + k)` is a palindrome (Mathlib's `List.Palindrome`), and it is `0` for `c > 2n`. These are the even and odd maximal radii of [Apostolico, Breslauer and Galil, Section 1][apostolicobreslauergalil95], `0`-indexed and merged into one sequence. No sentinel letters are interleaved.

- **Specification.** `palindrome_extract_iff_le_radius` says that for `a ≤ b ≤ n` the factor `w.extract a b` is a palindrome iff `b - a ≤ 2 * radius w (a + b) + (a + b) % 2`. `longestPalindrome w` is the maximal palindrome about a center maximizing that length. `length_le_longestPalindrome`, `palindrome_longestPalindrome` and `longestPalindrome_isInfix` show that it is a longest palindromic factor. `palindrome_take_iff` reads the palindromic prefixes off the radii: `w.take k` is a palindrome iff `radius w k = k / 2`. The list lemmas behind these (`List.palindrome_extract_iff`, `List.Palindrome.extract_reflect` and others) are in [Palindrome.lean](../../CslibFrontier/Foundations/Data/List/Palindrome.lean).
- **Mirror lemma.** `min_radius_mirror` is the step of the algorithm. If the maximal palindrome about `C` ends at `R`, then for `c ≥ C` the radii about `c` and about `2C - c` agree after truncating both at `R - (c + 1) / 2`.
- **Algorithm.** `manacherM w` ([Manacher][manacher75]) scans the centers left to right, keeping the center whose palindrome reaches furthest right. It reuses the mirrored radius when that radius is below the truncation; otherwise `extendM` compares letters outward. `manacher_eq` shows that `manacher w` is exactly `Array.ofFn (radius w.toList ·)` over the `2 * w.size + 1` centers. `manacherM_time_le` bounds the cost by `3 * w.size` comparisons: each successful comparison moves the right end of the furthest palindrome, and each of the `2n` centers makes at most one failed comparison. The bound is close to the worst case: the examples check that `a b^(n - 2) c` costs `3n - 6` comparisons for `n = 10` and `n = 20` (the count for general `n` is not proved). `longestPalindromeM` returns the interval of `longestPalindrome` within the same bound (`extract_longestPalindromeM`, `longestPalindromeM_time_le`).

The [examples](../../CslibFrontierTests/Manacher.lean) check the radii of `abacaba`, `abba`, `aaaa`, `abcd` (all `0`), the empty word and a one-letter word by `decide` through `manacher_eq`, as well as comparison counts, one extension phase, the longest palindrome of `xabacabay`, and a palindromic and a non-palindromic prefix. Manacher's original algorithm is on-line: it reports the palindromic prefixes as letters arrive. That formulation, palindromic trees (eertrees) and parallel algorithms are not formalized ([ROADMAP](../../ROADMAP.md#string-algorithms)).

## Lempel–Ziv incremental parsing (LZ78)

Import `CslibFrontier.Algorithms.Lean.LempelZiv.LZ78Bits`. The parse and pair code are in [LZ78.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ78.lean), which needs only list imports. The phrase count is in [LZ78Count.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ78Count.lean), the bit code in [LZ78Bits.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ78Bits.lean), and the alphabet-generic [distinct-parsing bound](../../CslibFrontier/Algorithms/Lean/LempelZiv/DistinctParsing.lean) in the namespace `DistinctParsing`. `LZ78.parse` is the incremental parsing of [Ziv and Lempel][zivlempel78] on `List α` for any type with decidable equality. Each phrase is the shortest prefix of the remaining input that is not an earlier phrase; when the input runs out first, the last phrase is the nonempty remainder and may repeat an earlier phrase. The phrases concatenate to the input (`flatten_parse`) and are nonempty. Each phrase is the shortest new prefix (`prefix_mem_take_parse`, `getElem_parse_notMem_take`), and the phrases before the last are pairwise distinct (`nodup_dropLast_parse`; all are distinct when the last phrase is new, `nodup_parse_of_getLast_notMem`). `LZ78.encode` writes phrase `w` as the pair (index of `w.dropLast` among `[]` and the earlier phrases, last symbol of `w`), and `decode_encode` says that `LZ78.decode` inverts it. `LZ78.encodeBits e` fixes a numbering `e : α ≃ Fin k` and writes the `i`-th pair with `⌈log₂ i⌉` pointer bits and `⌈log₂ k⌉` symbol bits, least significant bit first. `decodeBits_encodeBits` gives the round trip for `k ≥ 2`.

The bounds are for an alphabet of size `k ≥ 2`, an input of length `n` and `c` phrases. The basic inequality is `m * c ≤ n + 2 * k ^ m` for every `m` (`mul_length_le_of_nodup` for distinct parsings and `mul_length_parse_le` for LZ78, whose last phrase may repeat). Choosing `m` gives `c * ⌊log_k c⌋ ≤ n + 2c` (`length_parse_mul_log_le`) and `c (log_k n - log_k log_k n - 4) ≤ n` (`length_parse_mul_logb_sub_le`). It also gives `c ≤ n / ((1 - ε_n) log_k n)` for `n ≥ 2` and `ε_n < 1` (`length_parse_le_div`), where `epsilon k n = min 1 ((log_k log_k n + 4) / log_k n)` (`epsilon_def`) tends to `0` (`tendsto_epsilon`). For `k = 2` this is the distinct-parsing lemma of [Cover and Thomas][coverthomas06], §13.5; the general-`k` form, with logarithms to base `k`, is the same argument. The code length is exactly `∑_{i=1}^{c} (⌈log₂ i⌉ + ⌈log₂ k⌉)` (`length_encodeBits`). It is at most `c (⌈log₂ c⌉ + ⌈log₂ k⌉)` (`length_encodeBits_le`) and at most `⌈log₂ k⌉ (n + 4c)` (`length_encodeBits_le_mul_add`). It is also at most `⌈log₂ k⌉ n (1 + 4 / ((1 - ε_n) log_k n))` (`length_encodeBits_le_mul_one_add`), so LZ78 expands no input by more than a vanishing fraction over the fixed-length code (`exists_length_encodeBits_le`). The functions are reference implementations with list-based dictionary lookups, and no running time is claimed.

The [examples](../../CslibFrontierTests/Algorithms/Lean/LempelZiv.lean) check the Cover–Thomas input `ABBABBABBBAABABAA`: its phrases `A, B, BA, BB, AB, BBA, ABA, BAA`, its pairs, and its 25-bit code. They also cover the empty input and `AA`, whose repeated last phrase makes the parse not duplicate free. Further checks are a phrase list that is not tree structured, bit strings that fail to decode, `1 ^ 100` with 14 phrases and 55 bits, and an input length (`n = 256`) at which the `ε_n` hypotheses hold. Not formalized: optimality for stationary ergodic sources (Ziv's inequality, a compression ratio tending to the entropy rate), and the links to Kolmogorov complexity and finite-state compressibility ([ROADMAP](../../ROADMAP.md#pseudorandomness-coding-and-boolean-analysis)). The sliding-window variant is in the next section.

## Lempel–Ziv sliding-window parsing (LZ77) and complexity (LZ76)

Import `CslibFrontier.Algorithms.Lean.LempelZiv.LZ77Count`. The parse and the triple code are in [LZ77.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ77.lean), and the comparison with LZ78 is in [LZ77Count.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ77Count.lean), both in the namespace `LZ77`. `Reproducible W h u` says that `u` is empty or is a copy that starts `d` symbols before the end of the text `h`, for some `1 ≤ d ≤ min W |h|`. The copy may run into `u` itself, as in [Lempel and Ziv][lempelziv76]. A history (`IsHistory`) is a factorization into nonempty phrases, each reproducible from the text before it except for its last symbol. A history is exhaustive (`IsExhaustive`) when no phrase but the last is reproducible. `LZ77.parse W` takes as each phrase the longest reproducible prefix of the rest of the input plus one symbol, or the whole rest if it is reproducible. It is an exhaustive history of its input (`flatten_parse`, `isHistory_parse`, `isExhaustive_parse`). By an exchange argument it has the fewest phrases among all histories with the same window (`length_parse_le_of_isHistory`), and it is the only exhaustive history (`parse_eq_of_isExhaustive`). `LZ77.complexity x` is the phrase count with window `|x|`. That window is unbounded for `x`, because a copy cannot start before the text. The complexity is the least number of phrases of a history (`complexity_le_of_isHistory`). `LZ77.encode W` writes each phrase as a triple (distance, length − 1, last symbol), as in [Ziv and Lempel][zivlempel77]. `decode_encode` says that `LZ77.decode` inverts it; the decoder copies symbol by symbol and does not need `W`.

When the window covers the input, every LZ78 phrase is an earlier phrase followed by one symbol, so the LZ78 parse is a history (`isHistory_lz78Parse`). Hence LZ77 needs no more phrases than LZ78 (`length_parse_le_length_parse`, `complexity_le_length_parse`), and the LZ78 distinct-parsing bound transfers: `c ≤ n / ((1 - ε_n) log_k n)` for `n ≥ 2`, `k ≥ 2` and `ε_n < 1` (`LZ77.length_parse_le_div`, `LZ77.complexity_le_div`). The window bounds only how far back a copy may start. Copies may be arbitrarily long, so the 1977 algorithm's lookahead buffer and fixed-width codewords are not modelled. No bit code or running time is claimed.

The [examples](../../CslibFrontierTests/Algorithms/Lean/LempelZivLZ77.lean) parse `ABBABBABBBAABABAA` into the seven phrases `A, B, BA, BBABBB, AA, BABA, A` (LZ78 uses eight) and check its triples and decoding. They also check the overlapping copy in `a ^ 8` (two phrases, against four for LZ78) and window `0`. The period-3 input `abcabcabc` needs nine phrases with window `2` and four with window `3`. Further checks are a history that is not exhaustive, a factorization that is not a history, and the `n = 256` instance of the bound. Not formalized: bit-level LZ77 codes with bounded match length, the optimality of LZ77 for stationary ergodic sources, and the links to Kolmogorov complexity and finite-state compressibility ([ROADMAP](../../ROADMAP.md#pseudorandomness-coding-and-boolean-analysis)).

## Burrows–Wheeler transform

Import `CslibFrontier.Algorithms.Lean.BurrowsWheeler.Basic` ([source](../../CslibFrontier/Algorithms/Lean/BurrowsWheeler/Basic.lean)) and `CslibFrontier.Algorithms.Lean.BurrowsWheeler.Decode` ([source](../../CslibFrontier/Algorithms/Lean/BurrowsWheeler/Decode.lean)). The transform follows Algorithm C of [Burrows and Wheeler][burrowswheeler94], Section 2, over any `LinearOrder` alphabet, with no end-of-word sentinel. `bwtMatrix w` sorts the rotations of `w` lexicographically, and `bwt w = (bwtLast w, bwtIndex w)` is the last column together with the index of the *first* row equal to `w`. The empty word maps to `([], 0)`. Periodic words have repeated rows, and are still handled.

The LF-mapping `lfMap L r = L.countP (· < L[r]) + (L.take r).count L[r]` is computed from the last column alone, as in Section 4.2 of the report. `rotate_one_getElem_bwtMatrix_lfMap` proves its row form: row `lfMap L r`, rotated left by one place, is row `r`. `getElem?_bwtFirst_lfMap` and `count_take_bwtFirst_lfMap` prove the occurrence form (step D2): the `k`-th `c` of `L` corresponds to the `k`-th `c` of the first column. `lfMap_bwtLast_injOn` and `map_lfMap_range_perm` show that the LF-mapping is a permutation of the rows, which completes step D2. `bwtFirst_eq_mergeSort_bwtLast` says that the first column is the sorted last column (step D1). `getElem?_bwtLast_iterate_lfMap` is the decoding formula `w[n - 1 - i] = L[T^[i] I]` (step D3). `inverseBwt_bwt` and `bwt_injective` state invertibility and injectivity of the transform with its index. `inverseBwtM` is the table-driven decoder of Section 4.2 in `TimeM`, with the rank array `rankTable` and `C c = L.countP (· < c)`. `inverseBwtM_bwt` proves that it returns `w` after exactly `|w|` LF steps, and `inverseBwtM_time_le` bounds it by `|L|` on every input. The cost model charges one tick per LF step. Table lookups are idealized as unit cost, and neither the construction of the `C` and `P` tables nor the sort of the forward transform is charged.

The [examples](../../CslibFrontierTests/BurrowsWheeler.lean) check the report's running example (`abraca` ↦ `(caraab, 1)`, `T = (4 0 5 1 2 3)`), `banana`, the periodic word `cancan`, whose LF orbit `[2, 4, 0, 2, 4, 0]` repeats with period 3 and is not a permutation of the rows, the empty word, a single letter and a constant word. They also show that the last column alone is not injective. Not formalized: move-to-front and entropy coding, compression bounds in terms of empirical entropy, FM-index backward search, the link to suffix arrays, and charged construction of the transform ([ROADMAP](../../ROADMAP.md#string-algorithms)).
