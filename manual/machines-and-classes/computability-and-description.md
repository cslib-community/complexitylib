# Computability and description methods

[Chapter index](index.md) · [Other machine bridges](intermediate-and-legacy.md)

This part of the library separates eventual computation from several inequivalent clock conventions. It contains native universal machine descriptions and undecidability theorems, bridges to Mathlib partial recursion, an abstract description-method interface for Kolmogorov complexity, and Blum's machine-independent complexity measures over Mathlib's partial-recursive codes. These models share binary descriptions but should not be assigned the same notion of elapsed time. [complexitylib][complexitylib]

## Native descriptions, universality, and total computability

[Universal.Desc](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Universal/Basic.lean#L70) is a concrete finite transition-table description with encodings of control states, tape symbols and actions. `SCfg` represents the interpreter configuration by finite data; `simulate` and the universal interpreter execute descriptions. The interpreter is a functional program receiving native time/space certificates, rather than an assumed transition with unit-cost access to an arbitrary coded machine. A streaming input implementation and a windowed divide-and-conquer simulator provide distinct resource bounds. The chapter on hierarchies records the resulting quantitative boundary.

[IsComputable](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Computable/Defs.lean#L29) existentially quantifies arbitrary time and workspace bounds for one finite binary machine. It is equivalent to one such machine halting with the encoded result on every valid encoded input. [IsDecidable](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Computable.lean#L127) asks for a computable Boolean indicator. “Total” here is relative to encoded instances: an arbitrary embedding need not have a decidable image, and no contract is silently added on malformed words.

Native partial evaluation returns a `Part` value and is connected to Mathlib's `Partrec` by [partrec_eval](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Partrec.lean#L648). More generally [IsComputable.computable_enc](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Partrec.lean#L657) needs a computable input encoding to conclude that the encoded result is Mathlib-computable. Recovering the typed function additionally needs a computable left inverse for its output encoding. On plain bit strings these side conditions are immediate. This is a stated one-way bridge, not an unrestricted equivalence of arbitrary typed encodings.

The single-tape/TM0/TM1 path supplies primitive-recursive operations on the finite tape representations, clocked runs, and partial-recursive eventual evaluation. [SingleTape/Partrec.lean](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/SingleTape/Partrec.lean#L16) connects those models to the same Mathlib framework. Mathlib's typed [Primrec](https://github.com/leanprover-community/mathlib4/blob/69552756cd8a2d2d48763cf7279fd814d6a1224d/Mathlib/Computability/Primrec/Basic.lean#L174) lifts primitive recursion through `Primcodable` encodings; [Computable](https://github.com/leanprover-community/mathlib4/blob/69552756cd8a2d2d48763cf7279fd814d6a1224d/Mathlib/Computability/Partrec.lean#L242) is the total-function subfamily of `Partrec`. Neither predicate imposes a native time bound. They justify effective data transformations and eventual evaluation, not a polynomial-time characterization. [mathlib][mathlib]

The native description development proves self-halting and general halting undecidability, corresponding acceptance results, mapping-reduction transfer, and Rice's theorem for nontrivial extensional properties of computed behavior. [Halting.lean](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting.lean#L167) [Rice theorem](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Rice.lean#L622) The [s-m-n construction](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/SMN.lean#L210) is itself native polynomial-time: it computes a description that prepends a fixed word to the future input before executing the supplied machine. This combines effective program manipulation with semantic preservation.

## Abstract description methods

[DescriptionMethod](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Basic.lean#L82) is a function from binary programs to `Computation α`, a monotone clocked partial computation. A program produces at most one value. The structure imposes no computability condition on that function; it is an abstract semantic interface, not automatically an effective programming language.

Plain `ecomplexity` is the minimum program length for eventual production, and `etimeBoundedComplexity t` is the minimum program length producing the value by clock `t`. Both take values in `ℕ∞`, with infinity for an undescribable value. The natural-valued wrapper uses `ENat.toNat`, so its value zero is not meaningful as a complexity bound when extended complexity is infinite. Theorems explicitly supply finiteness when passing to that wrapper.

[Simulation](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Invariance.lean#L70) carries a compiler with additive program-length overhead and an explicit time-overhead function. It yields complexity inequalities and composes with the required monotonicity conditions. `IsAdditivelyOptimal` is relative to a specified class of description methods. Counting/incompressibility theorems hold for every method because each short program has at most one result; additive-optimality statements require the appropriate simulation/effectiveness premise.

A conditional method is simply a family `β → DescriptionMethod α`, holding the condition fixed while minimizing program length. [Composition](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/ChainRule.lean#L82) combines an unconditional and a conditional program with explicit code-length and clock overhead. A self-delimiting header gives the logarithmic length overhead in the chain rule. The existence of such a header is not the assertion that the entire description model is prefix-free.

For the Partrec model, [condUniversal](../../Complexity/Computability/Kolmogorov/ConditionalPartrec.lean) is the conditional universal method on natural numbers: after a code header, the announced code runs on the pair `Nat.pair y (encode p)` of the condition `y` and the rest `p` of the program. Every partial recursive function of the condition and the program is at most a constant worse, uniformly in the condition (`exists_ecomplexity_condUniversal_le_of_partrec₂`). This is the conditional invariance theorem of [Shen, Uspensky and Vereshchagin, Section 2.2][shenuspenskyvereshchagin17]. With `C(x) = universal.complexity x` and `C(y | x) = (condUniversal x).complexity y` the module proves `C(y | x) ≤ C(y) + O(1)`, `C(x | x) = O(1)` and the chain rule `C(⟨x, y⟩) ≤ C(x) + C(y | x) + 2 size C(x) + O(1)`, where `⟨x, y⟩` is `Nat.pair x y` and `size` is the binary length.

[SymmetryOfInformation](../../Complexity/Computability/Kolmogorov/SymmetryOfInformation.lean) proves the converse, the Kolmogorov–Levin theorem: `exists_complexity_universal_add_condUniversal_le` states `C(x) + C(y | x) ≤ C(⟨x, y⟩) + 2 size k + 4 size (size k) + O(1)` with `k = C(⟨x, y⟩)`. Together with the chain rule this gives `|C(⟨x, y⟩) − C(x) − C(y | x)| ≤ 6 size k + O(1)`. For the algorithmic information `I(x : y) = C(y) − C(y | x)` (`algorithmicInformation`, integer-valued), it gives `|I(x : y) − I(y : x)| ≤ 12 size k + O(1)` [Shen, Uspensky and Vereshchagin, Sections 2.2–2.3][shenuspenskyvereshchagin17]. The proof enumerates the partners `v` with `C(⟨x, v⟩) ≤ k`, and then the numbers with at least `2 ^ l` partners, through [Nat.nthDistinctValue](../../Complexity/Foundations/Computability/DistinctValues.lean) applied to primitive-recursive sequences of clocked runs. The counting step is the general bound `Set.mul_ncard_setOf_le_ncard_fiber_le`: few fibers can be large. All of this concerns plain complexity on natural numbers with `Nat.pair`; a different computable pairing changes `C(⟨x, y⟩)` by `O(1)`. The coefficients are those of this proof, and the source states only `O(log C(x, y))`. These results do not cover the prefix-complexity identity `K(x, y) = K(x) + K(y | x, K(x)) + O(1)`, the TM-based `condUniversalTM`, or time-bounded symmetry of information ([#3324](https://github.com/cslib-community/complexitylib/issues/3324)). [Checked clients](../../ComplexityTests/KolmogorovSymmetryOfInformation.lean) evaluate distinct-value enumerations, rule out a fourth value for a range of three, and run `condUniversal` on the code `left`. They also exhibit a number with `C(x | x) < C(x)`, and derive `C(⟨x, x⟩) = C(x) + O(log)` and `I(x : x) ≥ C(x) − O(1)`.

## Clock conventions

| Description model | Program interpretation | Meaning of clock `t` | Preserved result |
|---|---|---|---|
| `ofCode c` and Partrec `universal` | Mathlib `Nat.Partrec.Code`, with a code header and encoded binary input | Fuel for `Code.evaln`; bounds recursive evaluation depth and inspected numerical sizes | Additive optimality for partial-recursive description methods; same-fuel simulation of a fixed code |
| `ofMultiTapeTM tm`, `ofSingleTapeTM tm` | Binary program is the chosen machine's input | Steps of that fixed machine, under its halting/output convention | Exact output correspondence and explicit cross-model clock overhead |
| `ofTM0`, `ofTM1` | Finitely supported source machine is translated to a single-tape machine | Steps of the translated single-tape machine; TM0 detection adds one halt step | Eventual output and partial-recursive bridges; exact `t+1` TM0 clock theorem |
| `universalTM` | Parse a native description and an argument from the binary program | Steps of the **described machine**, not steps of a fixed interpreter | Constant code overhead with no simulated-clock overhead for each finite binary native machine |

Sources: [Partrec methods](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Partrec.lean#L101), [machine methods](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/MultiTape.lean#L69), [single-tape methods](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/SingleTape.lean#L81), and [universalTM conventions](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/TimeBounded.lean#L24).

The Partrec universal method has a genuine invariance theorem for its effective class, [isAdditivelyOptimal_universal](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Partrec.lean#L205). Its `evaln` fuel is not a machine-step complexity measure, though it is a Blum complexity measure (next section). The library proves uncomputability of its plain natural-number complexity, and that no computable unbounded function is everywhere a lower bound. [not_computable_complexity_universal](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Uncomputability.lean#L191)

The single-tape description method requires a halted canonical output tape. Its native simulation keeps the program unchanged and uses the explicit time bound `3|p| + 2t + 6`. `ofTM0` incorporates the source's extra halt-detection step; `ofTM1` uses the compiled single-tape clock and does not charge an arbitrary structured source procedure as one native instruction. [singleTapeSimulation](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/SingleTape.lean#L143) [ofTM0 clock](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/SingleTape.lean#L117) [ofTM1](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/SingleTape.lean#L133)

For the native `universalTM` method, `unframe p` determines the described transition table and `dropFrame p` its input. The output is the entire halted output tape. A fixed machine is represented by a constant-size header, while the clock directly counts its source steps. This makes linear-time bounds exact in the selected described-machine semantics; actually evaluating the description still incurs the separately proved native simulator overhead.

That choice is particularly consequential for `levinKt`, defined by minimizing program length plus the ceiling of the logarithm of the described step count. The source explicitly warns that replacing this by a fixed universal simulator's step count can alter the logarithmic-time term by a constant factor, rather than merely an additive constant. This is the library's described-machine Levin-style measure; retain that convention when using cryptographic or fine-grained implications. It is not licensed to transfer additive-invariance claims from the plain model to this clock without the required simulator theorem.

`condUniversalTM` fixes an auxiliary binary word and runs the described machine on a paired program argument and condition. Conditional plain, time-bounded and Levin-style measures reuse that exact clock. [Conditional conventions](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Conditional.lean#L132) The generic `depth` measure is the truncated difference between time-bounded and plain extended complexity. It uses plain complexity; it is not a formalization of every prefix-free or logical-depth convention in the literature. [Depth](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Depth.lean#L55)

## Abstract (Blum) complexity measures

[BlumMeasure](../../Complexity/Computability/BlumComplexity/Basic.lean) fixes Mathlib's `Nat.Partrec.Code` with `Code.eval` as the acceptable numbering. A measure is a partial cost `cost c n` satisfying Blum's two axioms [blum67][blum67]: the cost is defined exactly when `c.eval n` is, and the graph predicate `m ∈ cost c n` is a `ComputablePred` of `((c, n), m)`. From the axioms the library derives `partrec_cost`, that every measure is partial recursive, and `computablePred_cost_le`, that halting within a given cost is decidable. Neither axiom refers to a machine; the measure is an abstract interface, and results about it hold for every measure.

`complexityClass t` is the class `C_t` of total functions `f` such that some code computes `f` at every input and has cost at most `t n` for all sufficiently large `n` (`∀ᶠ n in atTop`). This is Borodin's almost-everywhere convention [borodin72][borodin72]. A bound may fail at finitely many inputs. It is not the everywhere-bounded class, which can be smaller.

[fuelMeasure](../../Complexity/Computability/BlumComplexity/Fuel.lean) is the instance whose cost `evalnFuel c n` is the least fuel `k` with `Code.evaln k c n` successful. Because `evaln` is primitive recursive, the graph predicate is decidable. The fuel bounds the evaluator's recursion depth and the size of every inspected number, so `n < evalnFuel c n` (`lt_of_mem_evalnFuel`) and classes of bounds `t ≤ id` are empty. It is the natural cost measure of Mathlib's evaluator, not a machine step count; it is the same clock as the Partrec description method above.

[gap_theorem](../../Complexity/Computability/BlumComplexity/Gap.lean) is Borodin's gap theorem for every measure. For computable `g` with `n ≤ g n` and any computable lower bound `a`, there is a computable, strictly increasing `t ≥ a` with `complexityClass (g ∘ t) = complexityClass t`. `gap_theorem₂` allows a stretch that also depends on the input: for computable `g` with `y ≤ g n y`, `complexityClass (fun n => g n (t n)) = complexityClass t`. The underlying `exists_gap₂` is pointwise with an explicit threshold: for every code `c` and every `n ≥ encode c`, each cost of `c` on `n` is at most `t n` or above `g n (t n)`. The threshold depends on the code, so this does not give the equality for the everywhere-bounded class. [recursively_related](../../Complexity/Computability/BlumComplexity/RecursiveRelatedness.lean) gives Blum's recursive relatedness: any two measures are bounded by each other through one computable `r`, for each code at all sufficiently large inputs. `recursively_related_of_encode_le` states the explicit threshold `n ≥ encode c`.

[speedup](../../Complexity/Computability/BlumComplexity/Speedup.lean) is Blum's speedup theorem for every measure [blum67][blum67]. For every computable `r : ℕ → ℕ → ℕ` there is a computable function `f` with values in `{0, 1}` such that every code `c` computing `f` has another code `c'` computing `f` with `r n (Φ c' n) < Φ c n` for all sufficiently large `n`. The inequality is strict, which implies the non-strict form. `speedup'` is the one-argument form `r (Φ c' n) < Φ c n`, and `exists_no_fastest` restates the theorem as the absence of a code for `f` that is fastest up to `r`. The proof is Blum's priority construction: a generic cancellation run ([Cancellation](../../Complexity/Computability/BlumComplexity/Cancellation.lean)) diagonalizes against every code that is cheap relative to a faster version of the construction, and Mathlib's recursion theorem `Code.fixed_point₂` lets the construction run its own versions. The theorem asserts that `c'` exists; it does not compute `c'` from `c`.

[Hierarchy](../../Complexity/Computability/BlumComplexity/Hierarchy.lean) proves the theorem on arbitrarily complex functions for every measure, customarily credited to Rabin (1960) and, in this axiomatic form, to Blum [blum67][blum67]; neither attribution nor a theorem locator has been checked against the original texts. For every computable bound `t`, `exists_arbitrarilyComplex` gives a computable function `f` with values in `{0, 1}` such that every code `c` computing `f` has `t n < Φ c n` for all sufficiently large `n`. The lower bound holds almost everywhere for every code, which is stronger than `f ∉ C_t`. The proof is a cancellation run whose eligibility test, cost at most `t y`, is decidable by Blum's second axiom, so no recursion theorem is needed. Consequently every class `C_t` of a computable bound misses a computable `0`/`1`-valued function (`exists_not_mem_complexityClass`), no such class contains every computable function, and every computable `t` is dominated by a computable `t'` with `C_t ⊂ C_{t'}` (`exists_complexityClass_ssubset`). That `t'` is obtained non-uniformly.

[Union](../../Complexity/Computability/BlumComplexity/Union.lean) proves the union theorem for every measure, Theorem VII.3.7 of Odifreddi's textbook [odifreddi99][odifreddi99], attributed there to McCreight and Meyer [mccreightmeyer69][mccreightmeyer69]. Let `T : ℕ → ℕ → ℕ` be `Computable₂` with `T i n ≤ T (i + 1) n`, which is the textbook's hypothesis. Then `union_theorem` gives a computable `t` with `complexityClass t = ⋃ i, complexityClass (T i)`. The bound is diagonal: `t n = T i n` for some `i ≤ n`. `exists_union_bound` states the pointwise content for every code, total or not: a code that halts within `t n` for almost all `n` halts within a single `T i n` for almost all `n`, and each `T i ≤ t` almost everywhere. `union_theorem_of_eventuallyLE` needs only `T i ≤ T (i + 1)` almost everywhere, and `union_theorem_of_directed` needs only `Directed (· ≤ᶠ[atTop] ·) T`: any two bounds are dominated almost everywhere by a third. Both are derived here from `union_theorem`, applied to the partial suprema `partialSups (T · n)`, that is `max (T 0 n) … (T i n)`. The proof was written independently using the library's cancellation run and has not been compared with the source's construction. Requirement `⟪j, i⟫` with `j ≤ i` is eligible at stage `y` when code `j` does not halt on `y` within `T i y`, and `t y` is `T i y` for the requirement cancelled there. Use the union theorem when a class is presented as an increasing union, such as the polynomial bounds `(n + 1) ^ i`. The bound it returns is computable but need not be one of the `T i`; for a constant family the diagonal property forces `t = T 0`. Nothing is claimed about how fast `t` itself can be computed. For a total code `c`, `forall_mem_cost_iff_exists_of_total` turns the class condition `∀ m ∈ Φ.cost c n, m ≤ t n` into `∃ m ∈ Φ.cost c n, m ≤ t n` and back.

[Naming](../../Complexity/Computability/BlumComplexity/Naming.lean) proves the naming theorem for every measure, Theorem VII.3.6 of [odifreddi99][odifreddi99], attributed there to McCreight and Meyer. A family `φ_{h 0}, φ_{h 1}, …` is *measured* when `φ_{h i} x = y` is decidable uniformly in `(i, x, y)`. `naming_theorem` gives a computable `h : Code → Code` whose family is measured, such that for every total `φ_i = t` the function `φ_{h i}` is total and `complexityClass φ_{h i} = complexityClass t`. The measured family is `Φ.name`: `partrec_name` and `computablePred_mem_name` give uniform partial recursiveness and the decidable graph, and `dom_name` (with `exists_name_total`) gives totality. For a total `t` with name `t'`, `eventually_cost_le_name_iff` states the pointwise content for every code, total or not: a code halts within `t` almost everywhere exactly when it halts within `t'` almost everywhere. `complexityClass_name` is the class equality. The construction is the textbook's priority argument with a dynamic priority list, encoded by keys computed from the history of earlier stages. It differs in two places. The value given when an index acts at stage `⟪x, z⟫` is `z`, where the textbook uses `Φ_e(x) - 1`, which may be undefined. The textbook's argument for the requirements `L_e` (`C_{t'} ⊆ C_t`) is replaced by a quiet-set stabilization argument, described in the module docstring. Use the naming theorem when an argument needs every class `C_t` named by a member of one measured family, as the honesty theorem below does. The theorem says nothing about how `t'` compares with `t` pointwise, and `h` acts on codes, not on the functions they compute.

[Honesty](../../Complexity/Computability/BlumComplexity/Honesty.lean) defines `IsHonest g f` for total `f`: some code computes `f` with cost at most `g n (f n)` for almost all `n` (Definition VII.2.13 of [odifreddi99][odifreddi99]; the textbook also allows partial `f`). `exists_isHonest_of_measured` is Exercise VII.2.14a there, for the total members of a measured family. `honesty_theorem` combines it with the naming theorem: one computable `g` gives every class `C_t` of a computable `t` a computable `g`-honest name `t'` with `complexityClass t' = complexityClass t`. Honesty is not automatic: for every computable `g`, the arbitrarily complex function for the bound `max (g n 0) (g n 1)` is a `0`/`1`-valued function that is not `g`-honest, a checked client below.

These are statements about the fixed numbering `Nat.Partrec.Code`. Native multitape time or space is not yet a `BlumMeasure`; that needs a Gödel-numbering bridge from native descriptions, with its own simulation overhead. Blum's compression theorem in its running-time form (a single computable `h` with `C_{Φ_i} ⊂ C_{n ↦ h n (Φ_i n)}` for every total `φ_i`; the form with the value `φ_i` in place of the cost `Φ_i` is false, by the gap theorem) is not formalized ([#2866](https://github.com/cslib-community/complexitylib/issues/2866)). The honesty results above cover total functions only. [Checked clients](../../ComplexityTests/BlumComplexity.lean) compute the fuel of the constant-zero code, show an empty class and an inhabited class, and exercise the almost-everywhere convention. They instantiate the gap theorem for `g n = n * n` with an inhabited gap class, and the two-argument gap theorem for `g n y = y ^ (n + 1)`. They apply recursive relatedness with its threshold to the fuel measure and a second measure, fuel plus input. Finally, they apply the speedup theorem to the fuel measure with exponential speedup `r m = 2 ^ m`, show that the speedup function has a code so the conclusion is not vacuous, show that it lies outside the fuel class of `n + 1`, and iterate the speedup twice. They also give an arbitrarily complex function for the bound `2 ^ n` with a code, so its lower bound is not vacuous, and a strict extension of the fuel class of `2 ^ n`. For the union theorem they take the polynomial bounds `(n + 1) ^ i`: the union class contains the constant-zero code's function, which is outside the class of the constant bound `1`, and it is not the class of all computable functions. They also apply the almost-everywhere form to `n ^ i`, which does not increase pointwise at `n = 0`. For the naming theorem they take the code `Code.succ`: its name is total and names the class of `n + 1`, which contains the constant-zero function. They apply the honesty theorem to the bound `2 ^ n`, show that the constant-zero function is honest for `g n y = n + 1`, and give the non-honest function above.

## Decision and hardness clients

The description models support concrete membership theorems with visible parameter encodings:

- [MINKT.mem_NP](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/MINKT.lean#L251) verifies a short program producing a specified word by a supplied time. The instance uses unary size and time bounds; the verifier's polynomial cost is measured in that encoded input length.
- [MINcKT.mem_NP](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/MINcKT.lean#L231) adds an auxiliary condition, with the same explicit time/size convention.
- [MKtP.mem_E](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/MKtP.lean#L328) places the library's Levin-style threshold problem in single-exponential time when the threshold is unary. It does not prove that arbitrary binary-threshold input has the same resource bound.

Fixed-bound and gap/promise variants expose these conventions rather than treating the numerical parameters as free. Incompressibility, chain-rule, conditional-copy and computational-depth results concern these selected methods. Their hardness/cryptography applications cross into the programs-and-cryptography chapter; this chapter makes no claim that generic average-case assumptions or conjectured separations have been proved.
