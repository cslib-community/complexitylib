# Computability and description methods

[Chapter index](index.md) · [Other machine bridges](intermediate-and-legacy.md)

This part of the library separates eventual computation from several inequivalent clock conventions. It contains native universal machine descriptions and undecidability theorems, bridges to Mathlib partial recursion, an abstract description-method interface for Kolmogorov complexity, Blum's machine-independent complexity measures over Mathlib's partial-recursive codes, and Radó's busy beaver functions for those codes. These models share binary descriptions but should not be assigned the same notion of elapsed time. [cslib-frontier][complexitylib]

## Native descriptions, universality, and total computability

[Universal.Desc](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Universal/Basic.lean#L70) is a concrete finite transition-table description with encodings of control states, tape symbols and actions. `SCfg` represents the interpreter configuration by finite data; `simulate` and the universal interpreter execute descriptions. The interpreter is a functional program receiving native time/space certificates, rather than an assumed transition with unit-cost access to an arbitrary coded machine. A streaming input implementation and a windowed divide-and-conquer simulator provide distinct resource bounds. The chapter on hierarchies records the resulting quantitative boundary.

Descriptions also have a nondeterministic reading. In [NStep](../../CslibFrontier/Computability/Machines/Turing/MultiTape/Universal/Nondeterministic.lean) a running configuration may fire any entry whose key matches it, and one that matches no entry is stuck. `descN` describes a nondeterministic machine with finitely many states and symbols by listing every permitted transition. Steps of the machine and of its description correspond in both directions (`exists_nStep_of_step`, `exists_step_of_nStep`), so the machine accepts exactly when its description reaches a halted configuration with the output `[1]` (`accepts_iff_reflTransGen_nStep`). This correspondence carries no resource bound; bounding the space along a path is part of the NSPACE hierarchy work in [#4090](https://github.com/cslib-community/cslib-frontier/issues/4090). The [checked clients](../../CslibFrontierTests/UniversalNondeterministic.lean) use a machine that emits either bit and halts.

[IsComputable](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Computable/Defs.lean#L29) existentially quantifies arbitrary time and workspace bounds for one finite binary machine. It is equivalent to one such machine halting with the encoded result on every valid encoded input. [IsDecidable](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Computable.lean#L127) asks for a computable Boolean indicator. “Total” here is relative to encoded instances: an arbitrary embedding need not have a decidable image, and no contract is silently added on malformed words.

Native partial evaluation returns a `Part` value and is connected to Mathlib's `Partrec` by [partrec_eval](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Partrec.lean#L648). More generally [IsComputable.computable_enc](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Partrec.lean#L657) needs a computable input encoding to conclude that the encoded result is Mathlib-computable. Recovering the typed function additionally needs a computable left inverse for its output encoding. On plain bit strings these side conditions are immediate. This is a stated one-way bridge, not an unrestricted equivalence of arbitrary typed encodings.

The single-tape/TM0/TM1 path supplies primitive-recursive operations on the finite tape representations, clocked runs, and partial-recursive eventual evaluation. [SingleTape/Partrec.lean](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/SingleTape/Partrec.lean#L16) connects those models to the same Mathlib framework. Mathlib's typed [Primrec](https://github.com/leanprover-community/mathlib4/blob/69552756cd8a2d2d48763cf7279fd814d6a1224d/Mathlib/Computability/Primrec/Basic.lean#L174) lifts primitive recursion through `Primcodable` encodings; [Computable](https://github.com/leanprover-community/mathlib4/blob/69552756cd8a2d2d48763cf7279fd814d6a1224d/Mathlib/Computability/Partrec.lean#L242) is the total-function subfamily of `Partrec`. Neither predicate imposes a native time bound. They justify effective data transformations and eventual evaluation, not a polynomial-time characterization. [mathlib][mathlib]

The native description development proves self-halting and general halting undecidability, corresponding acceptance results, mapping-reduction transfer, and Rice's theorem for nontrivial extensional properties of computed behavior. [Halting.lean](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting.lean#L167) [Rice theorem](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/Rice.lean#L622) The [s-m-n construction](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Halting/SMN.lean#L210) is itself native polynomial-time: it computes a description that prepends a fixed word to the future input before executing the supplied machine. This combines effective program manipulation with semantic preservation.

## Abstract description methods

[DescriptionMethod](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Basic.lean#L82) is a function from binary programs to `Computation α`, a monotone clocked partial computation. A program produces at most one value. The structure imposes no computability condition on that function; it is an abstract semantic interface, not automatically an effective programming language.

Plain `ecomplexity` is the minimum program length for eventual production, and `etimeBoundedComplexity t` is the minimum program length producing the value by clock `t`. Both take values in `ℕ∞`, with infinity for an undescribable value. The natural-valued wrapper uses `ENat.toNat`, so its value zero is not meaningful as a complexity bound when extended complexity is infinite. Theorems explicitly supply finiteness when passing to that wrapper.

[Simulation](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Invariance.lean#L70) carries a compiler with additive program-length overhead and an explicit time-overhead function. It yields complexity inequalities and composes with the required monotonicity conditions. `IsAdditivelyOptimal` is relative to a specified class of description methods. Counting/incompressibility theorems hold for every method because each short program has at most one result; additive-optimality statements require the appropriate simulation/effectiveness premise.

A conditional method is simply a family `β → DescriptionMethod α`, holding the condition fixed while minimizing program length. [Composition](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/ChainRule.lean#L82) combines an unconditional and a conditional program with explicit code-length and clock overhead. A self-delimiting header gives the logarithmic length overhead in the chain rule. The existence of such a header is not the assertion that the entire description model is prefix-free.

For the Partrec model, [condUniversal](../../CslibFrontier/Computability/Kolmogorov/ConditionalPartrec.lean) is the conditional universal method on natural numbers: after a code header, the announced code runs on the pair `Nat.pair y (encode p)` of the condition `y` and the rest `p` of the program. Every partial recursive function of the condition and the program is at most a constant worse, uniformly in the condition (`exists_ecomplexity_condUniversal_le_of_partrec₂`). This is the conditional invariance theorem of [Shen, Uspensky and Vereshchagin, Section 2.2][shenuspenskyvereshchagin17]. With `C(x) = universal.complexity x` and `C(y | x) = (condUniversal x).complexity y` the module proves `C(y | x) ≤ C(y) + O(1)`, `C(x | x) = O(1)` and the chain rule `C(⟨x, y⟩) ≤ C(x) + C(y | x) + 2 size C(x) + O(1)`, where `⟨x, y⟩` is `Nat.pair x y` and `size` is the binary length.

[SymmetryOfInformation](../../CslibFrontier/Computability/Kolmogorov/SymmetryOfInformation.lean) proves the converse, the Kolmogorov–Levin theorem: `exists_complexity_universal_add_condUniversal_le` states `C(x) + C(y | x) ≤ C(⟨x, y⟩) + 2 size k + 4 size (size k) + O(1)` with `k = C(⟨x, y⟩)`. Together with the chain rule this gives `|C(⟨x, y⟩) − C(x) − C(y | x)| ≤ 6 size k + O(1)`. For the algorithmic information `I(x : y) = C(y) − C(y | x)` (`algorithmicInformation`, integer-valued), it gives `|I(x : y) − I(y : x)| ≤ 12 size k + O(1)` [Shen, Uspensky and Vereshchagin, Sections 2.2–2.3][shenuspenskyvereshchagin17]. The proof enumerates the partners `v` with `C(⟨x, v⟩) ≤ k`, and then the numbers with at least `2 ^ l` partners, through [Nat.nthDistinctValue](../../CslibFrontier/Foundations/Computability/DistinctValues.lean) applied to primitive-recursive sequences of clocked runs. The counting step is the general bound `Set.mul_ncard_setOf_le_ncard_fiber_le`: few fibers can be large. All of this concerns plain complexity on natural numbers with `Nat.pair`; a different computable pairing changes `C(⟨x, y⟩)` by `O(1)`. The coefficients are those of this proof, and the source states only `O(log C(x, y))`. These results do not cover the prefix-complexity identity `K(x, y) = K(x) + K(y | x, K(x)) + O(1)`, the TM-based `condUniversalTM`, or time-bounded symmetry of information ([#3324](https://github.com/cslib-community/cslib-frontier/issues/3324)). [Checked clients](../../CslibFrontierTests/KolmogorovSymmetryOfInformation.lean) evaluate distinct-value enumerations, rule out a fourth value for a range of three, and run `condUniversal` on the code `left`. They also exhibit a number with `C(x | x) < C(x)`, and derive `C(⟨x, x⟩) = C(x) + O(log)` and `I(x : x) ≥ C(x) − O(1)`.

## Clock conventions

| Description model | Program interpretation | Meaning of clock `t` | Preserved result |
|---|---|---|---|
| `ofCode c` and Partrec `universal` | Mathlib `Nat.Partrec.Code`, with a code header and encoded binary input | Fuel for `Code.evaln`; bounds recursive evaluation depth and inspected numerical sizes | Additive optimality for partial-recursive description methods; same-fuel simulation of a fixed code |
| `ofMultiTapeTM tm`, `ofSingleTapeTM tm` | Binary program is the chosen machine's input | Steps of that fixed machine, under its halting/output convention | Exact output correspondence and explicit cross-model clock overhead |
| `ofTM0`, `ofTM1` | Finitely supported source machine is translated to a single-tape machine | Steps of the translated single-tape machine; TM0 detection adds one halt step | Eventual output and partial-recursive bridges; exact `t+1` TM0 clock theorem |
| `universalTM` | Parse a native description and an argument from the binary program | Steps of the **described machine**, not steps of a fixed interpreter | Constant code overhead with no simulated-clock overhead for each finite binary native machine |

Sources: [Partrec methods](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Partrec.lean#L101), [machine methods](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/MultiTape.lean#L69), [single-tape methods](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/SingleTape.lean#L81), and [universalTM conventions](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/TimeBounded.lean#L24).

The Partrec universal method has a genuine invariance theorem for its effective class, [isAdditivelyOptimal_universal](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Partrec.lean#L205). Its `evaln` fuel is not a machine-step complexity measure, though it is a Blum complexity measure (next section). The library proves uncomputability of its plain natural-number complexity, and that no computable unbounded function is everywhere a lower bound. [not_computable_complexity_universal](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Uncomputability.lean#L191)

[Incompleteness](../../CslibFrontier/Computability/Kolmogorov/Incompleteness.lean) proves Chaitin's incompleteness theorem for plain complexity [chaitin74][chaitin74]. Its standing hypothesis is `MinorizesPartrec`: the method is at most an additive constant worse than every partial recursive decoder `List Bool →. α`. The method itself need not be partial recursive. `universal` satisfies it, and so does its pushforward along any map with a computable section, for example the decoding to binary strings. A theory is an r.e. predicate on a `Primcodable` type of sentences with a computable `read` that recognizes the sentences asserting `n ≤ C(x)`. Soundness is a hypothesis on those sentences, so no logic is built. The quantitative form `exists_forall_le_complexity_universal_add` gives one constant `c` such that, whenever a `Nat.Partrec.Code` `e` semi-decides a sound collection, each of its bounds `n` is at most `universal.complexity (encode e) + c`. Its corollaries are bounded lower bounds for every sound r.e. collection or theory, and a true statement missing from each such collection. They also show that the incompressible strings (`|x| ≤ C(x)`) and the numbers with `Nat.size x ≤ C(x)` form infinite sets with no infinite r.e. subset. The proof is the Berry-paradox search. These results concern only the Partrec-side methods. The multi-tape `plain` complexity is not covered, because there is no compilation of partial recursive functions into `universalTM` programs. A prefix-free version and Chaitin's `Ω` are not formalized ([#3323](https://github.com/cslib-community/cslib-frontier/issues/3323)). [Checked clients](../../CslibFrontierTests/KolmogorovIncompleteness.lean) show that `literal` fails the hypothesis and apply the theorem to the trivially true statements `0 ≤ C(x)`. They state the string and number immunity results with `IsImmune`.

The single-tape description method requires a halted canonical output tape. Its native simulation keeps the program unchanged and uses the explicit time bound `3|p| + 2t + 6`. `ofTM0` incorporates the source's extra halt-detection step; `ofTM1` uses the compiled single-tape clock and does not charge an arbitrary structured source procedure as one native instruction. [singleTapeSimulation](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/SingleTape.lean#L143) [ofTM0 clock](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/SingleTape.lean#L117) [ofTM1](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/SingleTape.lean#L133)

For the native `universalTM` method, `unframe p` determines the described transition table and `dropFrame p` its input. The output is the entire halted output tape. A fixed machine is represented by a constant-size header, while the clock directly counts its source steps. This makes linear-time bounds exact in the selected described-machine semantics; actually evaluating the description still incurs the separately proved native simulator overhead.

That choice is particularly consequential for `levinKt`, defined by minimizing program length plus the ceiling of the logarithm of the described step count. The source explicitly warns that replacing this by a fixed universal simulator's step count can alter the logarithmic-time term by a constant factor, rather than merely an additive constant. This is the library's described-machine Levin-style measure; retain that convention when using cryptographic or fine-grained implications. It is not licensed to transfer additive-invariance claims from the plain model to this clock without the required simulator theorem.

`condUniversalTM` fixes an auxiliary binary word and runs the described machine on a paired program argument and condition. Conditional plain, time-bounded and Levin-style measures reuse that exact clock. [Conditional conventions](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Conditional.lean#L132) The generic `depth` measure is the truncated difference between time-bounded and plain extended complexity. It uses plain complexity; it is not a formalization of every prefix-free or logical-depth convention in the literature. [Depth](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/Depth.lean#L55)

## Abstract (Blum) complexity measures

[BlumMeasure](../../CslibFrontier/Computability/BlumComplexity/Basic.lean) fixes Mathlib's `Nat.Partrec.Code` with `Code.eval` as the acceptable numbering. A measure is a partial cost `cost c n` satisfying Blum's two axioms [blum67][blum67]: the cost is defined exactly when `c.eval n` is, and the graph predicate `m ∈ cost c n` is a `ComputablePred` of `((c, n), m)`. From the axioms the library derives `partrec_cost`, that every measure is partial recursive, and `computablePred_cost_le`, that halting within a given cost is decidable. Neither axiom refers to a machine; the measure is an abstract interface, and results about it hold for every measure.

`complexityClass t` is the class `C_t` of total functions `f` such that some code computes `f` at every input and has cost at most `t n` for all sufficiently large `n` (`∀ᶠ n in atTop`). This is Borodin's almost-everywhere convention [borodin72][borodin72]. A bound may fail at finitely many inputs. It is not the everywhere-bounded class, which can be smaller.

[fuelMeasure](../../CslibFrontier/Computability/BlumComplexity/Fuel.lean) is the instance whose cost `evalnFuel c n` is the least fuel `k` with `Code.evaln k c n` successful. Because `evaln` is primitive recursive, the graph predicate is decidable. The fuel bounds the evaluator's recursion depth and the size of every inspected number, so `n < evalnFuel c n` (`lt_of_mem_evalnFuel`) and classes of bounds `t ≤ id` are empty. It is the natural cost measure of Mathlib's evaluator, not a machine step count; it is the same clock as the Partrec description method above.

[gap_theorem](../../CslibFrontier/Computability/BlumComplexity/Gap.lean) is Borodin's gap theorem for every measure. For computable `g` with `n ≤ g n` and any computable lower bound `a`, there is a computable, strictly increasing `t ≥ a` with `complexityClass (g ∘ t) = complexityClass t`. `gap_theorem₂` allows a stretch that also depends on the input: for computable `g` with `y ≤ g n y`, `complexityClass (fun n => g n (t n)) = complexityClass t`. The underlying `exists_gap₂` is pointwise with an explicit threshold: for every code `c` and every `n ≥ encode c`, each cost of `c` on `n` is at most `t n` or above `g n (t n)`. The threshold depends on the code, so this does not give the equality for the everywhere-bounded class. [recursively_related](../../CslibFrontier/Computability/BlumComplexity/RecursiveRelatedness.lean) gives Blum's recursive relatedness: any two measures are bounded by each other through one computable `r`, for each code at all sufficiently large inputs. `recursively_related_of_encode_le` states the explicit threshold `n ≥ encode c`.

[speedup](../../CslibFrontier/Computability/BlumComplexity/Speedup.lean) is Blum's speedup theorem for every measure [blum67][blum67]. For every computable `r : ℕ → ℕ → ℕ` there is a computable function `f` with values in `{0, 1}` such that every code `c` computing `f` has another code `c'` computing `f` with `r n (Φ c' n) < Φ c n` for all sufficiently large `n`. The inequality is strict, which implies the non-strict form. `speedup'` is the one-argument form `r (Φ c' n) < Φ c n`, and `exists_no_fastest` restates the theorem as the absence of a code for `f` that is fastest up to `r`. The proof is Blum's priority construction: a generic cancellation run ([Cancellation](../../CslibFrontier/Computability/BlumComplexity/Cancellation.lean)) diagonalizes against every code that is cheap relative to a faster version of the construction, and Mathlib's recursion theorem `Code.fixed_point₂` lets the construction run its own versions. The theorem asserts that `c'` exists; it does not compute `c'` from `c`.

[Hierarchy](../../CslibFrontier/Computability/BlumComplexity/Hierarchy.lean) proves the theorem on arbitrarily complex functions for every measure, customarily credited to Rabin (1960) and, in this axiomatic form, to Blum [blum67][blum67]; neither attribution nor a theorem locator has been checked against the original texts. For every computable bound `t`, `exists_arbitrarilyComplex` gives a computable function `f` with values in `{0, 1}` such that every code `c` computing `f` has `t n < Φ c n` for all sufficiently large `n`. The lower bound holds almost everywhere for every code, which is stronger than `f ∉ C_t`. The proof is a cancellation run whose eligibility test, cost at most `t y`, is decidable by Blum's second axiom, so no recursion theorem is needed. Consequently every class `C_t` of a computable bound misses a computable `0`/`1`-valued function (`exists_not_mem_complexityClass`), no such class contains every computable function, and every computable `t` is dominated by a computable `t'` with `C_t ⊂ C_{t'}` (`exists_complexityClass_ssubset`). That `t'` is obtained non-uniformly.

[Union](../../CslibFrontier/Computability/BlumComplexity/Union.lean) proves the union theorem for every measure, Theorem VII.3.7 of Odifreddi's textbook [odifreddi99][odifreddi99], attributed there to McCreight and Meyer [mccreightmeyer69][mccreightmeyer69]. Let `T : ℕ → ℕ → ℕ` be `Computable₂` with `T i n ≤ T (i + 1) n`, which is the textbook's hypothesis. Then `union_theorem` gives a computable `t` with `complexityClass t = ⋃ i, complexityClass (T i)`. The bound is diagonal: `t n = T i n` for some `i ≤ n`. `exists_union_bound` states the pointwise content for every code, total or not: a code that halts within `t n` for almost all `n` halts within a single `T i n` for almost all `n`, and each `T i ≤ t` almost everywhere. `union_theorem_of_eventuallyLE` needs only `T i ≤ T (i + 1)` almost everywhere, and `union_theorem_of_directed` needs only `Directed (· ≤ᶠ[atTop] ·) T`: any two bounds are dominated almost everywhere by a third. Both are derived here from `union_theorem`, applied to the partial suprema `partialSups (T · n)`, that is `max (T 0 n) … (T i n)`. The proof was written independently using the library's cancellation run and has not been compared with the source's construction. Requirement `⟪j, i⟫` with `j ≤ i` is eligible at stage `y` when code `j` does not halt on `y` within `T i y`, and `t y` is `T i y` for the requirement cancelled there. Use the union theorem when a class is presented as an increasing union, such as the polynomial bounds `(n + 1) ^ i`. The bound it returns is computable but need not be one of the `T i`; for a constant family the diagonal property forces `t = T 0`. Nothing is claimed about how fast `t` itself can be computed. For a total code `c`, `forall_mem_cost_iff_exists_of_total` turns the class condition `∀ m ∈ Φ.cost c n, m ≤ t n` into `∃ m ∈ Φ.cost c n, m ≤ t n` and back.

[Naming](../../CslibFrontier/Computability/BlumComplexity/Naming.lean) proves the naming theorem for every measure, Theorem VII.3.6 of [odifreddi99][odifreddi99], attributed there to McCreight and Meyer. A family `φ_{h 0}, φ_{h 1}, …` is *measured* when `φ_{h i} x = y` is decidable uniformly in `(i, x, y)`. `naming_theorem` gives a computable `h : Code → Code` whose family is measured, such that for every total `φ_i = t` the function `φ_{h i}` is total and `complexityClass φ_{h i} = complexityClass t`. The measured family is `Φ.name`: `partrec_name` and `computablePred_mem_name` give uniform partial recursiveness and the decidable graph, and `dom_name` (with `exists_name_total`) gives totality. For a total `t` with name `t'`, `eventually_cost_le_name_iff` states the pointwise content for every code, total or not: a code halts within `t` almost everywhere exactly when it halts within `t'` almost everywhere. `complexityClass_name` is the class equality. The construction is the textbook's priority argument with a dynamic priority list, encoded by keys computed from the history of earlier stages. It differs in two places. The value given when an index acts at stage `⟪x, z⟫` is `z`, where the textbook uses `Φ_e(x) - 1`, which may be undefined. The textbook's argument for the requirements `L_e` (`C_{t'} ⊆ C_t`) is replaced by a quiet-set stabilization argument, described in the module docstring. Use the naming theorem when an argument needs every class `C_t` named by a member of one measured family, as the honesty theorem below does. The theorem says nothing about how `t'` compares with `t` pointwise, and `h` acts on codes, not on the functions they compute.

[Honesty](../../CslibFrontier/Computability/BlumComplexity/Honesty.lean) defines `IsHonest g f` for total `f`: some code computes `f` with cost at most `g n (f n)` for almost all `n` (Definition VII.2.13 of [odifreddi99][odifreddi99]; the textbook also allows partial `f`). `exists_isHonest_of_measured` is Exercise VII.2.14a there, for the total members of a measured family. `honesty_theorem` combines it with the naming theorem: one computable `g` gives every class `C_t` of a computable `t` a computable `g`-honest name `t'` with `complexityClass t' = complexityClass t`. Honesty is not automatic: for every computable `g`, the arbitrarily complex function for the bound `max (g n 0) (g n 1)` is a `0`/`1`-valued function that is not `g`-honest, a checked client below.

These are statements about the fixed numbering `Nat.Partrec.Code`. Native multitape time or space is not yet a `BlumMeasure`; that needs a Gödel-numbering bridge from native descriptions, with its own simulation overhead. Blum's compression theorem in its running-time form (a single computable `h` with `C_{Φ_i} ⊂ C_{n ↦ h n (Φ_i n)}` for every total `φ_i`; the form with the value `φ_i` in place of the cost `Φ_i` is false, by the gap theorem) is not formalized ([#2866](https://github.com/cslib-community/cslib-frontier/issues/2866)). The honesty results above cover total functions only. [Checked clients](../../CslibFrontierTests/BlumComplexity.lean) compute the fuel of the constant-zero code, show an empty class and an inhabited class, and exercise the almost-everywhere convention. They instantiate the gap theorem for `g n = n * n` with an inhabited gap class, and the two-argument gap theorem for `g n y = y ^ (n + 1)`. They apply recursive relatedness with its threshold to the fuel measure and a second measure, fuel plus input. Finally, they apply the speedup theorem to the fuel measure with exponential speedup `r m = 2 ^ m`, show that the speedup function has a code so the conclusion is not vacuous, show that it lies outside the fuel class of `n + 1`, and iterate the speedup twice. They also give an arbitrarily complex function for the bound `2 ^ n` with a code, so its lower bound is not vacuous, and a strict extension of the fuel class of `2 ^ n`. For the union theorem they take the polynomial bounds `(n + 1) ^ i`: the union class contains the constant-zero code's function, which is outside the class of the constant bound `1`, and it is not the class of all computable functions. They also apply the almost-everywhere form to `n ^ i`, which does not increase pointwise at `n = 0`. For the naming theorem they take the code `Code.succ`: its name is total and names the class of `n + 1`, which contains the constant-zero function. They apply the honesty theorem to the bound `2 ^ n`, show that the constant-zero function is honest for `g n y = n + 1`, and give the non-honest function above.

## Busy beaver functions

[BusyBeaver.Partrec](../../CslibFrontier/Computability/BusyBeaver/Partrec.lean) defines Radó's busy beaver functions [rado62][rado62] for the same numbering `Nat.Partrec.Code`, started on input `0` in place of a blank tape. The size of a code `c` is its Gödel number `encode c`; exactly `n + 1` codes have size at most `n`, so each maximum ranges over a finite set. `bbOutput n` is the largest output of a code of size at most `n` that halts on `0`, the analogue of Radó's `Σ(n)`. `bbFuel n` is the largest `evalnFuel c 0` among those codes, the analogue of his shift function `S(n)`; it uses the fuel clock of the previous section, not a machine step count. Use `le_bbOutput` / `le_bbFuel` to bound a specific code's output or fuel, and `exists_mem_eval_bbOutput` / `exists_mem_evalnFuel_bbFuel` to obtain a code attaining the maximum. Both functions are monotone, but not strictly so: the four codes of size at most `3` output `0`, `1`, `0`, `0`.

`eventually_lt_bbOutput` and `eventually_lt_bbFuel` prove domination: for every computable `f`, `f n` is below each function for all sufficiently large `n`. `not_computable_bbOutput` and `not_computable_bbFuel` follow. For `H m = ∑_{i < m} f i`, the proof adapts Radó's argument: `H` plays the role of his majorant `F`, and the recursion theorem replaces his double application `F(F(x))` and machine chaining to absorb the program's own size. Concretely, `Code.fixed_point₂` yields a code `G` whose run on `k` outputs `H (encode (w (k + 1)))`, where `w k = succ ∘ G ∘ const k`. The code `w k` then outputs more than `f n` for every `n < encode (w (k + 1))`, and its fuel is at least its output. `eventually_lt_bbOutput_comp` covers coarser size measures `n ↦ bbOutput (σ n)` with `n ≤ σ n`, such as bit length with `σ ℓ = 2 ^ ℓ - 1`.

Halting gives a second, independent route, the unrelativized corollary of Aaronson's Proposition 1 [aaronson20][aaronson20] (which solves the halting problem with oracle access to any upper bound on the shift function). `dom_eval_iff_isSome_evaln_bbFuel` shows that fuel `bbFuel n` decides halting for every code of size at most `n`. Therefore `computablePred_dom_eval_of_bbFuel_le` turns a computable upper bound on `bbFuel` into a decision procedure, contradicting `ComputablePred.halting_problem` (`not_exists_computable_bbFuel_le`). The two functions bound each other up to computable changes of size. `bbOutput_lt_bbFuel` gives `bbOutput n < bbFuel (4 * n ^ 2 + 14)`, since a code's output plus one is at most the fuel of its composition with `succ`. `exists_computable_bbFuel_le_bbOutput` goes the other way, since the fuel of a code is the output of another code of computably bounded size. So `not_exists_computable_bbOutput_le` holds as well.

The model is not Radó's. Programs are partial recursive codes measured by Gödel number rather than Turing machines measured by states, and the output is a number rather than a count of ones. Nothing here computes or bounds the Turing-machine values such as `S(5) = 47,176,870`. A simulation bridge to Turing machines, independence results and the connection to Chaitin's `Ω` are open ([#3314](https://github.com/cslib-community/cslib-frontier/issues/3314)). [Checked clients](../../CslibFrontierTests/BusyBeaver.lean) compute `bbOutput 0 = 0`, `bbOutput 1 = bbOutput 3 = 1` and `bbFuel 3 = 1` exactly. They show `3 ≤ bbOutput 16` via `pair succ succ`, and they apply the halting characterization to `zero`. They apply domination to the diagonal Ackermann function, which is computable but not primitive recursive, under both size measures, and derive unboundedness of `bbOutput`.

## Post's correspondence problem

[PostCorrespondence.Basic](../../CslibFrontier/Computability/PostCorrespondence/Basic.lean) defines dominoes over an arbitrary alphabet, `Solvable` for a list of dominoes (some nonempty list of its dominoes, repetitions allowed, has equal top and bottom concatenations), and the modified problem `MInstance.Solvable` of [sipser13][sipser13]: the match must begin with a designated start domino. An MPCP instance lists the start domino separately from the dominoes that may follow it, so the start domino recurs only if it is also in that list; Sipser's MPCP is the case where it is. Instances are `Primcodable` whenever the alphabet is, so both problems are predicates for Mathlib's `ComputablePred` and `≤₀`. `not_computablePred_solvable_bool` proves that PCP over `Bool` is undecidable [post46][post46], [sipser13][sipser13] (Theorem 5.15), and `not_computablePred_solvable` extends this to any `Primcodable` alphabet with two distinct letters. `not_computablePred_mSolvable_bool` and `not_computablePred_mSolvable` do the same for MPCP. Every reduction below is primitive recursive and proved correct in both directions.

The chain starts from `ComputablePred.halting_problem`. [TM0Universal](../../CslibFrontier/Computability/Machines/Turing/SingleTape/TM0Universal.lean) fixes a `ToPartrec` code that evaluates the `n`-th partial recursive code at `0`, compiles it with Mathlib's `PartrecToTM2`, `TM2to1` and `TM1to0` into one `TM0` machine `M₀`, and restricts that machine to its finite support ([TM0Restrict](../../CslibFrontier/Computability/Machines/Turing/SingleTape/TM0Restrict.lean), `TM0.restrict`, `TM0.eval_restrict_dom`) into `M₀'` with finitely many states. [Undecidable](../../CslibFrontier/Computability/PostCorrespondence/Undecidable.lean) feeds the input tape `input (encode c)` into [OfTM0](../../CslibFrontier/Computability/PostCorrespondence/OfTM0.lean), which builds the MPCP instance of Sipser's computation-history construction, and `OfTM0.eval_dom_iff_solvable` shows that it is solvable iff the machine halts. The argument goes through [Rewrite](../../CslibFrontier/Computability/PostCorrespondence/Rewrite.lean), which reads dominoes as semi-Thue rules: with copy dominoes and a start domino `ε / w`, a match is a rewriting of `w` to the empty word, given an end marker that separates successive words. [Modified](../../CslibFrontier/Computability/PostCorrespondence/Modified.lean) reduces MPCP to PCP (`toPCP`, `solvable_toPCP_iff`). [Substitution](../../CslibFrontier/Computability/PostCorrespondence/Substitution.lean) moves between alphabets with letter substitutions that are injective on words (`solvable_map_subst_iff`). A unary code reduces any `Primcodable` alphabet to `Bool`, and a two-letter map reduces `Bool` to any alphabet with two distinct letters.

The formal chain differs from Sipser's in three ways. The machine is fixed: the instance depends only on the input of one universal machine, not on a machine–input pair as in his reduction from the acceptance problem `A_TM`. Mathlib's `TM0` has a two-way infinite tape and halts when no transition applies, so the instance encodes halting rather than acceptance and has rules that extend the tape on both sides. The MPCP-to-PCP step adds a start marker `▷` to the start domino and drops the domino `ε / ε`. Without the marker, the construction can be unsound on MPCP instances that contain a domino with an empty bottom. For the start domino `a / ba` and the domino `b / ε`, the MPCP instance has no match, but the unmarked PCP instance does. Sipser's machine instances never contain such a domino, so this does not affect his proof.

Not formalized (see the ROADMAP entry; milestone [#3387](https://github.com/cslib-community/cslib-frontier/issues/3387)): decidability of PCP over a one-letter alphabet and of PCP with two dominoes; undecidability for a bounded number of dominoes, such as five; the reduction from the acceptance problem of an arbitrary machine–input pair, as in Sipser; and the standard consumers, namely ambiguity of context-free grammars, emptiness of the intersection of two context-free languages, universality of context-free grammars, and matrix mortality. [Checked clients](../../CslibFrontierTests/PostCorrespondence.lean) check a match of Sipser's four-domino example by `decide` and give an instance with no match because every top is longer than its bottom. They check the start-marker counterexample above, an MPCP instance of a machine that halts at once with a match, and one for a machine that never halts with no match.

## Relative computability and Turing degrees

Mathlib defines relative computability inductively: `Nat.RecursiveIn O f` is the closure of the basic functions and the oracles in `O` under pairing, composition, primitive recursion and unbounded search, `f ≤ᵀ g` is `RecursiveIn {g} f`, and `TuringDegree` is the quotient by mutual reducibility. Diagonal constructions over this notion need an enumeration of oracle computations with finite approximations. [RecursiveInCode](../../CslibFrontier/Foundations/Computability/RecursiveInCode.lean) supplies it. `Nat.RecursiveIn.Code` is the analogue of Mathlib's `Nat.Partrec.Code` with an extra atomic code `oracle`, `Code.eval g` evaluates a code relative to the oracle `g`, and `Code.exists_code` (with `turingReducible_iff_exists_code`) shows that `Nat.RecursiveIn {g} f` holds exactly when `f = Code.eval g c` for some code `c`. Consequently a function or a Turing degree has only countably many predecessors (`countable_setOf_turingReducible`, `TuringDegree.countable_Iic`).

`Code.evaln σ k c n` is stage-bounded evaluation against a finite oracle prefix `σ : List ℕ`, following Mathlib's `evaln`: it is defined only for `n < k`, every intermediate value is also bounded by the stage, and the oracle query at `i` returns `σ[i]?`. It reads only the first `k` entries of `σ` (`evaln_take`) and is monotone in the stage and the prefix (`evaln_mono`, with the sharper `evaln_mono_of_agree`). `evaln_sound` holds for every partial oracle extending `σ`. Completeness (`evaln_complete`, `mem_eval_iff_exists_evaln`, `eval_eq_rfindOpt`) is stated for total oracles `f : ℕ → ℕ`, through the prefixes `prefixOf f N`, because a partial oracle has no contiguous finite prefix. Soundness and completeness give the use principle `exists_use`: a convergent computation relative to a total `f` converges to the same value relative to every total oracle that agrees with `f` below some bound.

[KleenePost](../../CslibFrontier/Foundations/Computability/KleenePost.lean) proves the incomparability part of the Kleene–Post theorem [kleenepost54][kleenepost54] by finite extension (see also [soare87][soare87]). `Nat.RecursiveIn.kleene_post` gives sets `A B : Set ℕ` whose indicators satisfy `¬A ≤ᵀ B` and `¬B ≤ᵀ A`, and `TuringDegree.exists_incomparable` restates it as two incomparable degrees. Each stage extends one finite string by a bit against one code, after deciding whether some extension of the other string forces that code to converge at the new position; the construction makes that decision by classical choice. The source theorem also places `A` and `B` below `0′`, because the decision is a `Σ₁` question. That bound is not formalized: it needs a primitive recursive `evaln` on encoded codes, typed `RecursiveIn` combinators and a halting set for the jump. Merged Mathlib lacks these; the open Mathlib PR [mathlib4#38973](https://github.com/leanprover-community/mathlib4/pull/38973) proposes oracle codes with total oracles, a code for the oracle `evaln` and the jump, and is a possible route to the bound (the `RecursiveInCode` module docstring records its overlap with this library's codes). The Friedberg–Muchnik theorem (incomparable computably enumerable degrees) is also open ([#3379](https://github.com/cslib-community/cslib-frontier/issues/3379)). [Checked clients](../../CslibFrontierTests/KleenePost.lean) build the code `comp succ oracle` and its reduction, evaluate `evaln` on explicit prefixes, including a prefix that is too short and a stage too low for an intermediate value, and apply `evaln_take`, soundness and the use principle. They show a computable set below every oracle, and they derive from Kleene–Post that both sets are not computable and that the two degrees are distinct.

## Decision and hardness clients

The description models support concrete membership theorems with visible parameter encodings:

- [MINKT.mem_NP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/MINKT.lean#L251) verifies a short program producing a specified word by a supplied time. The instance uses unary size and time bounds; the verifier's polynomial cost is measured in that encoded input length.
- [MINcKT.mem_NP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/MINcKT.lean#L231) adds an auxiliary condition, with the same explicit time/size convention.
- [MKtP.mem_E](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Kolmogorov/MKtP.lean#L328) places the library's Levin-style threshold problem in single-exponential time when the threshold is unary. It does not prove that arbitrary binary-threshold input has the same resource bound.

Fixed-bound and gap/promise variants expose these conventions rather than treating the numerical parameters as free. Incompressibility, chain-rule, conditional-copy and computational-depth results concern these selected methods. Their hardness/cryptography applications cross into the programs-and-cryptography chapter; this chapter makes no claim that generic average-case assumptions or conjectured separations have been proved.
