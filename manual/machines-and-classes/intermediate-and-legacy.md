# Intermediate interfaces and other Turing formalisms

[Chapter index](index.md) · [Native resource contracts](native-and-resources.md)

The library uses several mathematical execution interfaces between an algorithm and the native transition table. Their abstract steps are specification steps. Finite control, time, and tape space are obtained through a separate compilation/resource theorem. This distinction is essential when a configuration contains a Lean natural number, list, or arbitrary state type. [complexitylib][complexitylib]

## Intermediate interfaces

| Interface | State and observation | Output/halting | Realization contract |
|---|---|---|---|
| `StepMachine σ Γ Out` | Arbitrary encoded state and a physically moving, bounded input head; the current optional symbol is observed | Each abstract step may append an output word | Compile state, emit, movement and continuation routines to native machines; charge their time and space |
| `ReadMachine σ` | State chooses an optional natural address; out-of-range or absent address returns `false` | State transition emits a word; halting freezes execution | Simulate addressed reads by StepMachine head movement and an encoded head-position counter |
| `QueryMachine σ` | State chooses a natural address and receives `Option Bool` | Live emission plus a final word; `none` distinguishes beyond-end reads | Native full-input scans with binary counters; resource certificates charge constituent functions |
| `NondeterministicQueryMachine σ` | QueryMachine-style input observation plus a Boolean choice | Decision-only acceptance after halt | All-choice-string halting and state-space certificates compile to a native NTM |
| `CounterProgram` | Finite instruction list, natural registers and program counter | Read branches distinguish true/false/end; emit and halt instructions | Compile to QueryMachine; fixed register count and polynomial register values yield logarithmic space |
| Nondeterministic counter program | Same syntax with register zero receiving a fresh Boolean after every instruction | Final `[true]` is accepting | Rank invariants prove all branches terminate; compile via the nondeterministic query interface |

Sources: [StepMachine](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/StepMachine/Basic.lean#L59), [ReadMachine](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/ReadMachine/Basic.lean#L41), [QueryMachine](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Complexity/LogSpace/QueryMachine.lean#L71), [NondeterministicQueryMachine](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Complexity/LogSpace/NondeterministicQueryMachine.lean#L48), [counter syntax](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Complexity/LogSpace/CounterProgram.lean#L1), and [nondeterministic counter semantics](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Complexity/LogSpace/CounterProgram/Nondeterministic.lean#L1).

`ReadMachine` and `QueryMachine` are not interchangeable: default-false reading cannot itself distinguish an actual false bit from a missing input position, whereas optional reading can. This matters for parsing framed inputs. Neither native compilation promises unit-time arbitrary-address access. The QueryMachine compiler scans the actual sequential input and reuses a binary position counter, saving space at the cost of time.

A StepMachine state type need not be finite. The compiler stores its encoding on tapes, so a large Lean state is not uncharged finite control. Its `Simulates` relation separately permits a fixed number of abstract steps per source step. A finite encoded-state bound yields a configuration-count halting bound; logarithmic state size gives a polynomial number of abstract steps when the machine halts. Native runtime still includes the cost of implementing each step. [Step-machine implementation](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/Combinators/StepMachine.lean#L48) [Read-to-step simulation](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/ReadMachine/StepMachine.lean#L45)

Counter expressions include addition, truncated subtraction, bit tests, multiplication, division and remainder. Their natural-number semantics are total: missing registers read as zero, division by zero gives zero, and remainder by zero returns the dividend. Exiting the code halts with the empty output. The logarithmic-space theorem uses a fixed number of polynomially bounded registers and charged expression evaluation, not unit-cost arithmetic on arbitrarily large integers. In the nondeterministic version the first instruction sees register zero initialized to zero; fresh choice is installed after the instruction.

These interfaces are used in concrete results. Reingold's connectivity algorithm passes through ReadMachine and StepMachine resource certificates. Configuration-graph algorithms and inductive counting use query/counter interfaces. The distinction between pure state semantics and native implementation keeps these programs readable without turning their arithmetic or random access into axioms about efficiency.

## cslib single-tape machines and Mathlib TM0/TM1

cslib's [SingleTapeTM](https://github.com/leanprover/cslib/blob/254e30e6d4299c51323aaeaf5f51a4763b375d4a/Cslib/Computability/Machines/Turing/SingleTape/Deterministic.lean#L96) packages a finite state type and finite inhabited alphabet. One bidirectionally infinite writable `BiTape` carries both input and output. A transition writes the scanned cell and may move left, right, or stay before selecting an optional next state. The function-computation contract asks for a canonical halted tape containing the output word. Its clocks count these single-tape transitions. The source credits Bolton Bailey, Pim Spelier and Daan van Gent. [cslib][cslib]

Mathlib's TM0 and TM1 supply different program syntax: TM0 is the low-level Post-style machine; TM1 packages structured tape statements, following Wang-style programming. The local [PostTuringMachine bridge](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/SingleTape/PostTuringMachine.lean#L15) translates cslib single-tape machines to TM1 step-exactly and then to TM0 at the level of eventual evaluation. Reverse constructions use the finite-support assumptions of the source programs; the TM0 direction accounts for an extra halt step. Thus a claim of one-step preservation belongs to the particular bridge theorem, not to every pair of these models.

The [single-to-multitape compiler](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/MultiTape/SingleTape.lean#L15) copies input to a work tape, executes the single-tape transition, and emits the canonical output. Its bound includes input copying, source steps and output traversal. It establishes a native polynomial-time realization of cslib `SingleTapeTM.PolyTimeComputable`; it does not assert equal clocks or equal work-space conventions.

### Crossing sequences and the palindrome lower bound

[CrossingSequence.lean](../../Complexity/Computability/Machines/Turing/SingleTape/CrossingSequence.lean) replays a `SingleTapeTM` run in absolute coordinates: an `AbsCfg` has an integer head position and an integer-indexed tape, with input cell `i` at position `i`, and `Agrees` links it to the `BiTape` run of `tm.step`. `AbsCfg.scanned` is the symbol under the head. Use `absRun_of_relatesWithinSteps` to move from any halting run of `tm.step` to the absolute run, which has halted by the time bound and scans the same symbol; `absRun_of_outputsWithinTime` and `DecidesByHeadInTime.absRun` are its specializations to canonical outputs and to head deciders. `AbsCfg.crossings k a t` lists the states entered by the steps that cross the boundary between cells `k - 1` and `k`. `AbsCfg.sum_length_crossings_le` bounds the total length of the crossing sequences over any finite set of boundaries by the number of steps. `AbsCfg.shift d` translates a configuration by `d` cells; `run_shift` and `crossings_shift` make runs and crossing sequences translation invariant.

`cut_and_paste_run` is Hennie's splicing lemma [Hennie1965][Hennie1965] in run form, for boundaries at different positions: if the runs on `u₁ ++ v₁` and `u₂ ++ v₂` have halted by `t₁` and `t₂` with the same crossing sequence after their prefixes, the run on `u₁ ++ v₂` has halted by `t₁ + t₂`, scans the final symbol of one of the two runs, and at every boundary on either kept side has the crossing sequence of the run that owns that side (shifted by `|u₂| - |u₁|` on the right). The prefixes must be both empty or both nonempty; otherwise the three heads start on different sides of the boundary, and the test file has a counterexample. `cut_and_paste` restates the lemma for canonical outputs.

[Decision.lean](../../Complexity/Computability/Machines/Turing/SingleTape/Decision.lean) defines `DecidesByHeadInTime tm ι L yes T`: every word `w` over the input alphabet, written on the tape as `w.map ι`, leads within `T |w|` steps to a halted configuration whose scanned cell holds `yes` exactly when `w ∈ L`. The rest of the final tape is unconstrained. This is more permissive than cslib's canonical output form.

[BoundedCrossings.lean](../../Complexity/Computability/Machines/Turing/SingleTape/BoundedCrossings.lean) proves `isRegular_of_crossings_le`: if `tm.DecidesByHeadInTime ι L yes T` and every crossing sequence at a boundary `1 ≤ b ≤ |w|` during the first `T |w|` steps has length at most `K`, then `L.IsRegular` in Mathlib's sense. The proof attaches to each nonempty word `u` the set of pairs (crossing sequence after `u`, final scanned symbol) over all extensions `u ++ v`. Words with the same tag have the same left quotient by `cut_and_paste_run`, so Myhill–Nerode (`Language.IsRegular.of_finite_range_leftQuotient`) applies. Boundary `0` is excluded because the splice needs nonempty prefixes; the empty word contributes the single extra quotient `L`. Pighizzini proves the nondeterministic analogue, calling it probably folklore ([Pighizzini 2009, Theorem 1][Pighizzini2009]).

[Palindrome.lean](../../Complexity/Computability/Machines/Turing/SingleTape/Palindrome.lean) applies these lemmas. `palindrome_lower_bound` gives `n ^ 2 ≤ 64 * d * T n` for `n ≥ 8 * d`, where `d = Nat.clog 2 (Fintype.card tm.State + 2)`, for every machine that decides `{w : List Bool | w.Palindrome}` with `DecidesByHeadInTime` and any letter map. `not_decidesByHeadInTime_palindromes_linear` rules out time `c * (n + 1)`. The constant depends on the machine's state count, as in the textbook statement. `DecidesPalindromesInTime tm a b yes T` is the canonical-output notion: a halt within `T n` steps on every word of length `n` over two letters `a, b`, with an output that begins with `yes` exactly on palindromes, the tape holding only the output and the head on its first cell. `DecidesPalindromesInTime.decidesByHeadInTime` converts it through `bitSymbol a b`, and `not_decidesPalindromesInTime_linear` is the corresponding corollary. The library has no single-tape palindrome decider yet, so the matching `O(n²)` upper bound is not formalized. [SingleTapeCrossing.lean](../../ComplexityTests/SingleTapeCrossing.lean) computes crossing sequences of a concrete right-moving machine, checks translation invariance and an unequal-length splice, shows the prefix hypothesis of `cut_and_paste_run` is needed, gives a positive `DecidesByHeadInTime` instance, applies `isRegular_of_crossings_le` to it, and applies both linear-time corollaries.

## Mathlib TM2 stack machines

TM2 is Mathlib's finite family of stacks with finite control and local auxiliary state. Complexitylib has explicit encodings and simulations in both directions. The forward implementation re-encodes finite stack alphabets as binary words. The reverse compiler encodes each native work tape as two stacks plus a current cell, handles read-only input with two stacks and a boundary flag, and reverses accumulated output during cleanup. [TM2 bridge guide](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/TM2/README.md#L1)

The important endpoint is not merely eventual computational equivalence:

- [computableInPolyTime_iff_tm2](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/TM2/Reverse/Transfer.lean#L139) preserves polynomial-time computability under the original binary input and output encodings.
- [computableInPolySpace_iff_tm2](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/TM2/Reverse/Transfer.lean#L150) connects the function model with polynomial encoded output to polynomial total-stack space.
- [mem_PSPACE_iff_tm2](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Machines/Turing/TM2/Reverse/Transfer.lean#L170) supplies the Boolean decision-class equivalence.

The reverse stack-space bound counts input, visited workspace and output at every target step, including initialization and cleanup. In contrast, native workspace excludes input and append-only output. Consequently these theorems establish polynomial-space invariance and do not identify logarithmic native workspace with logarithmic total stack size. A simulation that materializes the input cannot justify that sublinear-space conclusion. The guide explicitly preserves this boundary.

For a machine chosen after a parameter, as in a `2^(δ n)` argument, the degree of `stepTotal_polyTime` may depend on the program. [`stepTotal_computableInDegree`](../../Complexity/Computability/Machines/Turing/TM2/Degree.lean) certifies one step in `ComputableInDegree … 1 1` for every program, and `runBit_computableInDegree` certifies the clocked run on `(w, t)`, with `t` in unary, in degree two for every machine with finite stack alphabets; `runBit_eq` reads the answer once the clock reaches the running time.
