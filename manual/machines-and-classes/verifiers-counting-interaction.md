# Verifiers, counting, and interaction

[Chapter index](index.md) · [Endpoint map](endpoints-and-hierarchies.md)

Many class definitions are predicates over deterministic functions, accepted-witness counts, or oracle programs. Their efficiency clauses point back to finite binary native machines. This gives a common proof interface without identifying different quantifier orders, counting conventions, or prover capabilities. [cslib-frontier][complexitylib]

## Certificates, random seeds, and quantifier alternation

[NP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/NP.lean#L17) uses a deterministic polynomial-time Boolean verifier on `encPair enc encBits (a,w)`. A witness has exactly `p.eval |enc a|` bits for a fixed natural-coefficient polynomial `p`. Framing separates the input from its witness. The exact polynomial-length convention admits padding and gives the native NTM equivalence; merely handing a verifier a seed whose length is an arbitrary polynomially bounded function could encode uncomputable information in that length.

[PH](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/PH.lean#L211) iterates existential and universal quantification over bit-string blocks with fixed polynomial lengths. `SigmaP k` and `PiP k` differ in the first quantifier; zero blocks recover P and one existential block recovers NP. The library permits different polynomials for different blocks and proves the relevant padding/closure results. This is a verifier hierarchy, distinct from the operational ATM model; the polynomial-length alternating-game interface provides a separate connection to AP.

[BPP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/BPP.lean#L163) and [RP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/RP.lean#L143) use the same native deterministic verifier with a uniform seed of exactly polynomial length. BPP's fractions are expressed through finite accepted-seed counts, with thresholds two thirds and one third. RP has no false positives and accepts a yes instance on at least half of its seeds. `coRP` complements the language. Explicit amplification and coin-tape/PTM bridges connect these presentations to probabilistic execution.

A worked one-sided-error client is the Miller–Rabin test in [MillerRabin.lean](../../CslibFrontier/Computability/Complexity/Problems/Primes/MillerRabin.lean). Its verifier reads `2 |n|` random bits on the binary input `n` and reduces them to a base in `[1, n - 1]`. [decidesWithOneSidedError](../../CslibFrontier/Computability/Complexity/Problems/Primes/MillerRabin.lean#L268) charges the bias of reducing a uniform word modulo `n - 1` against the strong-liar bound [two_mul_card_isStrongLiar_le](../../CslibFrontier/Foundations/NumberTheory/Primality/StrongLiars.lean#L217), which gives [primes_mem_coRP](../../CslibFrontier/Computability/Complexity/Problems/Primes/MillerRabin.lean#L321). The sharper Rabin–Monier bound [four_mul_card_isStrongLiar_le](../../CslibFrontier/Foundations/NumberTheory/Primality/RabinMonier.lean#L334), at most `φ(n) / 4` strong liars for odd composite `n ≠ 9` (attributed in the module docstring to Rabin and to Monier, 1980), is not needed for the `1/2` error of `RP`. The same membership follows from AKS through `P_subset_coRP`; the client is there to exhibit the verifier and its error count, not to give a new route to the class membership.

The Solovay–Strassen test compares `a ^ ((n - 1) / 2)` with the Jacobi symbol `J(a | n)` modulo `n`; its Euler-liar bound is [two_mul_card_eulerLiars_le](../../CslibFrontier/Foundations/NumberTheory/Primality/EulerLiars.lean#L147). The symbol itself is certified by [binary_jacobiSym](../../CslibFrontier/Computability/Machines/Turing/MultiTape/Complexity/PolyTime/Nat/Jacobi.lean#L287): Mathlib's `jacobiSym` on binary naturals, with a binary signed result, for every `a` and `n` (even `n` and `n = 0` included). The proof runs the reciprocity reductions as a counted loop of `2 * Nat.size n` steps, each of which at least halves `a * n` ([jacobiReadout_iterate_jacobiStep](../../CslibFrontier/Computability/Machines/Turing/MultiTape/Complexity/PolyTime/Nat/Jacobi.lean#L244)), and `intBin_jacobiSym` extends it to a signed numerator. [JacobiPolyTime](../../CslibFrontierTests/JacobiPolyTime.lean) composes it into the Solovay–Strassen comparison and runs the loop on concrete inputs. The Solovay–Strassen `coRP` verifier is not yet stated ([#2958](https://github.com/cslib-community/cslib-frontier/issues/2958)).

[ZPP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/ZPP.lean#L19) changes the result type to `Option Bool`. A returned Boolean is always correct; at least half of all seeds yield an answer. The remaining seeds return `none`. The source proves `ZPP = RP ∩ coRP`. Expected polynomial running time is not modeled by this definition, and no equivalence with an expected-time operational semantics is claimed here.

## Counting and acceptance variants

[SharpP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/SharpP.lean#L67) consists of natural-valued functions counting accepted witnesses of a fixed polynomial length. [GapP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/SharpP.lean#L73) consists of differences of two such counts. The native list-branching CTM characterization preserves both accepting and rejecting multiplicities, rather than collapsing equivalent transitions. [mem_SharpP_iff_exists_machine](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/SharpP/Characterization.lean#L102) [mem_GapP_iff_exists_machine](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/SharpP/GapMachine.lean#L190)

The following are acceptance conventions over these shared count models, not a separate tape instruction set for each class. Here `f` is a #P function, `g` a GapP function, and all constraints apply to every valid encoded input.

The BPPpath presentation uses two counts and fixes a three-quarter ratio gap. Its source explicitly does not prove equivalence with arbitrary threshold-machine paths or invariance under every constant error threshold. Do not assume those stronger operational equivalences. Likewise AWPP's signed-count ratio is not a probability distribution supplied for free. Counting closure, lowness, relativization and time-bounded variants are developed over these definitions.

Prime-power moduli collapse to their prime: [ModP_prime_pow](../../CslibFrontier/Computability/Complexity/Classes/ModP/PrimePower.lean) proves `ModP (p ^ e) = ModP p` for prime `p` and `e ≥ 1` (Beigel and Gill, Theorem 30). So complement, intersection and union closure, and `coModP = ModP`, hold for every `IsPrimePow k`, and `ModP (2 ^ e) = ParityP`. A count is divisible by `p ^ e` exactly when `p` divides `C(f(a), p ^ i)` for every `i < e`, by Lucas's theorem ([Nat.pow_dvd_iff_forall_dvd_choose](../../CslibFrontier/Foundations/Data/Nat/Choose/PrimePowerDvd.lean), shared with the `ACC⁰` modular-gate reduction). Each such binomial coefficient is a #P count ([SharpP.choose_mem](../../CslibFrontier/Computability/Complexity/Classes/SharpP/Choose.lean)): a certificate lists `g(a)` accepted certificates in strictly increasing order. For other composite moduli only the divisor inclusion `ModP j ⊆ ModP k` (`j ∣ k ≠ 0`) is proved; Hertrampf's union closure for arbitrary moduli is not formalized.

The Boolean hierarchy (`BH`, `DP`) builds finite Boolean combinations/differences of NP languages, while `ParityOp` and `BPOp` act on other classes through existentially quantified polynomial lengths and parity or bounded-error seed counts. These are class operators over the preceding verifier machinery. [BooleanHierarchy](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/BooleanHierarchy.lean#L209) [Operators](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/Operators.lean#L68)

Deterministic polynomial-space counting enumerates `t`-bit certificates using a binary counter and binary accumulator via [`streamAcceptCount`](../../CslibFrontier/Computability/Complexity/Classes/SharpP/Space.lean) (`computableInPolySpace_acceptCount`, giving `SharpP.computableInPolySpace`). Unlike `SharpSAT.mem_SharpP`, which pads certificates to `|encCNF φ|` bits, [Problems/SAT/Space](../../CslibFrontier/Computability/Complexity/Problems/SAT/Space.lean) indexes `φ.numVars`-bit certificates by `φ.distinctVars` (`SAT.distinctVerifier`). Running `streamAcceptCount` over those `2 ^ φ.numVars` assignments computes `SharpSAT φ` in polynomial space (`SharpSAT.computableInPolySpace_numVars`), and testing positivity or uniqueness puts `SAT`, `UNSAT`, and `USAT` directly into `PSPACE encCNF` (`SAT.mem_PSPACE_of_enumeration`, `UNSAT.mem_PSPACE_of_enumeration`, `USAT.mem_PSPACE_of_enumeration`). The [checked examples](../../CslibFrontierTests/BooleanQuotientSAT.lean) evaluate `streamAcceptCount` on `2 ^ φ.numVars` assignments for gapped variable labels, unique satisfiability, the empty formula (`numVars = 0`), and unsatisfiability.

## Randomized approximate counting

[IsFPRAS](../../CslibFrontier/Computability/Complexity/Classes/FPRAS.lean) is the fully polynomial randomized approximation scheme interface for a counting function `f`. The algorithm `A x p t` is a strict PPT program (`IsPPTOn`, not expected time) on the encoded triple of the instance and two unary numbers. The relative error is `ε = 1/p` and the failure probability is `δ = 2^(-t)`, so polynomial time in the input length is polynomial time in `|x|`, `1/ε` and `log(1/δ)`. The output is a binary pair `(num, den)` standing for the rational estimate `num/den`. Success means `ApproxWithin (f x) p num den`, that is `den > 0` and `|num/den - f x| ≤ f x / p`, with probability at least `1 - (1/2)^t`. The bound is multiplicative, so an instance with count zero must be answered exactly (`ApproxWithin.num_eq_zero`). `IsFPRAS.approx` restates the guarantee for real `ε, δ > 0` by running on `p = ⌈1/ε⌉` and `t = ⌈log₂⌈1/δ⌉⌉`. The interface fixes no output-distribution error; samplers are specified separately by `IsFPAUS` below.

[SharpDNF](../../CslibFrontier/Computability/Complexity/Problems/SharpDNF.lean) counts the models of a DNF over `ℕ`-numbered variables, encoded by `encDNF`. Here [`KarpLubyMadras.isFPRAS`](../../CslibFrontier/Computability/Complexity/Problems/SharpDNF.lean) proves the Karp–Luby–Madras estimator is an FPRAS, including the native runtime. The estimator draws a term with probability proportional to its subcube size and then a uniform point of that subcube. Those weights need not be dyadic, so [the trial](../../CslibFrontier/Computability/Complexity/Problems/SharpDNF/KarpLubyMadras.lean) uses fair-coin rejection instead. It draws a uniform index below a power of two `D > m`, then `w_i - L` padding coins that must all be `false`, where `L` is the minimum width of a consistent term. Each pair (term, point) then has probability exactly `1/(D·2^(n-L))`. `eval_trial_true_toReal` gives the acceptance probability `#φ/(D·2^(n-L)) ≥ 1/D`. `approxWithin_estimate` applies the multiplicative Chernoff bound to `D·3(t+1)p²` trials. Inconsistent terms are rejected automatically, and a formula without models is counted exactly. The machine certificates are in [KarpLubyMadras/PolyTime](../../CslibFrontier/Computability/Complexity/Problems/SharpDNF/KarpLubyMadras/PolyTime.lean). To certify a new FPRAS instance, follow the same recipe:

1. Prove the deterministic steps with plain `ComputableInPolyTime` and `fun_prop`.
2. Build one trial from `isPPTOn_sampleDyadicIndex` (a uniform index below a power of two), `IsPPTOn.of_seeded` (a polynomial-time function of a unary-length block of fair coins), `IsPPTOn.ite'` and `IsPPTOn.bind_with`.
3. Repeat the trial with `IsPPTOn.countTrue` (after `IsPPTOn.preprocess` to restrict the input), using a unary trial budget.
4. Compute the output fraction with `IsPPTOn.map_with`.

The [model-count API](../../CslibFrontier/Logics/Propositional/DNF/ModelCount.lean) relates `DNF.modelCount` to subcube sizes. [Checked examples](../../CslibFrontierTests/SharpDNF.lean) cover exact counts, contradictory terms, the exact trial law and a zero-count formula.

[IsFPAUS](../../CslibFrontier/Computability/Complexity/Classes/FPAUS.lean) is the fully polynomial almost uniform sampler interface for a witness family `W : α → Finset (List Bool)`. The sampler `S x q` is strict PPT on the instance and the unary accuracy `q`, outputs an `Option (List Bool)` in `encOption encBits`, and its output law is within total-variation distance `(1/2)^q` of `uniformWitness (W x)`, stated with the library's statistical-distance predicate `Cslib.Probability.CloseTo` (all events, in `ℝ≥0∞`); `CloseTo.abs_toReal_sub_le` turns it into a real two-sided bound. That law is uniform on `some w` for `w ∈ W x`, and the point mass at `none` when `W x` is empty, so the zero-count case is part of the specification. The runtime is polynomial in `|x|` and `log(1/δ)` for `δ = 2^(-q)`.

[SelfReducible](../../CslibFrontier/Computability/Complexity/Classes/FPAUS/SelfReducible.lean) packages binary self-reducibility with explicit encodings. Every witness of `x` has length `len x` (computed in unary). When `len x > 0`, the witnesses of `x` beginning with `b` are `b ::` the witnesses of `child x b`, which has `len` one smaller and encoding no longer than `x`. The child map and the base test `[] ∈ W x` are polynomial-time. Each step fixes one bit; more general self-reductions that fix several symbols per step are not covered.

[`SelfReducible.isFPRAS_of_isFPAUS`](../../CslibFrontier/Computability/Complexity/Classes/FPAUS/FPRAS.lean) proves that a self-reducible family with an FPAUS has an FPRAS for `|W x|` (class form `mem_FPRAS_of_mem_FPAUS`). [The estimator](../../CslibFrontier/Computability/Complexity/Classes/FPAUS/Counting.lean) runs `len x` levels. Each level calls the sampler with accuracy `M = 16(ℓ+1)(p+1)`, counts `N = (t+ℓ+2)M²` samples beginning with each bit, descends to the child with the larger count `c` and multiplies the running ratio by `N/c`. The final numerator is zeroed when the last instance has no witness. `approxWithin_estimate` uses only the total-variation half of `IsFPAUS`. Choosing the larger count keeps the chosen fraction at least `1/4`, so `1/M` additive errors become `8/M` relative errors per level, and the `2ℓ` Chernoff failures total at most `2^(-t)`. `isPPTOn_estimate` certifies the loop with `IsPPTOn.iterateWith_spec'`, under the invariant that the current instance is no longer than `x` and both counters are at most `N^i` after `i` levels. [Checked examples](../../CslibFrontierTests/SamplingCounting.lean) instantiate the theorem with an exact sampler for the family whose witnesses of `(m, r, true)` are the words of length `m + r` beginning with `m` false bits (and `∅` for `(m, r, false)`). There, fixing a `true` bit inside the prefix leads to an empty branch. The examples also cover zero counts, witness length `0` and a sampler that fails `IsFPAUS`.

[`SelfReducible.closeTo_sampler`](../../CslibFrontier/Computability/Complexity/Classes/FPAUS/Sampler.lean) (`import CslibFrontier.Computability.Complexity.Classes.FPAUS.Sampler`) proves the output-law half of the converse, approximate counting ⇒ almost uniform sampling, following Jerrum, Valiant and Vazirani and Sinclair's Lecture 4, Section 4.2.3. Suppose a counter `A` is within relative error `1/p` with probability at least `1 - (1/2)^t` on every instance (`CounterAccurate W A p t`), for all `p > 0` and `t`. This is the correctness clause of `IsFPRAS`, so `closeTo_sampler_of_isFPRAS` applies to an FPRAS. Then the sampler's output law is within total-variation distance `(1/2)^q` of `uniformWitness (W x)`. Let `ℓ = len x`. The sampler estimates `|W x|` once and then runs at most `6(q+2)` trials. Each trial walks down the self-reduction tree. At each level it estimates both children with relative error `1/(4ℓ+3)` and confidence `q+ℓ+4`, then draws a dyadic coin that moves to child `c` with probability about `(1 - 1/m)(a_c/b_c)/(a/b)` and rejects otherwise (damping `m = 2ℓ+2`). Leaf estimates are exact, so the probability of reaching a witness telescopes to about `(1-1/m)^ℓ b/a`, the same for every witness. This spreads Sinclair's single final rejection step over the levels, and no path probability is recorded. `eval_walk_le` and `le_eval_walk` bound one walk, `eval_trial_none_le` shows that a trial rejects with probability at most `7/8` at a good root estimate, and `closeTo_uniformWitness_of_le` (built on `CloseTo.of_le_apply`) turns the pointwise lower bounds `(1 - 2^(-q))/|W x|` into closeness. The geometric-sum law of `OracleComp.retry` is `evalWith_retry_some`. The counter must have accuracy `1 + O(1/ℓ)`, which an FPRAS supplies at polynomial cost. Sinclair and Jerrum's weighted walk, which tolerates polynomial errors, is not formalized.

[`SelfReducible.isPPTOn_sampler`](../../CslibFrontier/Computability/Complexity/Classes/FPAUS/OfFPRAS.lean) (`import CslibFrontier.Computability.Complexity.Classes.FPAUS.OfFPRAS`) certifies the sampler as strict PPT on `(x, q)` when the counter is strict PPT on `(y, p, t)`. With the output law this gives `isFPAUS_of_isFPRAS`, the class inclusion `mem_FPAUS_of_mem_FPRAS`, and with the forward direction `mem_FPAUS_iff_mem_FPRAS`: sampling and counting are equivalent for one-bit self-reducible families. The recursive walk is run as a bounded loop of `len x` steps (`IsPPTOn.iterateWith_spec'`). Its state is the current node, its estimate in binary, the reversed path, and a running flag; a rejected walk stops and keeps its state. The invariant says the node is no longer than `x`, at most `i` bits are recorded after `i` steps, and the estimate is the root estimate or one returned at a node no longer than `x`. The counter's output-length bound (`IsPPTOn.length_le`) then bounds every state. The branching coin samples `coinWidth` fair bits with `isPPTOn_sampleBinaryNat` and compares them with thresholds computed in binary. The trials use the generic rule [`IsPPTOn.retry`](../../CslibFrontier/Computability/Probabilistic/Retry.lean) (bounded retries of a strict PPT program with a polynomial-time test and unary fuel; registered with `@[program_certificate]`). The [checked examples](../../CslibFrontierTests/SamplingCounting.lean) instantiate the output law with the exact counter and with the FPRAS obtained from the exact sampler, and cover the dead instance, the acceptance bound, good and bad estimates, the branching coin, and a counter that misses the accuracy hypothesis. They also certify the exact counter as strict PPT, instantiate `isFPAUS_of_isFPRAS`, the round trip through both reductions and the equivalence, and show that a strict PPT counter can still fail `IsFPRAS`.

When an exact witness counter `count z = |W z|` (on instances with `|enc z| ≤ |enc x|`) is available, [`FPAUS/ExactSampler.lean`](../../CslibFrontier/Computability/Complexity/Classes/FPAUS/ExactSampler.lean) (`import CslibFrontier.Computability.Complexity.Classes.FPAUS.ExactSampler`) avoids damped retries altogether. `SelfReducible.exactSample` queries `count x` once at the root (returning `none` when `count x = 0`) and queries only `count (R.child y true)` at each positive-length node, deducing `|W (R.child y false)| = c - c₁` from `SelfReducible.card_eq_add` and branching on an exact uniform draw in `Fin c`. By `SelfReducible.exactSample_eq_uniformWitness`, its output `PMF` equals `uniformWitness (W x)` identically (`CloseTo ... 0`), using at most `1 + R.len x` counter evaluations all on instances no longer than `x` (`length_exactSampleQueries_le`, `mem_exactSampleQueries_length_le`). Because `SelfReducible.card_le_two_pow_len` gives `|W y| ≤ 2 ^ R.len y`, drawing each index with the discrete-distribution-generating tree `Probability.uniformFinTree n` (exactly uniform by `uniformFinTree_generates`, at most `2 * ⌈log₂ n⌉` expected flips by `expectedFlips_uniformFinTree_le`) consumes at most `R.len x * (R.len x + 1)` expected fair flips in total (`0` when `W x = ∅`, `exactSampleExpectedBits_le`).

For strict native PPT and oracle-PPT execution (where coin budgets are worst-case polynomial rather than unbounded Las Vegas), `sampleFinBounded c fuel` caps binary rejection sampling at `fuel` trials of `sampleBinaryNat c.size` (consuming at most `2 * c.size` expected fair coins via `expectedCost_sampleFinBounded_le`). Running `R.len x` steps with `fuel = q + R.len x` (`SelfReducible.boundedConditionalSample`) keeps the counter budget at `1 + R.len x` (independent of `q`), achieves total-variation distance at most `(1 / 2) ^ q` (`closeTo_boundedConditionalSample`), certifies `IsPPTOn` and `IsFPAUS` when `count` is polynomial-time (`isPPTOn_boundedConditionalSample`, `isFPAUS_boundedConditionalSample`), and lifts to `IsOraclePPTOn` when `count` is `ComputableInPolyTimeWithOracle` (`isOraclePPTOn_boundedConditionalOracleSample`, `exists_oraclePPTSampler_of_oracle_count`). [Checked examples](../../CslibFrontierTests/ThresholdSearchAndExactSampler.lean) cover a non-dyadic (`|W| = 3`) witness family, dead branches, zero-length witnesses, `IsFPAUS`, and the oracle lift.

Counting arguments for matchings and permanents can use the deterministic upper bound [Bregman.lean](../../CslibFrontier/Foundations/Combinatorics/Bregman.lean) (`import CslibFrontier.Foundations.Combinatorics.Bregman`), which proves Brégman's theorem (Minc's conjecture) [bregman73][bregman73]. For a 0/1 matrix `A : Matrix n n ℕ` (every entry at most `1`) with row sums `r i`, `Matrix.permanent_le_prod_factorial_rpow` gives `per A ≤ ∏ i, (r i)! ^ (1 / r i)` in `ℝ`. `Matrix.permanent_le_factorial_rpow_card_div` is the `d`-regular form `per A ≤ d! ^ (n / d)`. A zero row contributes `0! ^ (1 / 0) = 1` under Mathlib's `Real.rpow` convention, and the permanent is then `0`, so there are no positivity hypotheses. The underlying statement `Equiv.card_filter_forall_rel_le_prod_factorial_rpow` counts the bijections `e : α ≃ β` with `R a (e a)` for all `a`. These are the perfect matchings of the bipartite graph `R` (the witnesses of `Cslib.Circuits.BipartiteMatching.HasPerfectMatching` when `α = β`), and `d a = #{b | R a b}` is the left degree. Equality holds for disjoint unions of complete bipartite graphs `K_{d,d}` (`Equiv.card_filter_forall_eq_eq_prod_factorial_rpow`, `Matrix.permanent_eq_prod_factorial_rpow_of_eq_ite`). The proof follows Schrijver's induction on `n` [schrijver78][schrijver78]. It uses the convexity inequality `Real.sum_mul_log_div_card_le` from [LogSum.lean](../../CslibFrontier/Foundations/Analysis/SpecialFunctions/LogSum.lean), not the entropy proof of [radhakrishnan97][radhakrishnan97]. `Matrix.permanent_eq_card_filter_of_le_one`, in [Permanent/ZeroOne.lean](../../CslibFrontier/Foundations/Data/Matrix/Permanent/ZeroOne.lean), identifies the permanent of a 0/1 matrix with this count. Only 0/1 matrices are covered. Extensions of the bound to nonnegative real matrices, the van der Waerden lower bound and the Kahn–Lovász bound for general graphs are not formalized. The [checked examples](../../CslibFrontierTests/Bregman.lean) evaluate `per J₃ = 6` (equality), a `2 × 2` matrix with `1 < √2`, a zero row, the block matrix `K_{2,2} ⊕ K_{1,1}` (equality) and a `2`-regular `4 × 4` instance.

## Efficient oracle programs

[IsOraclePPTOn](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Probabilistic/Oracle.lean#L63) realizes an open probabilistic word-query program by one finite native oracle PTM under one polynomial clock. The semantic equality quantifies over every state type, stateful oracle handler and initial oracle state, and preserves the joint output and final oracle state. Checking only the output marginal would permit a program to erase externally visible query effects; the joint contract rules this out.

The verifier pays for writing its query and reading the returned word locally. The oracle's own work is external. A reply may be arbitrarily long, but a polynomially clocked verifier can inspect only a polynomial prefix through its reply head. Named finite channels can share an interpreter state when that is the intended oracle semantics.

Deterministic [WordQueryComp and PolyTimeOracleProgram](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/Oracle.lean#L197) underlie `PWithOracle` and `NPWithOracle`. A language oracle returns one membership bit. The counting-oracle model uses [AnswersBits](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/Oracle/Counting.lean#L72): it constrains answers only on valid encodings of function arguments and bit positions. `PWithSharpPOracle` requires the same realizing program for every admissible answer function. This quantifier order prevents arbitrary answers outside the encoding image from providing an extra recognition oracle. Toda's theorem constructs one query to one bit of one #P function; the class definition itself allows general polynomially many oracle queries.

Promise oracles likewise quantify over all valid completions on the promise, rather than selecting a favorable behavior off it. The randomized promise-oracle route is used by Valiant–Vazirani. [RPWithPromiseOracle](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/ValiantVazirani.lean#L107)

For unsigned replay certificates, import
[`Classes.SharpP.OracleReplay`](../../CslibFrontier/Computability/Complexity/Classes/SharpP/OracleReplay.lean).
`Cslib.Complexity.replayPathCount` multiplies the answer-certificate counts along an
instruction-indexed transcript. Local and halted instructions require the canonical padding
bit `false`. Its membership lemma preserves `#P` when the input map is polynomial time and
both answer counts are in `#P`. When those counts recognize the oracle's yes and no answers
by positivity, `replayPathCount_pos_iff` identifies exactly the canonical oracle transcript;
when both counts are at most one, `replayPathCount_le_one` preserves unambiguity.
`Cslib.Complexity.replayWeightedSum` weights the path count of every transcript of the clock
length by a function of the instance and the replayed output, and sums. It stays in `#P` for a
`#P` weight (`replayWeightedSum_mem_SharpP`), is positive exactly when the weight of the
canonical replay is (`replayWeightedSum_pos_iff`), and equals that weight for unambiguous counts
(`replayWeightedSum_eq_of_le_one`). The
[decision](../../CslibFrontier/Computability/Complexity/Classes/Oracle/Lowness.lean) lowness
proofs weight by the indicator of a polynomial-time predicate, and the
[counting](../../CslibFrontier/Computability/Complexity/Classes/SharpP/Lowness.lean) ones by an
arbitrary `#P` function. They start from
`Cslib.Complexity.ComputableInPolyTimeWithOracle.exists_replayOutput` in
[`Classes.Oracle.CanonicalReplay`](../../CslibFrontier/Computability/Complexity/Classes/Oracle/CanonicalReplay.lean):
an `FP^A` output is the canonical replay of one finite oracle machine under one polynomial clock.

For quantifier-alternation simulations of oracle programs, import
[`Classes.PH.OracleNP`](../../CslibFrontier/Computability/Complexity/Classes/PH/OracleNP.lean).
`Turing.MultiTapePTM.eq_oracleReplies_iff` characterizes the canonical transcript by its reply
equations. `oracleTranscriptYes` and `oracleTranscriptNo` split those equations by bit: the transcripts whose
`true` bits answer queries in `A` form an `NP` problem when `A ∈ NP`, and the transcripts whose
`false` query bits answer queries outside `A` form a `coNP` problem. Guessing the transcript and
projecting with `mem_SigmaP_of_exists` (`Classes/PH/Collapse.lean`) gives
`PWithOracle_subset_SigmaP_two_inter_PiP_two`, that is `P^NP ⊆ Σ₂ ∩ Π₂`, and so
`PNPLog_subset_PH`. With `PH_subset_PNPLog_of_sparse`, `PH_eq_PNPLog_of_sparse` in
[`Classes.Sparse.Kadin`](../../CslibFrontier/Computability/Complexity/Classes/Sparse/Kadin.lean) is
Kadin's `PH = P^{NP[O(log n)]}` for a sparse Turing-complete `S ∈ NP`. Kadin's stronger hypothesis
`coNP ⊆ NP^S` and Hemachandra's `P^{NP[O(log n)]} = P^NP_tt` are not formalized. The
[checked client](../../CslibFrontierTests/PHOracleNP.lean) certifies the empty transcript, rejects an
uncertified `true` reply for the empty oracle, and places an `NP` problem and its complement in
`Σ₂ ∩ Π₂`.

For integer threshold optimization and witness recovery via adaptive oracle queries, import
[`Classes.Oracle.ThresholdSearch`](../../CslibFrontier/Computability/Complexity/Classes/Oracle/ThresholdSearch.lean).
`MaxThresholdSpec` and `MinThresholdSpec` bisect over `[0, bound x]` via
`Cslib.Algorithms.Lean.lowerBoundM` in `TimeM` (`maxOptWitnessM_spec`, `minOptWitnessM_spec`),
returning `none` when no valid witness exists and otherwise an optimal value and witness in at most
`Nat.log 2 (bound x + 1) + 1` threshold probes plus one witness-finder call. In the native oracle
model, `bisectProgram` iterates `bisectStepProgram` for `(hi x - lo x).size` rounds (`IsOraclePPTOn`
via `ComputableInPolyTime.binary_size`, so exponentially large binary bounds `hi x` are supported),
agrees with `lowerBoundM` (`iterate_bisectStep_eq_lowerBoundM`), makes at most
`(hi x - lo x).size ≤ Nat.log 2 (hi x - lo x) + 1` requests all in `[lo x, hi x)`
(`computableInPolyTimeWithOracleQueries_bisect`), and sequences with a witness-recovery stage via
`ComputableInPolyTimeWithOracleQueries.bind_with`.

As a worked `NP`-oracle client,
`MaxSATThreshold` (`MaxSATQuery` with `encMaxSATQuery`) lies in `NP` (`MaxSAT.mem_NP_threshold`),
and `MaxSAT.solveMaxSAT` recovers both `MaxSAT.maxClauseScore φ` and an optimal assignment
(`MaxSAT.solveMaxSAT_spec`) in at most `φ.length.size + φ.numVars` queries of encoded length at
most `(encMaxSATQuery ⟨φ, φ.length⟩).length` by partially evaluating `φ` over `φ.distinctVars`
(`applyPartial`), collapsing to plain `ComputableInPolyTime` when `MaxSATThreshold ∈ P`

This is a `P^NP` formulation on bare `CNF ℕ` with binary targets and the `NP` language itself as
oracle. [`FineGrained/MaxSAT/Reduction.lean`](../../CslibFrontier/Computability/Complexity/FineGrained/MaxSAT/Reduction.lean)

Unweighted `MaxSAT` clauses have unit weight; general integer-weighted objectives instantiate
`MaxThresholdSpec` / `MinThresholdSpec` and `computableInPolyTimeWithOracleQueries_bisect` directly.
The [checked examples](../../CslibFrontierTests/ThresholdSearchAndExactSampler.lean) exercise

[Bridge examples](../../CslibFrontierTests/MaxSATThresholdBridge.lean) check

## MA and AM

The [Arthur–Merlin definitions](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/ArthurMerlin.lean#L98) are fixed polynomial-length classical verifier games. In MA the proof precedes the random seed: a yes instance has one proof accepted on at least two thirds of seeds, while every proof for a no instance is accepted on at most one third. In AM the random challenge precedes the proof: acceptance counts the seeds for which some reply makes the verifier accept. The existential reply may therefore depend on the challenge.

The function `arthurMerlinSlice` is the logical existential predicate used to count favorable challenges. It is not asserted to be a polynomial-time decision procedure. The library proves amplification, `MA ⊆ AM` and containment in the second level of PH through this explicit verifier formulation. [`AM_subset_NPPoly`](../../CslibFrontier/Computability/Complexity/Classes/ArthurMerlin/Advice.lean) puts `AM` in `NP/poly`, a result usually attributed to Babai and Moran, by Adleman's fixed-coins argument for `RP ⊆ P/poly`. With the error reduced to `2 ^ (-(n + 1))`, the union bound over the at most `2 ^ n` instances of length `n` gives one random string that decides all of them (`exists_coins_forall_iff_exists`). That string is the advice, and Merlin's reply is the `NP` certificate. Corollaries are `MA ⊆ NP/poly`, private-coin games of any fixed pattern in `NP/poly` (`IPGameClass_subset_NPPoly`), and graph isomorphism in `coNP/poly` (`GraphNonIsomorphism.GraphIsomorphism_mem_coNPPoly`).

[Games with a fixed pattern of moves](../../CslibFrontier/Computability/Complexity/Classes/ArthurMerlin/Games.lean) extend these definitions. Each move is Arthur's fresh public coins or a Merlin message, with lengths polynomial in the instance length. One polynomial-time verifier reads the whole transcript. `AMGame.count` sums over Arthur's coins and maximises over Merlin's messages, so the value against an optimal, adaptive Merlin is counted exactly. `AMGameClass enc π` requires count at least two thirds of `2 ^ B` on members and at most one third on non-members, where `B` is the number of Arthur's bits. The patterns `A M` and `M A` give exactly `AM` and `MA`, and `AMk`/`MAk` are the alternating patterns. Parallel repetition is multiplicative for these public-coin games, which gives [error reduction](../../CslibFrontier/Computability/Complexity/Classes/ArthurMerlin/Games/Repetition.lean) for every pattern. The [round collapse](../../CslibFrontier/Computability/Complexity/Classes/ArthurMerlin/RoundCollapse.lean) proves that every fixed pattern lies in `AM`, with equality when `A M` is a sublist of the pattern. In particular `AM[k] = AM` for `k ≥ 2`, `MA[k] = AM` for `k ≥ 3` and `MAM = AM`. The patterns are fixed, so the round count is constant. The polynomial-round speedup is not covered; private-coin games with a fixed pattern are described under IP below.

## IP and MIP

[Prover](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/IP.lean#L78) has a private state, initial state and a probabilistic stateful response function. No computational bound is imposed on the prover. [IP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/IP.lean#L22) uses a Unit-channel oracle-PPT verifier, completeness two thirds and soundness one third. For every yes input there exists a prover; for every no input every prover fails with probability at least two thirds. Only transmitted messages reveal verifier information to the prover; fair coins remain private until their consequences are sent.

The finite native verifier and strict clock permit a finite quotient of observable interaction histories at every input, even though the prover's raw state and replies are unbounded. The `IP ⊆ PSPACE` direction optimizes over consistent histories and evaluates the finite game tree in polynomial space. The opposite direction builds the arithmetized TQBF protocol and transports it along PSPACE-completeness reductions. Together these yield `IP = PSPACE` for these encodings and semantics. [Shamir endpoint](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/IP/Shamir.lean#L61)

[Private-coin games with a fixed pattern of moves](../../CslibFrontier/Computability/Complexity/Classes/IP/Games.lean) give the constant-round class `IP[k]` in the form used by Goldwasser and Sipser. Each move is a verifier message computed from its private coins or a prover message, with lengths polynomial in the instance length. The verifier is a pair of polynomial-time functions (next message and final decision) of its `ρ(n)` coins, which the prover never sees. `IPGame.count` sums over verifier messages and maximises over prover messages. At a complete transcript it counts the coins that agree with every verifier message and accept, so `IPGame.bestCount` is exactly the number of coins accepted against an optimal adaptive prover: no deterministic prover does better and some prover attains it (`isIPGameVerifier_iff_provers`). Randomized provers are not modelled, since they do no better. `IPGameClass enc π` requires at least two thirds of the coins on members and at most one third on non-members; `IPk` is the alternating pattern with the verifier first. A public-coin verifier sends its coins, so `AMGameClass_subset_IPGameClass` and `AMk_subset_IPk` hold. [Parallel repetition](../../CslibFrontier/Computability/Complexity/Classes/IP/Games/Repetition.lean) runs `t` independent copies move by move and accepts when every copy accepts; `bestCount_repeat` shows the optimal count is the `t`-th power, and `IPGameClass.exists_repeat` turns the two-thirds/one-third gap into a `2^T : 1` multiplicative gap with the same pattern. Completeness also decreases under this AND-repetition; only the multiplicative gap is used. These games are separate from the oracle-PPT `IP` above. The [Goldwasser–Sipser emulation](../../CslibFrontier/Computability/Complexity/Classes/IP/Games/Emulation.lean) lets Merlin prove lower bounds on the count of any `0`/`1` payoff on a private-coin shape. At each verifier move Arthur sends an affine-hash seed, and Merlin answers with a claim `b`, a message and padding that hash to zero. The claim says the continuation is worth `2 ^ b`, and the padding must be zero on a prefix whose length is fixed by the previous claim and `b`. `Emulation.value_le` bounds the soundness error by `c (B + 1) 2 ^ K / (μ 2 ^ B) + μ ^ c N / 2 ^ κ` for every `μ > 0`, using only the first-moment bound of the hash. `Emulation.one_sub_le_value` bounds the completeness error by `c (B + 1) 2 ^ B / 2 ^ K` using the second-moment bound. Here `c` is the number of verifier moves, `N` the count and `κ` the initial claim. The claims are exact bit counts, so there is no rounding to powers of two. [GoldwasserSipser](../../CslibFrontier/Computability/Complexity/Classes/IP/Games/GoldwasserSipser.lean) applies this to the count of accepted coins, revealed by one last verifier move (`Emulation.countFrom_revealPayoff`). It first repeats the verifier `R(n)` times in parallel. The threshold is `K = B + ⌈log₂ (6 c (B + 1))⌉` and the initial claim is `ρ(n) - R(n)`, with `R` and `B` polynomials in the game size large enough for the gap `2 ^ R` to beat the soundness factor `μ ^ c`. `IPGameClass_subset_AMGameClass` maps pattern `π` to `Emulation.pattern (π ++ [.verifier])`: each verifier move becomes `A M`, a prover move becomes `M`, and a final `A M` is appended. With round collapse this gives `IPk_subset_AMk : IP[k] ⊆ AM[k + 2]` and `IPk_eq_AM : IP[k] = AM` for constant `k ≥ 2`. After merging adjacent Merlin moves the emulation pattern alternates in `k + 2` moves for even `k` and in `k + 3` moves for odd `k`, where the `k + 2` bound uses round collapse. Polynomially many rounds and the oracle-PPT `IP` are not covered ([#3425](https://github.com/cslib-community/cslib-frontier/issues/3425)).

[MIP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/MIP/Defs.lean#L15) uses a fixed finite number of classical noncommunicating provers. Its `Prover.independent` handler updates only the addressed component of the product of private states. Each prover sees its own local history; the verifier can query adaptively. The model permits coordinated deterministic strategies and independent private random coins; it does not represent entangled provers. `MIP₂` fixes two channels; `MIP` quantifies the finite channel count once for the whole language.

The proved class chain is `IP ⊆ MIP₂ ⊆ MIP ⊆ NEXP`. The last containment presamples deterministic strategies and verifies exponentially sized, locally consistent transcripts. The reverse `NEXP ⊆ MIP₂` route is absent at this snapshot, so the classical theorem `MIP = NEXP` is not a completed library endpoint. [MIP scope](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/MIP.lean#L15)

## PCP, local tests, and two-prover games

[PCPVerifier](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Classes/PCP.lean#L70) consists of three polynomial-time functions: a computable coin count, a list of queried natural-number addresses, and a verdict based on the answers. Queries are nonadaptive. A proof is a finite bit string, with `false` beyond its end; address encodings are binary. The class charges random bits and number of proof queries, with constant factors, while the three functions have native polynomial-time certificates.

The verifier computes its own coin count. The external function `r(n)` only bounds that count; the verifier is not handed a potentially uncomputable amount of random tape. Completeness is perfect and every false instance is accepted with probability at most one half under every proof. The full theorem is `NP = PCP(log₂ n + 1, 1)`. [NP_eq_PCP_log](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/PCP/Completeness.lean#L80)

The intermediate proof representations are useful models in their own right:

- [LocalTest](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/PCP/LocalTest.lean#L79) reads positions in an arbitrary typed proof using uniformly sampled finite randomness and a finite query layout. It is semantic; no uniform running-time certificate is built into the structure. It composes tests and translates rejection probability into violated-edge fractions.
- [ConstraintGraph](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/PCP/ConstraintGraph.lean#L94) has typed vertices, indexed directed edges, and a binary label relation per edge. Parallel edges and loops are allowed; unsatisfiability is a minimum violated-edge fraction. [RegularConstraintGraph](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/PCP/RegularConstraintGraph.lean#L76) adds a rotation map, with constraints on darts. Opposite darts need not carry the same relation. The [encoded graph](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/PCP/Encoded/Basic.lean#L119) uses concrete lists, addresses and a `WellFormed` predicate so constructions can receive native cost proofs.
- Assignment testers express proximity to satisfying label encodings through local tests. The generic Hadamard tester and the selected tester are construction components; their query/alphabet parameters should not be conflated. The final PCP endpoint uses its own fixed binary encoding and enormous but constant construction parameters. [Assignment-tester construction](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/PCP/AssignmentTester.lean#L25)
- [TwoProverGame](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/PCP/TwoProverGame.lean#L51) draws a pair of questions from a PMF and applies a predicate to separate classical answers. For finite question/answer types and nonempty answers, the value is attained by deterministic strategies and shared randomness does not increase it. Parallel repetition asks independent question tuples and checks all coordinates; no native efficiency is part of this abstract game model. Entangled strategies, the CHSH game and Tsirelson's bound are described in [Nonlocal games and Tsirelson's bound](../circuits-logic-and-other-models/algebraic-and-quantum.md#nonlocal-games-and-tsirelsons-bound).

The two-prover-game library proves the product-strategy lower bound on repeated value. [ParallelRepetition/Recursion](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/PCP/ParallelRepetition/Recursion.lean#L16) proves the analytic consequence of an assumed recurrence. For the upper bound, `TwoProverGame.lean` supplies the events `winsOn` (every coordinate in a set is won), their probabilities `winProbOn`, and the strategy-extraction step `winProbOn_insert_le` of Holenstein's Lemma 6.5. The step takes an embedding of the questions into the repetition conditioned on the won coordinates as a premise; [Compose local embeddings and extract a strategy](../workflows/probabilistic-workflows.md#compose-local-embeddings-and-extract-a-strategy) gives the imports, premises and checked clients. [Model the coordinates of the parallel repetition proof](../workflows/probabilistic-workflows.md#model-the-coordinates-of-the-parallel-repetition-proof) sets up the random variables of the proof of Lemma 6.4 and proves its first bound, (6.5). [Embed the questions at a free coordinate](../workflows/probabilistic-workflows.md#embed-the-questions-at-a-free-coordinate) carries the proof through (6.16) and proves the first stage of that embedding, with total error `27 / √2 · √(#Cᶜ (#C ln (|A| |B|) + ln (1 / Pr[W_C])))` over the free coordinates. [Extend the coordinate embedding to the question tuples](../workflows/probabilistic-workflows.md#extend-the-coordinate-embedding-to-the-question-tuples) proves the second stage, (6.17)–(6.19), and composes the two stages, so each free coordinate supplies that premise with its first-stage error. [Bound the value of a parallel repetition](../workflows/probabilistic-workflows.md#bound-the-value-of-a-parallel-repetition) states Lemma 6.4 and proves Holenstein's Lemma 6.5 and his parallel repetition theorem, Theorem 2.5: `TwoProverGame.value_pow_le` bounds the value of the `n`-fold repetition by `(1 - (1 - v)³ / 6000)^{n / log₂ (|A| |B|)}` when `|A| |B| ≥ 2`, over arbitrary tuple strategies. [LabelCover/Repetition](../../CslibFrontier/Computability/PCP/Approximation/LabelCover/Repetition.lean) applies it to Label Cover. The `k`-fold repetition `LabelCoverRepetition.pow` has the `k`-tuples of edges as edges, numbered by iterated `Nat.pair`, and keeps satisfiability. A Label Cover instance with at least one edge is a two-prover game (`LabelCoverRepetition.game`): a uniformly random edge, its left end asked of one prover and its right end of the other. Its value is at most the value of the instance. For an instance without parallel edges ([`Graph.NoParallelEdges`](../../CslibFrontier/Computability/PCP/Encoded/ParallelEdges.lean): no two edge occurrences with the same ordered endpoints; loops are allowed), the repeated game is no harder than the repeated instance. So `LabelCoverRepetition.one_sub_unsatVal_pow_le` bounds the value of the `k`-fold repetition by `(1 - ε³ / 6000)^{k / log₂ (|β| |γ|)}` when the instance has no parallel edges and every labelling violates at least the proportion `ε` of its edges. This is Raz's theorem for Label Cover without parallel edges, with Holenstein's explicit but astronomically large constants. Instances with parallel edges are not covered by this proof route. [LabelCover/SmallSoundness](../../CslibFrontier/Computability/PCP/Approximation/LabelCover/SmallSoundness.lean) derives NP-hardness. Loop removal ([`Graph.deloop`](../../CslibFrontier/Computability/PCP/Encoded/Deloop.lean), which keeps the value) makes the hard binary CSP instances loopless. The incidence reduction of a loopless instance has no parallel edges (`LabelCoverIncidence.noParallelEdges_reduce`). For each fixed `k` the repetition is polynomial-time (`LabelCoverRepetition.isPolyTime_pow`); its vertex numbers grow like `(n + 1)^{2^k}` (`LabelCoverRepetition.vertices_pow_le`), so the degree is exponential in `k`. So `GapLabelCover_npHard_pow` proves Label Cover with `128^{2k}` left and `128^k` right labels NP-hard at completeness `1` and soundness `(1 - 2⁻¹⁸⁶ / 6000)^{k / 21}`, and `exists_GapLabelCover_npHard` reaches every soundness `δ ∈ (0, 1)` with `k` depending on `δ`. This is Raz's theorem applied to the library's own PCP instance, not a general statement for arbitrary verifiers. Håstad's reductions to MAX-E3LIN and MAX-E3SAT are not yet formalized ([#886](https://github.com/cslib-community/cslib-frontier/issues/886)).

Satisfiable unique games are easy, which is why the Unique Games Conjecture asks for completeness `1 - ε`. [UniqueGames/Propagation](../../CslibFrontier/Computability/PCP/Approximation/UniqueGames/Propagation.lean) formalizes the label-propagation algorithm of [Khot 2010](../sources.md#khot10), Section 2.4. `UniqueGames.Propagation.solve` takes an executable instance and a list of the labels. It explores each connected component once, carrying every guess for the label of the component's first vertex in lockstep, and then checks the labelling it extracts against every edge. Its answers always satisfy every edge (`solve_sound`). If the list contains every label, every edge table is injective and the instance is satisfiable, it returns its labelling (`solve_eq_some_labelling`). So on unique games it decides value `1` (`solve_isSome_iff_unsatVal_eq_zero`) and solves `GapUniqueGames α 1 s` for every `s` (`solvedBy_gapUniqueGames_one`). Injectivity is needed: [UniqueGamesPropagation.lean](../../CslibFrontierTests/UniqueGamesPropagation.lean) has a satisfiable instance with constant tables on which `solve` fails. The tests also cover a 3-cycle of rotations, the odd and even cycles of negations over two labels, and a disconnected instance. [UniqueGames/PropagationTime](../../CslibFrontier/Computability/PCP/Approximation/UniqueGames/PropagationTime.lean) gives a `TimeM` version with the same answer (`solveM_ret`), charged at most `(L + 5) · N + (9 L + 16) · E + 1` steps for `L` labels, `N` vertex slots and `E` edges (`solveM_time_le`). The cost model has unit-cost array access, and one pass over a table on the labels costs `L + 1`. Khot only says that propagation runs in polynomial time; the explicit charge is this library's own analysis. For each fixed finite alphabet `Fin L`, [UniqueGames/Complexity](../../CslibFrontier/Computability/PCP/Approximation/UniqueGames/Complexity.lean) wires label propagation through the native multi-tape Turing machine framework under the `UniqueGamesConjecture` encoding `Graph.encoding (encPi (encFinEnum (Fin L)))`. Checking the final state table directly avoids constructing `ℕ → Fin L` closures at runtime and matches `(solve (List.finRange L) ·).isSome`, giving `UniqueGames.Propagation.computableInPolyTime_isSome_solve` for `[NeZero L]`, `gapUniqueGames_one_mem_PromiseP_of_pos` for `0 < L`, `gapUniqueGames_zero_mem_PromiseP` for the degenerate `L = 0` case (every unique game is vacuously a yes-instance and `.no = ∅`, while `not_satisfiable_fin_zero` shows none is satisfiable), the combined `gapUniqueGames_one_mem_PromiseP` for all `L : ℕ`, and exact `P` membership for unique-game recognition (`isUniqueGame_mem_P`) and satisfiability (`satisfiable_uniqueGame_mem_P`). This fixes `L` per problem rather than making `L` part of the input; [UniqueGamesComplexity.lean](../../CslibFrontierTests/UniqueGamesComplexity.lean) checks positive, negative, non-unique, and `L = 0` instances.

## Representative tests

[ArthurMerlinGames.lean](../../CslibFrontierTests/ArthurMerlinGames.lean) evaluates game counts and gives a game verifier that holds with the moves in one order and fails with them swapped. [IPGames.lean](../../CslibFrontierTests/IPGames.lean) evaluates private-coin counts, shows on one game that hiding the coins lowers the optimal count from two to one, evaluates a repeated game and instantiates `AM[k] ⊆ IP[k]` and gap amplification. [GoldwasserSipser.lean](../../CslibFrontierTests/GoldwasserSipser.lean) evaluates the emulation patterns. On a one-bit game the emulating verifier wins on six of eight seeds with the honest claim and on four with an inflated one, and never against a rejecting payoff. It also evaluates a revealed-coin count and instantiates `IP[k] ⊆ AM[k + 2]` and `IP[3] = AM`. [AMAdvice.lean](../../CslibFrontierTests/AMAdvice.lean) instantiates `AM ⊆ NP/poly` on a problem in `BPP`, on graph non-isomorphism (graph isomorphism in `coNP/poly`) and on a problem in `IP[2]`. [OraclePPT.lean](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/ComplexityTests/OraclePPT.lean#L1) checks actual composed query programs, the distinction between sampling and external query count, and a negative example showing that returning an unbounded oracle reply is not free. [MIP.lean](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/ComplexityTests/MIP.lean#L1) checks that querying channel zero preserves the other private state and includes positive and negative transcript-consistency instances. [Toda.lean](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/ComplexityTests/Toda.lean#L1) includes concrete counting identities, isolation examples and admissible counting-oracle instances. [PCPCompleteness.lean](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/ComplexityTests/PCPCompleteness.lean#L1) instantiates the encoded PCP interface. No execution of these tests is claimed by this chapter.
