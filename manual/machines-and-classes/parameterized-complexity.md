# Parameterized computation and kernelization

Parameterized complexity keeps encoded input length and an instance parameter separate. The parameter is an arbitrary map `κ : α → Nat`; a language is a set of typed instances with an injective encoding `enc : α ↪ List Bool`. The native machine reads only `enc a`. Declaring a parameter does not give it a separate register or an oracle for the parameter's value. The models here are native deterministic resource contracts and polynomial-time preprocessing interfaces. [complexitylib][complexitylib]

## One algorithm, potentially ineffective bounds

Write `L = |enc a|` and `k = κ a`. [`FPT`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L123) requires bound witnesses and then one native decision procedure valid for every input, with time bounded up to a global affine constant by `f(k) (L+1)^c`. The exponent `c` is independent of the parameter. [`XP`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L131) permits `f(k) (L+1)^g(k)`, so the degree can vary with the slice. Both use [`DecidableInTimeO`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/FineGrained.lean#L96), whose workspace bound is independently existential; neither imposes a separate small-space requirement.

The quantifiers do not require `κ`, `f`, or `g` to be computable. This is a uniform algorithm with possibly ineffective parameter bounds, not a separately chosen algorithm for each slice. It differs from Definitions 1.2–1.3 of Cygan et al., which require computable bound functions and present instances as `(x,k)` with size `|x|+k`. The library's encoding can instead encode a numerical parameter in binary. [cygan2015][cygan2015]

The finite-sum argument in [`mem_FPT_iff_exists_monotone`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L203) replaces an arbitrary bound by a monotone majorant; it does not establish computability. Likewise, [reparameterization](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L186) requires only `κ(a) ≤ h(κ'(a))`, without an effectiveness condition on `h`. The module proves `P ⊆ FPT ⊆ XP` and identifies both [FPT](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L448) and [XP](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L458) with `P` when the parameter is globally bounded.

## Functions and parameter-respecting reductions

[`ComputableInFPTTime`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L247) asks for a total native computation of `f : α → β` with both time and visited-work-cell space bounded by `F(κ(a)) (L+1)^c`. This common bound is not an independent space restriction on the FPT class: [the native time-to-FPT bridge](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L281) absorbs the fixed machine's work-tape count into `F`, since each step visits only a bounded number of new cells. Output is uncharged to raw workspace, but emitting it costs time. [`mem_FPT_iff_computableInFPTTime`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L408) characterizes FPT membership by a Boolean decider satisfying this function predicate.

[`FPTReducible`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L537) adds membership preservation and a target-parameter bound `κB(f(a)) ≤ h(κA(a))`. The reducing function has a native FPT computation; its time multiplier and `h` remain arbitrary. [`ComputableInFPTWithParam`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L528) exposes the computation and parameter conditions separately for the generic many-one calculus. The relation is transitive and pulls back both [FPT](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L581) and [XP](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L588). Composition uses finite majorants rather than an unrecorded monotonicity assumption. Other bounded reduction interfaces are described in [Reductions and information access](reductions.md).

## Kernels and the decidability boundary

[`IsKernelization`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L88) packages `K : α → α` and `g : Nat → Nat` with four obligations:

| Obligation | Formal content |
|---|---|
| Efficient preprocessing | `K` is native polynomial time in the original encoded input length. |
| Same decision problem | `K(a) ∈ A ↔ a ∈ A`. |
| Small encoded output | `encodedLength(K(a)) ≤ g(κ(a))`. |
| Controlled output parameter | `κ(K(a)) ≤ g(κ(a))`. |

The output stays in the same instance type and language. [`HasKernel`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L100) existentially quantifies `K` and arbitrary `g`; [`HasPolyKernel`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L105) additionally requires `g` to be polynomially bounded. The latter supplies a polynomial majorant, without declaring the original witness `g` computable. Separate bounds on length and parameter differ by at most a factor two from a bound on their sum. Cygan et al.'s Definition 2.1 requires a computable size bound; `HasKernel` omits that requirement. [cygan2015][cygan2015]

[`mem_FPT_iff_hasKernel`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L278) assumes a nonempty instance type and an existing native decision bound `A ∈ DTIME enc t`, for some length-based function `t`. Under those hypotheses, `A ∈ FPT enc κ ↔ HasKernel enc κ A`. The reverse implication runs the kernel and then the supplied decider. Having a small equivalent instance alone does not assert decidability.

The forward construction [`hasKernel_of_mem_FPT`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L181) performs a polynomially bounded universal simulation of the FPT decider. If it halts, preprocessing outputs a fixed yes- or no-instance with the matching answer; otherwise it returns the original instance, whose size is then bounded in terms of the parameter. It need not compute `f(k)` or `κ(a)`. This implements the timeout argument of the standard FPT-to-kernel proof; compare Cygan et al., Lemma 2.2, retaining the effectiveness difference above. [`hasPolyKernel_of_mem_P`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L290) separately gives a polynomial kernel for every `P` language over a nonempty type. These results do not make every FPT kernel polynomial.

## SAT and the exact-cardinality vertex-cover client

[`SAT_mem_FPT`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L229) places CNF satisfiability in FPT for the number of distinct variables; the module also covers each fixed clause-width restriction. The more detailed client is [`VertexCover_mem_FPT`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover.lean#L396), with the native bound in [`VertexCover_decidableInExpTime_one`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover.lean#L365) corresponding to `2^k` times a polynomial in encoded input length.

The target problem has a material convention: [`VertexCover`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Problems/VertexCover.lean#L86) asks for a cover of **exactly** `k` vertices from the declared vertex set. It is equivalent to an at-most-`k` cover only when `k` does not exceed the number of distinct declared vertices, as stated in [`mem_VertexCover_iff_exists_card_le`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Problems/VertexCover.lean#L110). A triangle with `k=4` is therefore rejected. The search procedure caps its internal unary search depth by the vertex count and checks that the cap equals the binary target. A huge binary target does not force a correspondingly huge polynomial-time preprocessing loop.

The explicit [`bussKernel`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L454) uses high-degree vertices forced into every small cover, then densely relabels the remaining active vertices. It retains enough isolated vertices to pad a cover to the exact target size. This differs from the at-most-`k` presentation in Cygan et al., Section 2.2.1, where isolated vertices can be discarded. [cygan2015][cygan2015]

The source proves these bounds for every input, including rejected inputs:

| Output quantity | Bound in the original target `k` | Declaration |
|---|---|---|
| Listed vertices | `k(k+2)` | [`length_bussKernel_vertices_le`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L573) |
| Listed edges | `(k(k+1))^2` | [`length_bussKernel_edges_le`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L581) |
| Encoded instance length | `40(k+1)^6` | [`length_encode_bussKernel_le`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L589) |
| Output target | `max(k,1)` | [`bussKernel_snd_le`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L610) |

The fixed rejection instance is an empty graph with target one, explaining the `max(k,1)` allowance. [`computableInPolyTime_bussKernel`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L601) proves native polynomial-time preprocessing under `encPair encGraph encNat`; [`isKernelization_bussKernel`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L618) packages its contract, and [`VertexCover_hasPolyKernel`](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L635) concludes a polynomial kernel. These are the actual encoded-size bounds; a smaller literature kernel is not substituted for them.

## Checked examples and scope

The inspected [Parameterized tests](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/ComplexityTests/Parameterized.lean#L1) instantiate bounded parameters, restricted-CNF FPT reductions, Boolean closure, and a constant kernel with both yes- and no-instances. They exercise the triangle at targets one through four. The [VertexCoverKernel tests](https://github.com/cslib-community/complexitylib/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/ComplexityTests/VertexCoverKernel.lean#L1) check dense relabeling, isolated-vertex padding, rejection from too many forced or active vertices, and a target exceeding the vertex count. These are existing test sources, not new compilation results.

The survey compared the displayed quantifiers and quantitative bounds with the pinned source fragments linked above. This was a textual check, not Lean elaboration or an audit of the proofs.

The local library declarations discussed here have candidate upstream markers. The [model map](../model-map.md) indexes the explanatory pages; declaration links here identify the pinned locations. This page describes FPT, XP, parameter-respecting reductions, kernels, and vertex-cover endpoints; it does not infer a W-hierarchy machine characterization or an effective-bound strengthening.
