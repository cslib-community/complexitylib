# Parameterized computation and kernelization

Parameterized complexity keeps encoded input length and an instance parameter separate. The parameter is an arbitrary map `κ : α → Nat`; a language is a set of typed instances with an injective encoding `enc : α ↪ List Bool`. The native machine reads only `enc a`. Declaring a parameter does not give it a separate register or an oracle for the parameter's value. The models here are native deterministic resource contracts and polynomial-time preprocessing interfaces. [cslib-frontier][complexitylib]

## One algorithm, potentially ineffective bounds

Write `L = |enc a|` and `k = κ a`. [`FPT`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L123) requires bound witnesses and then one native decision procedure valid for every input, with time bounded up to a global affine constant by `f(k) (L+1)^c`. The exponent `c` is independent of the parameter. [`XP`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L131) permits `f(k) (L+1)^g(k)`, so the degree can vary with the slice. Both use [`DecidableInTimeO`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/FineGrained.lean#L96), whose workspace bound is independently existential; neither imposes a separate small-space requirement.

The quantifiers do not require `κ`, `f`, or `g` to be computable. This is a uniform algorithm with possibly ineffective parameter bounds, not a separately chosen algorithm for each slice. It differs from Definitions 1.2–1.3 of Cygan et al., which require computable bound functions and present instances as `(x,k)` with size `|x|+k`. The library's encoding can instead encode a numerical parameter in binary. [cygan2015][cygan2015]

The finite-sum argument in [`mem_FPT_iff_exists_monotone`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L203) replaces an arbitrary bound by a monotone majorant; it does not establish computability. Likewise, [reparameterization](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L186) requires only `κ(a) ≤ h(κ'(a))`, without an effectiveness condition on `h`. The module proves `P ⊆ FPT ⊆ XP` and identifies both [FPT](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L448) and [XP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L458) with `P` when the parameter is globally bounded.

## Functions and parameter-respecting reductions

[`ComputableInFPTTime`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L247) asks for a total native computation of `f : α → β` with both time and visited-work-cell space bounded by `F(κ(a)) (L+1)^c`. This common bound is not an independent space restriction on the FPT class: [the native time-to-FPT bridge](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L281) absorbs the fixed machine's work-tape count into `F`, since each step visits only a bounded number of new cells. Output is uncharged to raw workspace, but emitting it costs time. [`mem_FPT_iff_computableInFPTTime`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L408) characterizes FPT membership by a Boolean decider satisfying this function predicate.

[`FPTReducible`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L537) adds membership preservation and a target-parameter bound `κB(f(a)) ≤ h(κA(a))`. The reducing function has a native FPT computation; its time multiplier and `h` remain arbitrary. [`ComputableInFPTWithParam`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L528) exposes the computation and parameter conditions separately for the generic many-one calculus. The relation is transitive and pulls back both [FPT](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L581) and [XP](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L588). Composition uses finite majorants rather than an unrecorded monotonicity assumption. Other bounded reduction interfaces are described in [Reductions and information access](reductions.md).

## Kernels and the decidability boundary

[`IsKernelization`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L88) packages `K : α → α` and `g : Nat → Nat` with four obligations:

| Obligation | Formal content |
|---|---|
| Efficient preprocessing | `K` is native polynomial time in the original encoded input length. |
| Same decision problem | `K(a) ∈ A ↔ a ∈ A`. |
| Small encoded output | `encodedLength(K(a)) ≤ g(κ(a))`. |
| Controlled output parameter | `κ(K(a)) ≤ g(κ(a))`. |

The output stays in the same instance type and language. [`HasKernel`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L100) existentially quantifies `K` and arbitrary `g`; [`HasPolyKernel`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L105) additionally requires `g` to be polynomially bounded. The latter supplies a polynomial majorant, without declaring the original witness `g` computable. Separate bounds on length and parameter differ by at most a factor two from a bound on their sum. Cygan et al.'s Definition 2.1 requires a computable size bound; `HasKernel` omits that requirement. [cygan2015][cygan2015]

[`mem_FPT_iff_hasKernel`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L278) assumes a nonempty instance type and an existing native decision bound `A ∈ DTIME enc t`, for some length-based function `t`. Under those hypotheses, `A ∈ FPT enc κ ↔ HasKernel enc κ A`. The reverse implication runs the kernel and then the supplied decider. Having a small equivalent instance alone does not assert decidability.

The forward construction [`hasKernel_of_mem_FPT`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L181) performs a polynomially bounded universal simulation of the FPT decider. If it halts, preprocessing outputs a fixed yes- or no-instance with the matching answer; otherwise it returns the original instance, whose size is then bounded in terms of the parameter. It need not compute `f(k)` or `κ(a)`. This implements the timeout argument of the standard FPT-to-kernel proof; compare Cygan et al., Lemma 2.2, retaining the effectiveness difference above. [`hasPolyKernel_of_mem_P`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/Kernelization.lean#L290) separately gives a polynomial kernel for every `P` language over a nonempty type. These results do not make every FPT kernel polynomial.

## SAT and the exact-cardinality vertex-cover client

[`SAT_mem_FPT`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized.lean#L229) places CNF satisfiability in FPT for the number of distinct variables; the module also covers each fixed clause-width restriction. The more detailed client is [`VertexCover_mem_FPT`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover.lean#L396), with the native bound in [`VertexCover_decidableInExpTime_one`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover.lean#L365) corresponding to `2^k` times a polynomial in encoded input length.

The target problem has a material convention: [`VertexCover`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Problems/VertexCover.lean#L86) asks for a cover of **exactly** `k` vertices from the declared vertex set. It is equivalent to an at-most-`k` cover only when `k` does not exceed the number of distinct declared vertices, as stated in [`mem_VertexCover_iff_exists_card_le`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Problems/VertexCover.lean#L110). A triangle with `k=4` is therefore rejected. The search procedure caps its internal unary search depth by the vertex count and checks that the cap equals the binary target. A huge binary target does not force a correspondingly huge polynomial-time preprocessing loop.

The explicit [`bussKernel`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L454) uses high-degree vertices forced into every small cover, then densely relabels the remaining active vertices. It retains enough isolated vertices to pad a cover to the exact target size. This differs from the at-most-`k` presentation in Cygan et al., Section 2.2.1, where isolated vertices can be discarded. [cygan2015][cygan2015]

The source proves these bounds for every input, including rejected inputs:

| Output quantity | Bound in the original target `k` | Declaration |
|---|---|---|
| Listed vertices | `k(k+2)` | [`length_bussKernel_vertices_le`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L573) |
| Listed edges | `(k(k+1))^2` | [`length_bussKernel_edges_le`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L581) |
| Encoded instance length | `40(k+1)^6` | [`length_encode_bussKernel_le`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L589) |
| Output target | `max(k,1)` | [`bussKernel_snd_le`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L610) |

The fixed rejection instance is an empty graph with target one, explaining the `max(k,1)` allowance. [`computableInPolyTime_bussKernel`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L601) proves native polynomial-time preprocessing under `encPair encGraph encNat`; [`isKernelization_bussKernel`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L618) packages its contract, and [`VertexCover_hasPolyKernel`](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/Complexity/Computability/Complexity/Parameterized/VertexCover/BussKernel.lean#L635) concludes a polynomial kernel. These are the actual encoded-size bounds; a smaller literature kernel is not substituted for them.

## Crown decompositions and the linear vertex-cover kernel

The linear kernel is formalized only combinatorially, on Mathlib's `SimpleGraph` with a finite vertex type, `Finset` vertex sets and the vertex cover number `vertexCoverNum : ℕ∞`. It is in [Crown](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/Crown.lean). `IsCrown G C H` says that `C` is independent, `H` is its neighbourhood, and `H` matches into `C`. `IsMatchingInto G A B m` records that matching as a partner map `m` that is injective on `A`; `IsMatchingInto.exists_isMatching` converts it into a Mathlib `Subgraph.IsMatching`. Unlike Cygan et al., Section 2.3, `C` may be empty: the empty crown is the base case, and `IsCrown.union_map` composes a crown with a crown of the residual graph. Theorems that need a nonempty crown state `C.Nonempty`. [cygan2015][cygan2015] [abukhzam2007][abukhzam2007]

`IsCrown.vertexCoverNum_eq` proves `τ(G) = τ(G - (C ∪ H)) + |H|`, where the residual graph is `G.induce (↑C ∪ ↑H)ᶜ`, and `IsCrown.vertexCoverNum_le_iff` gives the reduction rule for a target `k : ℕ`. `isCrown_iff_forall_card_le` is Hall's criterion. It provides a `Decidable` instance, so concrete crowns and non-crowns are checked by `decide`.

The crown lemma `exists_isMatchingInto_or_exists_isCrown` assumes more than `3k` vertices. It gives either a matching of more than `k` edges, which by `IsMatchingInto.card_le_vertexCoverNum` rules out a cover of at most `k` vertices, or a crown with `C` nonempty. For graphs without isolated vertices, `exists_isMatchingInto_or_exists_isCrown_of_forall_exists_adj` also gives `H` nonempty. The proof uses a maximum matching and Hall's theorem (Mathlib's `Finset.all_card_le_biUnion_card_iff_exists_injective`) in place of Kőnig's theorem in the usual textbook argument. A crown with the largest `C ∪ H` leaves a residual graph whose crowns are all empty.

That residual gives `exists_isMatchingInto_or_exists_isCrown_card_compl_le`: either a matching of more than `k` edges, or a crown with `|H| ≤ k` whose residual has at most `3 (k - |H|)` vertices. In the crown case, `IsCrown.vertexCoverNum_le_iff` makes `(G - (C ∪ H), k - |H|)` an equivalent instance: the residual of an explicit crown with the target lowered by `|H|`. A bare statement "some `R` with at most `3k` vertices and some `k' ≤ k` give `τ(G) ≤ k ↔ τ(G[R]) ≤ k'`" is deliberately not stated. Without a computability requirement it holds trivially, with `R` empty or a single edge and `k' = 0`. `card_le_two_mul_card_of_forall_isCrown_eq_empty` and `exists_isCrown_forall_card_compl_le` sharpen the residual bound to `2 (k - |H|)` for every `k ≥ τ(G)`, the size of the Nemhauser–Trotter kernel.

None of this is an `IsKernelization` of the encoded `VertexCover` problem. The crowns are obtained by choice, and nothing is computed in the machine model. The encoded problem also asks for covers of exactly `k` vertices, so it would need padding as in `bussKernel`. A polynomial-time kernelization needs a polynomial-time maximum matching or Kőnig cover. `ROADMAP.md` lists this, the LP-based `2k` kernel and the expansion lemma as open work ([#3378](https://github.com/cslib-community/cslib-frontier/issues/3378)). The [VertexCoverCrown tests](../../CslibFrontierTests/VertexCoverCrown.lean) check by `decide` that the leaves of a star form a crown with its centre as head. They also check that the centre alone, a head smaller than the neighbourhood and a non-independent set are not crowns, that the triangle has only the empty crown, and that two disjoint edges have crowns. They compute `τ = 1` for the star through the reduction rule and apply the crown lemma and the `2k` bound to these graphs.

## Color coding and fpt-reductions between graph problems

[`LongPath`](../../CslibFrontier/Computability/Complexity/Problems/LongPath.lean) is k-Path: a graph with a duplicate-free list of `k` declared vertices whose consecutive entries are adjacent. For `k+1` vertices this is a Mathlib `SimpleGraph.Walk.IsPath` of length `k` on the induced graph (`mem_LongPath_succ_iff`). The target `k = 0` is accepted by the empty path.

k-Path is `NP`-complete, with `k` in binary: [`LongPath_npComplete`](../../CslibFrontier/Computability/Complexity/Problems/LongPath/Hardness.lean). A certificate for `LongPath.mem_NP` is an ordering of the declared vertices, read by `Graph.verifyOrdering` as for Hamiltonian path. `LongPath.verifier` checks that the first `k` entries are `k` vertices with consecutive ones adjacent, and a path on `k` vertices extends to an ordering by appending the other vertices. Taking the first `k` entries with `k` in binary is polynomial-time as taking the first `min (length) k`, a count in unary. `LongPath_npHard` reduces undirected Hamiltonian path by the pendant copy `HamPath.pendantCopy`, described in the k-Path kernel section below; `HamPath.pendantCopy_mem_LongPath_iff` is its correctness. The gadget was written for this library and no novelty is claimed.

[`ColorfulPath`](../../CslibFrontier/Computability/Complexity/Parameterized/ColorCoding.lean) is the colored problem solved by the dynamic programming of Alon, Yuster and Zwick. An instance (`ColorfulPathInstance`, encoded by `encColorfulPathInstance`) packages a `graph`, a list of `colors` parallel to the vertex list (the color of a vertex is the entry at its first occurrence, `0` when the list is short), and a target `length` (`k`). The question is whether some path on `k` vertices has pairwise distinct colors, all less than `k`. Color sets are bit masks. `ColorCoding.mem_table_getD` proves that the table entry at a mask lists exactly the endpoints of colorful paths with that color set. `colorfulPathBool_eq_true_iff` proves the decider correct. [alonyusterzwick1995][alonyusterzwick1995] [cygan2015][cygan2015]

The resource statement is coarser than the RAM analysis. The table on `N` masks (`ColorCoding.TableInput` under `ColorCoding.encTableInput`) is polynomial-time with `N` in unary (`ColorCoding.computableInPolyTime_table`). The decider pads the instance by `2^min(n,k)`, where `n` is the number of distinct vertices. The parameter `k` is written in binary, so padding by `2^k` itself could be exponential in the input length. Capping at `n` keeps the padding below `2^n`, and the decider rejects `k > n` outright. [`DecidableInExpTime.of_computableInPolyTime_pad`](../../CslibFrontier/Computability/Complexity/FineGrained/Padding.lean) assumes three things. First, a Boolean procedure `Ψ` is polynomial-time on `encPair enc encUnary`. Second, an exponent `ν` is polynomial-time computable into unary with `ν ≤ μ`. Third, `a ∈ A ↔ Ψ (a, 2^ν a) = true`. Under these it gives a native machine within time `2^(δμ)` times a polynomial in the encoded length, for an existential `δ`. Hence `ColorfulPath_decidableInExpTime` and `ColorfulPath_mem_FPT`. The `2^k` operation count of the source is not claimed for multi-tape machines.

The randomized algorithm for k-Path, which colors uniformly at random and repeats, is not yet formalized; see issue #2870.

[`fptReducible_Clique_IndependentSet`](../../CslibFrontier/Computability/Complexity/Parameterized/Clique.lean) and its converse complement the graph on its declared vertices and keep `k`. This polynomial-time map is an `FPTReducible` instance, so `Clique` and `IndependentSet` are together in `FPT` (`Clique_mem_FPT_iff`) and in `XP`.

## Iterative compression: odd cycle transversal

Import `CslibFrontier.Algorithms.Lean.IterativeCompression.OddCycleTransversal` for the algorithm; it publicly imports the combinatorial layer and the separator solver. An odd cycle transversal of a Mathlib `SimpleGraph` is a vertex set whose deletion leaves a bipartite graph. [`IsOddCycleTransversal G S`](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/OddCycleTransversal.lean) is `(G.induce Sᶜ).IsBipartite`. It is equivalent to a Boolean colouring that is proper on the edges outside `S` (`isOddCycleTransversal_iff_exists_bool`) and to every odd closed walk visiting `S` (`isOddCycleTransversal_iff_forall_odd_walk`). The compression lemma `exists_isOddCycleTransversal_card_le_iff` is purely combinatorial. Let `W` be any set with a colouring `c₀` proper off `W`. Then an odd cycle transversal of at most `k` vertices exists exactly when there are three things. First, a part `D ⊆ W` to delete. Second, a colouring `σ` proper on `W \ D`. Third, a set `X` disjoint from `W` with `|D| + |X| ≤ k`, such that `W ∪ X` separates the *keep* terminals from the *flip* terminals of `(D, σ)` ([`SimpleGraph.IsSeparator`](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/Separator.lean)). A vertex `v ∉ W` adjacent to `w ∈ W \ D` keeps its `c₀`-colour when `σ w ≠ c₀ v`, and flips it otherwise. Its disjoint case `D = ∅` is Lemma 2 of [Hüffner][hueffner2009], stated there after subdividing the edges at `W`. [reedsmithvetta2004][reedsmithvetta2004] [cygan2015][cygan2015]

The separator is computed. [`minSeparatorM`](../../CslibFrontier/Algorithms/Lean/MaxFlow/VertexSeparator.lean) builds `vertexSplitNetwork`: it splits each vertex into an in-copy and an out-copy joined by a unit arc and gives all other arcs capacity `n + 1`. It then runs the library's dense Edmonds–Karp solver on `Fin (2n + 2)` and reads the separator off the minimum cut. It is minimum (`minSeparatorM_length_sep_le`), and a side labelling certifies separation (`minSeparatorM_isSeparator`). The [algorithm](../../CslibFrontier/Algorithms/Lean/IterativeCompression/OddCycleTransversal.lean) `octM G k` adds the vertices of `G` on `Fin n` one at a time. When the current solution reaches `k + 1` vertices, `compressM` tries the `3^(k+1)` guesses (delete, colour `false` or colour `true` on each vertex of `W`), each with one minimum-separator call. `octM_isSome_iff` states that `octM` succeeds exactly when an odd cycle transversal of at most `k` vertices exists. `octM_isOddCycleTransversal` certifies the output, and `octM_eq_none` gives the lower bound when it fails.

`time_octM_le` bounds the `TimeM` cost by `312 · 3^k · (n + 1)^6`. Reed, Smith and Vetta state `O(4^k · kmn)` for their algorithm. The `3^k` count, one of three roles for each vertex of `W`, is the analysis of [Hüffner][hueffner2009] (Theorem 1, `O(3^k · kmn)`), also used in [cygan2015][cygan2015], Section 4.4. The polynomial factor `n^6` is `n` iterations times the `O(n^5)` dense Edmonds–Karp bound. The sharper bounds stop each flow after `k + 1` augmenting paths on adjacency lists; they are not formalized. The cost annotations are trusted and follow the Edmonds–Karp unit-cost conventions, including unit-cost `Vector` updates in the shared guess tree. This is a `TimeM` RAM-model algorithm, so `OddCycleTransversal` is not yet placed in the encoded `FPT` class. The [OddCycleTransversal tests](../../CslibFrontierTests/OddCycleTransversal.lean) prove from colourings and `octM_isSome_iff` that the triangle and the five-cycle need one vertex, `K₄` needs two and the four-cycle needs none. They also run `octM` by `#guard` on these graphs, two disjoint triangles and the seven-cycle, and check `minSeparatorM` on a path and a four-cycle.

## The W-hierarchy

The *weft* of a circuit ([`Circuit.weft`](../../CslibFrontier/Computability/Circuit/Weft.lean)) is its depth with costs in which a gate of more than two arguments costs one and every other gate costs nothing. So it is the largest number of large gates on a path to the output. [`WeightedCircuitSAT`](../../CslibFrontier/Computability/Complexity/Parameterized/WHierarchy.lean) (over `WeightedCircuitSATInstance`, encoded by `encWeightedCircuitSAT`) asks whether a one-output circuit over the unbounded fan-in basis (negation, and conjunction and disjunction of any arity) has a satisfying input with exactly `k` ones. `WCS t d` restricts it to circuits of weft at most `t` and depth at most `d`. Its instances (`WCSInstance t d`, encoded by `encWCS t d`) package a circuit bounded in weft and depth (`WeftCircuit t d`), encoded as the circuit alone, together with the weight in binary. A reduction to `WCS t d` must therefore produce circuits that provably lie in the class. The cited definition likewise restricts instances to circuits of the class. `W t enc κ` is the class of problems that fpt-reduce to `WCS t d` for some `d`, with `WCSInstance.weight` as parameter. [cygan2015][cygan2015]

The module proves that `W t` is closed under fpt-reductions (`FPTReducible.mem_W`), increasing in `t` (`W_mono`), and contains `FPT` (`FPT_subset_W`): an fpt decider selects the fixed instance `WCS.yesInstance` or `WCS.noInstance` of `WCS t 1`. Fan-in is counted as arity with multiplicity, and the basis has constants and unary gates; neither changes the classes, since merging repeated arguments only lowers weft and constants propagate. `WHard t` is hardness under fpt-reductions; `wHard_iff` reduces it to every `WCS t d`, and `WHard.subset_FPT` says that a `W[t]`-hard problem in `FPT` puts `W[t]` in `FPT`.

[`IndependentSet_mem_W`](../../CslibFrontier/Computability/Complexity/Parameterized/WHierarchy/IndependentSet.lean) builds, in polynomial time, a circuit with one input per distinct declared vertex. It negates every input, takes for every edge between distinct declared vertices the disjunction of the negations of its ends, and outputs the conjunction of these disjunctions. A satisfying input of weight `k` is an independent set of `k` declared vertices (`toCircuit_satisfiableWithWeight_iff`). The final conjunction is the only large gate, so the circuit has weft at most `1` and depth at most `3`. These bounds use the reusable method in [`Circuit/Encoding/Layer.lean`](../../CslibFrontier/Computability/Circuit/Encoding/Layer.lean) for circuits built as codes. `evalCode_layer` evaluates a block of gates that reads only earlier wires. `le_of_mem_evalCode_depth_layer` adds the largest cost in the block to the depth bound, and `Circuit.depthWith_le_of_evalCode` turns the result into a weft or depth bound for the circuit. Edges with an undeclared end and self-loops are dropped, matching `Graph.toSimpleGraph` restricted to declared vertices. `Clique_mem_W` follows through the complement reduction.

The converse also holds: [`Clique_wHard`](../../CslibFrontier/Computability/Complexity/Parameterized/WHierarchy/Clique.lean) proves that `Clique` is W[1]-hard, by an fpt-reduction from every `WCS 1 d` (`WCS.fptReducible_Clique`). `IndependentSet_wHard` follows by complementing the graph, so both problems are W[1]-complete. `W_one_eq_FPT_iff` proves that `W[1] = FPT`, for every problem type, encoding and parameter, exactly when `Clique` is in `FPT`. The reduction is polynomial-time for each fixed `d` (`WCS.computableInPolyTime_toClique`), not uniformly in `d`. Its clique size is at most `(k + 1) ^ 2 ^ (d + 1) + 1` (`WCS.ToClique.size_le`). `WHard.fptReducible` transfers W[1]-hardness along fpt-reductions, so a new problem is W[1]-hard once `Clique` or `IndependentSet` fpt-reduces to it. The reduction is built in two steps, described in the next two paragraphs.

The first step is formalized in [`Circuit/Boolean/Unbounded/Certificate.lean`](../../CslibFrontier/Computability/Circuit/Boolean/Unbounded/Certificate.lean), on top of Kleene's three-valued evaluation of unbounded fan-in gate lists ([`Kleene.lean`](../../CslibFrontier/Computability/Circuit/Boolean/Unbounded/Kleene.lean), `kleeneEval`). A *claim* list (wire, value) is valid for an output (`WeftOne.claimsValid`) when Kleene evaluation finds the output true after the conjunctions claimed true and the disjunctions claimed false are replaced by constants, and every check of a claim lies at small depth at most `d`. Small depth counts only gates with at most two arguments. Validity does not read the input: what depends on the input is whether the checks hold on it. Valid claims whose checks hold on an input force the output true (`eval_of_claimsValid`). Conversely, if a circuit of weft at most `1` and depth at most `d` accepts an input, some list of at most `2 ^ d` claims that are correct on the input is valid (`exists_claimsValid_circuit`). A wire of small depth `D` is determined by at most `2 ^ D` inputs (`exists_determining`), and for fixed `d` the check is polynomial-time (`computableInPolyTime_claimsValid`). The claims and their check by Kleene evaluation are an original device of this library; the `2 ^ d` bound on the inputs that determine a wire of bounded fan-in is the standard fact behind the source's proof (cf. Cygan et al., Chapter 13).

The second step, the graph construction ([`WHierarchy/Clique/Graph.lean`](../../CslibFrontier/Computability/Complexity/Parameterized/WHierarchy/Clique/Graph.lean), `WCS.toClique`) encodes the exact-weight constraint problem left after the claims are fixed. Write `n` for the number of inputs and `kk = min (n + 1) k`. The vertices (`WCS.ToClique.Vertex`) are *certificates*, lists of at most `2 ^ d` valid claims, and *brackets*, lists of at most `2 ^ (d + 1)` pairs `(j, s)` with `j < kk` and `s < n`, read as "the `j`-th selected input is `s`". A bracket determines a partial input ([`WHierarchy/Clique/Bracket.lean`](../../CslibFrontier/Computability/Complexity/Parameterized/WHierarchy/Clique/Bracket.lean), `know`): the inputs it names are true, and an input that lies before the first selected input, after the last, or strictly between two consecutive ones that it names is false. A certificate is adjacent to a bracket when Kleene evaluation from that partial input refutes no check. Two brackets are adjacent when they are consistent (equal indices name equal inputs, and indices and inputs are in the same order) and have different lists of indices. The clique size is one more than the number of lists of at most `2 ^ (d + 1)` indices below `kk`. `toClique_mem_Clique_iff` proves that the graph has a clique of the size exactly when the circuit has a satisfying input with `k` ones. A satisfying input gives its correct certificate and the correct bracket of every list of indices (`mem_Clique_of_eval`). Conversely (`satisfiableWithWeight_of_mem_Clique`), a clique of the size has one certificate and one bracket per list of indices. The one-index brackets select `k` increasing inputs. For every check, the inputs that determine it (`exists_determining`) are known to the bracket of some list of at most `2 ^ (d + 1)` indices (`exists_cover`), so the check holds on the selected input. Determining sets appear only in this proof, so the construction needs no computable determining set. The graph, with one certificate vertex built on the claims above and bracket vertices, is this library's formulation. Certifying an unselected input by the consecutive selected inputs around it follows the classical gap technique of the standard proof (Downey and Fellows; Flum and Grohe; locators not checked). Theorem numbers in Cygan et al. Chapter 13 have not been checked against the book; the declarations cite Chapter 13.

The [WeftOneCertificate tests](../../CslibFrontierTests/WeftOneCertificate.lean) evaluate Kleene evaluation, small depths, checks and the certificate check by `decide` on small gate lists. The [WHierarchyClique tests](../../CslibFrontierTests/WHierarchyClique.lean) evaluate short lists, what brackets know, bracket consistency and cliques of graphs given by an adjacency test by `decide`. They also apply `toClique_mem_Clique_iff` to the fixed yes- and no-instances of `WCS 1 1` and to the conjunction of three inputs, whose graph has a clique of the size for weight `3` and none for weight `2`. For the circuit that outputs the first of two inputs they compute the graph itself by `decide`: for weight `0` it has two vertices and no edge, because the empty bracket refutes the certificate, and for weight `1` it has eight vertices and clique size `4`. Finally, they check the clique-size bound on an instance, W[1]-completeness of both problems, a reduction from `WCS 1 5` to `IndependentSet`, and that `Clique` in `FPT` would put every `WCS 1 d` in `FPT`.

## Tree decompositions and treewidth

The treewidth parameter is defined combinatorially on Mathlib's `SimpleGraph`, not on an encoded instance. A [`TreeDecomposition G ι`](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/TreeDecomposition/Basic.lean) has a tree on `ι` and finite bags. It covers every vertex and edge, and the nodes containing each vertex induce a connected subtree. `etreewidth : ℕ∞` minimizes width over decompositions with finitely many nodes, and `treewidth` is its truncation to `ℕ`. Since finitely many finite bags cover only finitely many vertices, `etreewidth G = ⊤` if and only if `V` is infinite, whatever the edges (`etreewidth_eq_top_iff`). So `⊤` carries no graph information, and this is not the treewidth of infinite graphs. For a finite vertex type the minimum is attained and is at most `card V - 1`, and the empty vertex type gets treewidth `0`. Treewidth is monotone under subgraphs and injective homomorphisms, and invariant under isomorphism. Open Mathlib pull requests ([mathlib4#38334](https://github.com/leanprover-community/mathlib4/pull/38334) and its follow-ups) define the same structure under different names; the module docstring records the differences and which local parts are additive.

Algorithms consume a [`RootedTreeDecomposition G n`](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/TreeDecomposition/Rooted.lean) instead. Its nodes are `Fin (n + 1)`, its tree is a parent array whose parents precede their children, and every vertex has a unique topmost bag. The last condition is decidable for concrete data. `exists_rooted` renumbers any finite decomposition into this form with the same bags and an adjacency-preserving bijection of nodes, and `treewidth_le_iff_exists_rooted` states the width correspondence. Every finite clique lies in one bag. [Bounds](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/TreeDecomposition/Bounds.lean) proves `cliqueNum ≤ treewidth + 1`, `minDegree ≤ treewidth`, `treewidth ⊤ = card V - 1`, treewidth `0` iff edgeless, treewidth at most `1` iff acyclic, and treewidth `2` for every cycle. The [TreeDecomposition tests](../../CslibFrontierTests/Foundations/Combinatorics/TreeDecomposition.lean) check a rooted decomposition by `decide` and reject parent and bag data that violate connectivity.

[Subtree](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/TreeDecomposition/Subtree.lean) adds the descendant relation, children and the vertices of the bags below a node of a rooted decomposition. A vertex below a child that is not in the parent's bag occurs only in bags below that child, so the parent's bag separates it from the rest of the graph. The [independent-set program](../../CslibFrontier/Algorithms/Lean/TreeDecomposition/IndependentSet.lean) is the first dynamic program over decompositions. Its tables are indexed by the subsets of a bag, and it processes the nodes from the leaves up. Each child sends its parent a message indexed by the parent's subsets, so the program works on arbitrary rooted decompositions and needs no nice decomposition or separate join nodes. `isGreatest_mwisValue` proves that the specification `mwisValue R w` is the largest total `ℕ`-weight of an independent `Finset`, and `mwisValue_one_eq_indepNum` specializes this to unit weights and the independence number. The specification keeps its tables as `Finset` closures, so evaluating it takes time exponential in the depth of the decomposition.

To run the program, supply bag lists `L` with `IsBagOrder R L` (each `L i` lists `R.bag i` without repetition; `sortedBags R` builds them for a linearly ordered vertex type) and call the [executable program](../../CslibFrontier/Algorithms/Lean/TreeDecomposition/IndependentSetFPT.lean) `mwisFPT R w L`. `ret_mwisFPT` proves that it returns `mwisValue R w`, so `isGreatest_mwisFPT` and `mwisFPT_one_eq_indepNum` follow. `time_mwisFPT_le` bounds its ticks by `(n + 1) · 2 ^ (k + 1) · (4 (k + 1) ^ 2 + 3 (k + 1) + 12)` for width at most `k`, and `time_mwisFPT` gives the exact count as a sum over the nodes of a closed form in the bag sizes. The program stores the tables as arrays indexed by bit masks in a `Vector` over the nodes, and charges its ticks inside the loops that do the work. The mask encoding and the scans of a bag list (independence test, restriction of a mask to the parent bag, weight of the forgotten vertices) are in [BagMask](../../CslibFrontier/Algorithms/Lean/TreeDecomposition/BagMask.lean).

The ticks count unit-cost RAM operations with an adjacency matrix. Membership in a bag is a linear scan, so a mask costs `O(k ^ 2)` ticks. The ticks model in-place array updates. The program uses its arrays linearly, but this is not proved and copying of a shared array is not charged. Computing the decomposition and the bag ordering is not charged either. Here `n + 1` counts decomposition nodes, which are not bounded in terms of `card V`. Cygan et al., Section 7.3.1, state their `2 ^ k · k ^ O(1) · n` bound for `n` vertices, after converting to a nice decomposition with `O(k · n)` nodes, so `mwisFPT` matches its per-node form but not yet its bound in the number of vertices. [cygan2015][cygan2015] The [independent-set tests](../../CslibFrontierTests/TreeDecompositionIndependentSet.lean) evaluate `mwisValue` and `mwisFPT` by `decide` on a weighted path, a five-cycle, an edgeless graph and a star with three children, and check the tick counts `273` and `97` of `mwisFPT` on the weighted path and the single bag. On path decompositions of every depth `N` they prove that `mwisFPT` takes exactly `120 N + 33` ticks, evaluate it by `decide +kernel` at depth `40`, and run the compiled program by `#guard` at depth `2000` and on `sortedBags`.

[`NiceTree`](../../CslibFrontier/Foundations/Combinatorics/SimpleGraph/TreeDecomposition/Nice.lean) and `G.NiceTreeDecomposition` normalize a decomposition into binary `join`, unary `introduce`/`forget`, and `leaf` nodes ending at an empty root bag. `RootedTreeDecomposition.prune` collapses redundant non-branching nodes, and `RootedTreeDecomposition.toNiceTreePruned` converts any `RootedTreeDecomposition` into a `NiceTreeDecomposition` without increasing `width` (`toNiceTreePruned_width_le`) and with at most `(3 * R.width + 5) * (card V + 1)` nodes (`toNiceTreePruned_size_le`). The [CSP tree-decomposition specification](../../CslibFrontier/Logics/Propositional/CSP/PrimalGraph.lean) constructs `F.primalGraph` and the restricted `F.activePrimalGraph` on `F.vars.toFinset`, defining `specDPCount` and `specDPDecide` (`specDPCount_primalGraph_eq_modelCount`, `specDPCount_activePrimalGraph_eq_modelCount`). The [executable CSP dynamic programs](../../CslibFrontier/Algorithms/Lean/TreeDecomposition/CSP.lean) `cspCountRootedM`, `cspDecideRootedM`, `cspCountActiveRootedM`, and `cspDecideActiveRootedM` run over mixed-radix bag tables (`lookupM`, `projectM`, `evalScopeM` in [BagAssignment](../../CslibFrontier/Algorithms/Lean/TreeDecomposition/BagAssignment.lean)) on `Fin q` domains (`q > 0`), with `ret_cspCountNiceM_equiv` bridging arbitrary `[Fintype D]`/`[Inhabited D]` alphabets via `D ≃ Fin q`, and charge unit-cost `TimeM` ticks bounded by `(3 * R.width + 5) * (card V + 1) * q ^ (R.width + 1) * dpNodeCost R.width F` (`time_cspCountRootedM_le`, `time_cspDecideRootedM_le`). The `TimeM` bounds model selected table operations; they currently exclude the uncharged recursive overhead of `bagList` list construction and element erasure, the structure normalization size of `toNiceTreePruned` computed outside `TimeM`, `sem` evaluations, and unbounded integer arithmetic. Bounding all traversal and arithmetic work for CSP counting and decision in `card V`, migrating `mwisFPT` to pruned nice decompositions, graph coloring clients, decomposition-finding algorithms, and connecting an encoded treewidth parameter to `FPT` remain open under [#2927](https://github.com/cslib-community/cslib-frontier/issues/2927) and [#3672](https://github.com/cslib-community/cslib-frontier/issues/3672).

## OR-distillation and `coNP ⊆ NP/poly`

Kernelization lower bounds rest on the theorem of Fortnow and Santhanam: no `NP`-hard problem has a weak OR-distillation unless `coNP ⊆ NP/poly`. The library proves this implication. It does not assume `coNP ⊄ NP/poly`. [bodlaenderjansenkratsch2014][bodlaenderjansenkratsch2014] [fortnowsanthanam2011][fortnowsanthanam2011]

[`NPPoly enc`](../../CslibFrontier/Computability/Complexity/Classes/NP/Advice.lean) is `NP` with polynomial advice. An advice function `adv : ℕ → List Bool` with polynomially bounded length is paired with a problem `B ∈ NP (encPair encBits enc)`, and `a ∈ A ↔ (adv |enc a|, a) ∈ B`. The advice depends only on the encoded length, and the verifier of `B` reads it as part of its input. `coNPPoly` is the class of complements. `NP` lies in `NPPoly`, and both classes are closed downward under polynomial-time many-one reductions (`PolyTimeReducible.mem_NPPoly`). `coNP_subset_NPPoly_iff` states that `coNP ⊆ NP/poly ↔ NP ⊆ coNP/poly`, and `coNP_subset_NPPoly_of_coNPComplete` derives the inclusion from a single `coNP`-complete member. [Yap.lean](../../CslibFrontier/Computability/Complexity/Classes/PH/Yap.lean) proves Yap's collapse [yap1983][yap1983]: `SigmaP_two_subset_NPPoly_of_coNP_subset_NPPoly` (`Σ₂ ⊆ NP/poly` from `coNP ⊆ NP/poly` on the witness-paired encoding), `PiP_three_eq_SigmaP_three_of_coNP_subset_NPPoly` (`Π₃ = Σ₃`), and `PH_eq_SigmaP_three_of_coNP_subset_NPPoly` (`PH = Σ₃`, with `PH = Σ₃ ∩ Π₃` in `PH_eq_SigmaP_three_inter_PiP_three_of_coNP_subset_NPPoly`). Through `CookLevin.UNSAT_coNPComplete` and the CNF decoder, `UNSAT_mem_NPPoly_iff_forall_coNP_subset_NPPoly` and `coNP_encBits_subset_NPPoly_iff_UNSAT` identify the quantified hypothesis `∀ {β} (encB : β ↪ List Bool), coNP encB ⊆ NPPoly encB` with `coNP encBits ⊆ NPPoly encBits`, `NP encBits ⊆ coNPPoly encBits`, `UNSAT ∈ NPPoly encCNF`, and `SAT ∈ coNPPoly encCNF`, giving the single-hypothesis forms `PH_eq_SigmaP_three_of_UNSAT_mem_NPPoly` and `PH_eq_SigmaP_three_of_coNP_encBits_subset_NPPoly`. The quantifier-rewriting step uses downward closure of `Σₖ`, `Πₖ`, and `PH` under `≤ₘᵖ` and closure of `Σₖ` (`k ≥ 1`) under existential quantification over words of polynomial-time unary length in [Reduction.lean](../../CslibFrontier/Computability/Complexity/Classes/PH/Reduction.lean).

[`IsORDistillation encA encB A B f s`](../../CslibFrontier/Computability/Complexity/Parameterized/Distillation.lean) is Definition 4 of Bodlaender, Jansen and Kratsch. It has three obligations:

| Obligation | Formal content |
|---|---|
| Efficient | `f : List α → β` is native polynomial time on `encList encA`. |
| OR property | `f l ∈ B ↔ ∃ a ∈ l, a ∈ A`, for every nonempty list `l`. |
| Short output | If `l` is nonempty and every entry has encoded length at most `n`, then `|encB (f l)| ≤ s n`. |

The output bound is independent of the number of entries. The value on the empty list is unconstrained, since Definition 4 concerns `t ≥ 1` instances. The size bound `s` is not required to be computable. Time is polynomial in the encoded list length, `t + 2(|x₁| + ⋯ + |xₜ|)` for `t` entries. The source bounds time by a polynomial in `∑ |xᵢ|`, which implies the library bound, so the library's time hypothesis is weaker. The two agree when no instance has an empty encoding.

`coNP_subset_NPPoly_of_orDistillation`, `NP_subset_coNPPoly_of_orDistillation`, and `PH_eq_SigmaP_three_of_orDistillation` give both conclusions (`NP ⊆ coNP/poly` and `PH = Σ₃`, the latter via Yap's theorem [yap1983][yap1983]) of Theorem 2 of the source, for any `NP`-hard problem in place of `SAT`, any target problem `B`, and a polynomially bounded size bound. Both conclusions hold for every instance encoding; `PH_eq_SigmaP_three_of_orCompression` is the class-wise form. The theorem number in the Fortnow–Santhanam paper itself was not verified; the cited locator is the one in Bodlaender, Jansen and Kratsch.

The proof is stated in the class-wise form needed for cross-composition. [`IsPolyEquivalence enc r`](../../CslibFrontier/Computability/Complexity/Parameterized/Distillation.lean) is Definition 8 of the source: `r` is an equivalence relation decidable in polynomial time, and the instances up to length `n` meet at most `c n` classes, for a polynomially bounded `c`. `compl_mem_NPPoly_of_orCompression` makes three assumptions. First, `f` is polynomial time with the OR property on nonempty lists of pairwise related instances. Second, `t` is polynomially bounded. Third, every list of exactly `t n` related instances of length exactly `n` maps to an output shorter than `t n`. The conclusion is `Aᶜ ∈ NPPoly enc`. The theorem also takes a `Decoder enc`, since the verifier parses a list of instances from its certificate. `coNP_subset_NPPoly_of_orCompression` removes the decoder for `NP`-hard problems. It transfers the hypotheses along a reduction from `SAT`, whose formulas have a decoder, and pulls the relation back with `IsPolyEquivalence.comap`. In the source this argument appears inside the proof of Theorem 6, the theorem on cross-compositions of bounded cost, which is not formalized; the next section uses it for cross-compositions.

The advice is chosen by a counting argument. [`Finset.exists_tupleCover`](../../CslibFrontier/Foundations/Combinatorics/TupleCover.lean) considers a map `F` from `t`-tuples into a set `Y` with `#Y < 2^t`. For every finite `R`, it finds at most `⌊log₂ #R⌋ + 1` values of `F` such that every element of `R` is an entry of a tuple over `R` mapped to one of them. This is the counting behind the Fortnow–Santhanam theorem for compression to fewer than `t` bits. The complementary witness lemma, Lemma 1 of the source, which the source attributes to Dell and van Melkebeek without reproducing its proof, allows compression to `O(t log t)` bits; that case needs a cover by a number of values polynomial in `t` rather than the halving argument, and is not formalized. For each class and each length `n`, the library applies it to the no-instances of length `n` and keeps the resulting compressed words as advice. A verifier then accepts a no-instance `a` when it is given a list of related instances that contains `a` and compresses to an advice word. Every entry of such a list is a no-instance, because the advice word is also the compression of a list of no-instances, and the OR property holds for both lists.

## Cross-composition and polynomial kernels

Bodlaender, Jansen and Kratsch turn the distillation theorem into a kernelization lower bound: if an `NP`-hard problem OR-cross-composes into a parameterized problem, then that problem has no polynomial kernel and no polynomial compression unless `NP ⊆ coNP/poly`. The library proves this implication; it does not assume `coNP ⊄ NP/poly`. [bodlaenderjansenkratsch2014][bodlaenderjansenkratsch2014]

[`IsCompression enc κ A encB B K h`](../../CslibFrontier/Computability/Complexity/Parameterized/Compression.lean) is Definition 2 of the source. `K` maps instances of `A` to instances of `B`, with `K a ∈ B ↔ a ∈ A` and `|encB (K a)| ≤ h (κ a)`. It runs in time `T (|enc a| + κ a)` for a polynomially bounded `T`, which is the source's "time polynomial in `|x| + k`"; the source writes `k` in unary, so `|x| + k` is its input length. Definition 1 of the source allows kernelizations the same time bound. The library's `IsKernelization` is stricter: it asks for time polynomial in `|enc a|` alone. The compression time bound is therefore weaker than the library's kernel bound; the difference comes from the library's convention, not from the source. It matters when the parameter is much larger than the encoded instance, for instance a binary parameter. `HasPolyCompression enc κ A` asks for a compression into some problem on bit strings with polynomially bounded `h`. `IsCompression.hasPolyCompression` accepts any target encoding. `HasPolyKernel.hasPolyCompression` turns a polynomial kernel into a polynomial compression, as in Proposition 1 of the source. A generalized kernel bounds the encoded output by a polynomial in the parameter, so it is also a compression. As for kernels, `h` is not required to be computable. `IsCompression.computableInPolyTime_comp` composes a compression with a polynomial-time map whose output parameter is polynomially bounded in its input length.

[`IsORCrossComposition enc r A encQ κ Q C g`](../../CslibFrontier/Computability/Complexity/Parameterized/CrossComposition.lean) is Definition 9 of the source. It has three obligations:

| Obligation | Formal content |
|---|---|
| Efficient | `C : List α → β` is native polynomial time on `encList enc`. |
| OR property | `C l ∈ Q ↔ ∃ a ∈ l, a ∈ A`, for every nonempty list `l` of pairwise `r`-related instances. |
| Parameter bound | For such `l`, if every entry has encoded length at most `n`, then `κ (C l) ≤ g (n + ⌊log₂ |l|⌋)`. |

`ORCrossComposes enc A encQ κ Q` asks for such a `C` with respect to a polynomial equivalence relation `r`, with polynomially bounded `g`. `C` is a total map, and its value on lists that are empty or not pairwise related is unconstrained. The source algorithm receives only instances of one class, and `r` is decidable in polynomial time, so the total map is no stronger an assumption. As for distillations, time is polynomial in the encoded list length rather than in `∑ |xᵢ|`, a weaker hypothesis. The floor `⌊log₂ t⌋` is within one of `log₂ t`. Any `n` bounding the entries may be used, which agrees with the largest entry length for a monotone `g`. Every polynomially bounded function has a monotone polynomially bounded majorant.

`coNP_subset_NPPoly_of_orCrossComposes`, `NP_subset_coNPPoly_of_orCrossComposes`, and `PH_eq_SigmaP_three_of_orCrossComposes` give the `NP ⊆ coNP/poly` and `PH = Σ₃` conclusions of Corollary 2 of the source. If an `NP`-hard problem OR-cross-composes into `(Q, κ)` and `(Q, κ)` has a polynomial compression, both conclusions hold for every instance encoding. `not_hasPolyCompression_of_orCrossComposes` and `not_hasPolyKernel_of_orCrossComposes` are the contrapositive forms under `¬ coNP encC ⊆ NPPoly encC`, and `not_hasPolyCompression_of_orCrossComposes_of_PH_ne_SigmaP_three` and `not_hasPolyKernel_of_orCrossComposes_of_PH_ne_SigmaP_three` state them under `PH encC ≠ SigmaP 3 encC`. `compl_mem_NPPoly_of_orCrossComposes` puts the complement of any OR-cross-composing problem in `NP/poly`, given a decoder. Corollary 2 also concludes that the OR-distillation conjecture fails, which is not stated in the library.

The proof follows Theorem 5 of the source. Given a list, keep the entries related to every entry and erase repeats. A list of related instances of length at most `n` loses only repeats. At most `2^(n+1) - 1` distinct instances have length at most `n`, so the logarithm of the number kept is at most `n`. Neither `g` nor `h` is assumed monotone, so the proof takes monotone polynomial majorants `G m = c_g (m + 1)^d_g` of `g` and `H k = c_h (k + 1)^d_h` of `h`. Cross-composing gives a parameter at most `G (2n)`, and compressing gives a word of length at most `H (G (2n))`; `h (g (2n))` itself need not bound that length. That polynomial in `n` does not depend on the length of the list. Lists of `t n = H (G (2n)) + 1` related instances therefore compress to fewer than `t n` bits, and the class-wise theorem of the previous section applies. Theorem 5 builds instead a weak OR-distillation into the OR of the target language, compressing each class separately; the class-wise theorem covers the classes directly.

## A kernel lower bound for k-Path

k-Path has no polynomial kernel and no polynomial compression unless `coNP ⊆ NP/poly` (and hence `PH = Σ₃`). Bodlaender, Jansen and Kratsch attribute the kernel lower bound to Bodlaender, Downey, Fellows and Hermelin; the theorem number in that paper is not verified here. [bodlaenderjansenkratsch2014][bodlaenderjansenkratsch2014] [bodlaenderdowneyfellowshermelin2009][bodlaenderdowneyfellowshermelin2009] The library derives the bound from Corollary 2 of Bodlaender, Jansen and Kratsch. [`not_hasPolyKernel_LongPath`](../../CslibFrontier/Computability/Complexity/Parameterized/LongPathKernel.lean) and `not_hasPolyCompression_LongPath` take `¬ coNP encC ⊆ NPPoly encC` as an explicit hypothesis (`coNP_subset_NPPoly_of_hasPolyCompression_LongPath` is the direct form), while `not_hasPolyKernel_LongPath_of_PH_ne_SigmaP_three` and `not_hasPolyCompression_LongPath_of_PH_ne_SigmaP_three` take `PH encC ≠ SigmaP 3 encC` (`PH_eq_SigmaP_three_of_hasPolyCompression_LongPath` is the direct form).

The proof is an OR-cross-composition from undirected Hamiltonian path, `HamPath.orCrossComposes_LongPath`. The construction was written for this library within the framework of Bodlaender, Jansen and Kratsch; it is not taken from a source, and no novelty is claimed. Instances are related when their graphs have equally many distinct declared vertices. `IsPolyEquivalence.of_key` makes equality of any polynomial-time unary key a polynomial equivalence relation; the relation in Theorem 7 of the source similarly compares vertex counts. Entry `i` becomes a copy of its graph, `HamPath.pendantCopy`. Each declared vertex is relabeled `Nat.pair i (p + 2)`, for `p` the position of its first occurrence, and two pendant vertices `Nat.pair i 0` and `Nat.pair i 1` are attached to the copies of `s` and `t`. `HamPath.toLongPath` takes the disjoint union of the copies, with target `N + 2` for the common number `N` of distinct vertices.

A path on `N + 2` vertices stays in one copy and visits all of its vertices. Its ends are therefore the pendant vertices, whose only neighbours are the copies of `s` and `t`, and removing them leaves a Hamiltonian path from `s` to `t`. Conversely, the pendant vertices extend a Hamiltonian path. `HamPath.toLongPath_mem_iff` states this for nonempty lists of related instances. The labels use positions, which are bounded by the encoded length, because the library's pairing rule `unary_pair` takes unary arguments and a vertex name, written in binary, can be exponentially larger than its encoding. The target is at most two more than the length of an encoded entry, so the parameter bound is `g n = n + 2`, independent of the number of entries. On one instance the pendant copy is a reduction, which gives `LongPath_npHard` in `Problems/LongPath/Hardness.lean`, where the gadget lives.

Instances are encoded as `encLongPath` (`LongPathInstance` pairing a `Graph` and binary target `ℕ`), as for colorful k-Path; the source writes the parameter in unary. A library compression runs in time polynomial in the encoded length plus the parameter, which covers the time bounds of the source's kernelizations and compressions. A library kernel must run in time polynomial in the encoded length alone. For k-Path this loses nothing: a kernel in the source's sense can first map every instance whose `k` exceeds its number of distinct declared vertices to a fixed no-instance, in time polynomial in the encoded length, and on the remaining instances `k` is at most the encoded length. This remark is not formalized.

## Checked examples and scope

The inspected [Parameterized tests](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/ComplexityTests/Parameterized.lean#L1) instantiate bounded parameters, restricted-CNF FPT reductions, Boolean closure, and a constant kernel with both yes- and no-instances. They exercise the triangle at targets one through four. The [VertexCoverKernel tests](https://github.com/cslib-community/cslib-frontier/blob/13e6a31951bf1c89a1a6258c44f9444aecbbefd8/ComplexityTests/VertexCoverKernel.lean#L1) check dense relabeling, isolated-vertex padding, rejection from too many forced or active vertices, and a target exceeding the vertex count. These are existing test sources, not new compilation results. The [ColorCoding tests](../../CslibFrontierTests/ColorCoding.lean) evaluate the colorful-path decider by `decide` on accepted and rejected colorings of a four-vertex path, including `k = 0`, colors at least `k`, and `k` above the vertex count. The [WHierarchy tests](../../CslibFrontierTests/WHierarchy.lean) evaluate weft and depth of small circuits by `decide`. They check weighted satisfiability of a three-input conjunction at weights `3` and `2`, and use the circuit of the triangle to show that it has an independent set of one vertex and none of two. They also check that edges with an undeclared end and self-loops are ignored. The [Distillation tests](../../CslibFrontierTests/Distillation.lean) show that the distillation hypotheses are satisfiable. "Some entry is `true`" is an OR-distillation of `{true}` with output length one, which places `{false}` in `NPPoly encBool`. Equal length is a polynomial equivalence relation on bit strings with `n + 1` classes up to length `n`, and the class-wise theorem with `t n = 2` places the all-`false` strings in `NPPoly encBits`. The tests also check a concrete halving cover and `SAT ∈ NPPoly encCNF`. The [CrossComposition tests](../../CslibFrontierTests/CrossComposition.lean) show that the cross-composition hypotheses are satisfiable. "Some entry is `true`" is an OR-cross-composition of `{true}` with parameter `0`, and the identity is a compression with output length one, which places `{false}` in `NPPoly encBool`. "Every entry is `true`" fails the OR property. Every problem `A` OR-cross-composes into the OR of `A` by the identity, with parameter the largest entry length plus `⌊log₂ t⌋`. For `SAT` the theorem then says that a polynomial compression of OR-SAT gives `coNP ⊆ NP/poly`. Buss's kernel gives a polynomial compression for vertex cover, and with a constant parameter the identity on bit strings is no compression for any size bound. The [LongPathKernel tests](../../CslibFrontierTests/LongPathKernel.lean) check that the edge `1 — 2` has a Hamiltonian path from `1` to `2`, and that the same vertices without the edge, or with the undeclared start `5`, have none. They apply `HamPath.toLongPath_mem_iff` to lists of these related instances: a yes-entry gives a yes-instance of k-Path even beside an entry with an undeclared start, and two no-entries give a no-instance. The empty list, outside the OR property, gives a no-instance. Equal length is a polynomial equivalence relation on bit strings by `IsPolyEquivalence.of_key`, and so is equality of unary numbers by `isPolyEquivalence_eq_unary`. The tests also instantiate the hypotheses of the cross-composition theorem for k-Path. The [LongPathHardness tests](../../CslibFrontierTests/LongPathHardness.lean) evaluate the k-Path verifier by `decide` on the edge `1 — 2`. The certificate naming the ordering `[1, 2]` is accepted for `k = 1` and `k = 2` and rejected for `k = 3` and without the edge, and a certificate naming a repeated vertex is rejected. The tests also instantiate `NP`-hardness and `NP`-completeness. The [NiceTreeDecomposition tests](../../CslibFrontierTests/NiceTreeDecomposition.lean) check `LocalValid` violations and `CoversFinset` on `Fin 3`, together with the `(3 * width + 5) * (|V| + 1)` pruned size and width bounds on `P₄` and a redundant 6-node decomposition. The [TreeDecompositionCSP tests](../../CslibFrontierTests/TreeDecompositionCSP.lean) evaluate `cspCountNiceM` and `cspDecideNiceM` by `decide` on `3`-coloring of `P₄` (`24`) and `K₄` (`0`), verify tick bounds, and check `cspCountActiveRootedM` and `ret_cspCountNiceM_equiv` via `Bool ≃ Fin 2` on a constraint with an isolated variable.

The survey compared the displayed quantifiers and quantitative bounds with the pinned source fragments linked above. This was a textual check, not Lean elaboration or an audit of the proofs.
