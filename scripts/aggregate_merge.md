# Report an aggregate-only merge conflict

`aggregate_merge.py` checks the narrow generated `Complexity.lean` case from
[#2274](https://github.com/cslib-community/cslib-frontier/issues/2274). Run it against immutable,
locally available commits:

```sh
python3 -B scripts/aggregate_merge.py --repo /path/to/checkout \
  --prefix FULL_ACCEPTED_PREFIX_SHA --source FULL_SOURCE_HEAD_SHA \
  --reviewed-base FULL_ORIGINAL_PARENT_SHA --reviewed-head FULL_REVIEWED_HEAD_SHA \
  > aggregate-report.json
```

It prints JSON and exits zero only for `status: verified`. `rejected` means an input or merge
falls outside the supported case; `limitation` means canonical reconstruction passed but the
ordinary tracked-attribute Git merge did not produce that exact tree. Neither status authorizes
integration. The report includes immutable inputs, trees, the complete candidate entry map,
reviewed payload entries, feature/aggregate digests and exact inverse recovery of the prefix.

The verifier requires the complete neutral conflict set to be exactly `Complexity.lean`.
Each input aggregate must have the exact module-style preamble and complete sorted public
imports generated by `scripts/MkAll.lean`. Module names follow the conservative path syntax in
`quick_check.py`; dynamic Lake configuration, moved library roots, symlink modules and other
aggregate styles are rejected. This is an exact generated-format check, not a general Lean
parser that might overlook declarations or options after the imports.

Canonical imports come from the merged library inventory, so additions and deletions are both
accounted for. Every other entry and mode must equal the neutral merge. The complete original
nonaggregate feature, including docs, tests and removals, must replay onto the accepted prefix;
reviewed payload modes/blobs must remain exact. Reversing that feature and restoring the prefix
aggregate must recover the exact prefix tree. Additional unreviewed source payloads are rejected.

Finally, Git's ordinary merge with the prefix's tracked attributes must yield the identical
canonical tree. The temporary repository configures no merge driver, so the tracked
`merge=leanagg` falls back to a text merge, as on GitHub. Under an older prefix's `merge=union`,
an adjacent insertion may produce sorted imports, while reversing the insertion order may produce
unsorted imports, and adjacent independent deletions can reconstruct correctly while union retains
deleted imports. A conflict or a noncanonical result reports a limitation: the source owner must
refresh the source branch through the usual reviewed process.
The tool never proposes an alternative queue API or enables a merge driver.

Git operations use a temporary bare repository/index/object directory populated by an ordinary
local `file://` fetch. It has its own common directory, no alternates or shallow boundary, and
no object inode shared with the source. These properties are checked. Fetching complete history
can cost disk space and time; shallow source repositories are rejected. Pack threads are capped
at two. All inherited `GIT_*` environment variables are cleared before the first Git command,
including object, index, common-directory and worktree redirects.
No source/index/ref/config/object write, merge commit,
queue operation, workflow or cache action occurs in the inspected repository. User/system
attributes, local `info/attributes`, hooks and configured merge drivers are excluded; only the
prefix's tracked attributes participate in the ordinary comparison. Python 3.11+ and Git 2.43+
are required. Unavailable history is an error, not a request to repair or reconstruct objects.

This local standard-Git comparison does not certify GitHub's settings, current source ownership,
review approval, dependency landings or CI. Coordinators must still guard the live source/full
prefix, verify the actual hosted candidate tree, and require all six queue checks, including
`mk_all --check`. The report does not change admission policy.

Focused regression tests use independent temporary Git repositories and run without Lean:

```sh
python3 -B -m unittest discover -s scripts -p test_aggregate_merge.py -v
```

No Lean statement or definition changes.
